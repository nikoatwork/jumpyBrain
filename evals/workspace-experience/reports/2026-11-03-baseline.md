## Findings to improve next

1. **Hosted live editing is blocked; its error is misleading.** HTTP search/show/update and board operations succeeded, but the CLI reported `Could not connect to the backend` for collaboration. Native note text loaded while the editor remained `Connecting…`, disabled writing/linking, and said `This note is no longer available`. One explicit Retry failed. Canonical CLI reads proved the note still existed. Investigate server/proxy live-transport compatibility; do not infer a specific server version or deploy a fix from this report alone. Evidence: VPS `007-vps-editor-unavailable`, `008-vps-retry`, `019-vps-updated-logistics` and failed collaboration receipts.
2. **Ordinary opens/own edits produce weak external-change feedback.** New and personally edited local fixture notes displayed `Updated elsewhere` without an independently arranged external writer. Content was correctly saved, but the message loses its ability to distinguish an actual other-writer event. Evidence: local `001-new-note`, `003-human-corrected`, `009-handoff-human`.
3. **Append-only CLI editing raises an alarming replacement warning.** Supported whole-document CLI update appended one sentence while preserving the prior body. The app raised `External file replaced saved text — review retained version`. Native changed-passages comparison showed only an addition (`Retained passage: (nothing)`); Keep current preserved the note but left the notice. Investigate retention classification and acknowledgment behavior. No content loss was observed. Evidence: local `037-off-note-open`, `044-retained-review`, `045-retained-changed-passages`, `046-retained-kept-current`.
4. **Completion and cancellation are visually similar.** The generating chip was useful while active and disappeared on both finish and cancel. Actual outcomes are established by distinct CLI receipts, not by disappearance alone. Evaluate whether a quiet completion/interruption cue would improve understanding without adding notification noise.
