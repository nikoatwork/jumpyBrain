# Selection boundary experiment — frozen before outputs

Compare current production discovery + first-forty ordering with two small independent hypotheses, retaining all 140 seen cases and a separately authored `boundary-confirmation/` fixture. Fixture author inspects no run outputs; policy/runner author does not author fresh sources or rubrics. This is model-agent separation, not independent human adjudication.

## Arms

- `baseline`: current production, unchanged first-three unique available guarded handles.
- `ordering-all`: replace only production's stable first-40 named-subject partition with stable partition of the entire already bounded grouped pool. Same computed subject, guards, admission, scores, grouping, diversity and output limits; no new reads or backend calls.
- `read-spread`: unchanged production retrieval; choose first two distinct expandable sources then last distinct expandable source. With <=3, use all. Preserve order of those selected and line-1, hash-guarded, 8,192-byte reads. The hypothesis is that a small exploration slot can expose complementary lower-ranked sources; it may instead discard essential rank3 evidence.
- `ordering-all-read-spread`: both, predeclared factorial diagnostic. Attribute changes to separate arms; a combined gain cannot erase an individual arm's rejection.

The rank-spread policy is deliberately simple and may fail. It is a non-oracle evaluator policy, not production automatic retrieval or a claim that rank5 means missing evidence. Keep it outside scoring and use only returned handles/order, never rich search, rubric, source contents or query-specific IDs. No policy/source/threshold changes after outputs.

## Fixed evaluation

Lexical real QMD 2.8.3, existing provisioned dependencies, no model/download/native build. Same frozen source/compiled runtime and complete eval inputs for all arms. Five compact results, 8,192 bytes each response, max three guarded reads, 32,768 total response bytes. Requests/responses/errors all tokenized with pinned tokenizer. Fresh independent cases vary domains and paragraph/section positions, include long records and protected exact/phrase/multi-name/historical/unknown tasks. All become seen after execution.

Each arm independently requires >=2 fresh complete-task improvements, >=5 percentage-point gain in orientation/current/multi-source/rationale, zero complete-task and individual required-unit losses (including protected cases), zero provenance/budget failures and <=5% total interaction-token increase. Record initial versus post-read evidence. Review every changed required-unit packet and all losses against canonical cited text; mechanical spans are not answer accuracy. Do not tune failed arms or integrate them into production. Passing ordering additionally requires 20 alternating quiet pairs after six warmups, <=10% recall p95 / <=50 MiB extra sampled CPU RSS, production packet parity and focused lifecycle/transport checks. Overlapping quality runs provide no cost acceptance evidence. Evaluator read-policy results remain evaluation-only.

Commit compact results, input/runtime identities, private QA aggregates without content, rejected arms, reproduction commands and limits. External archive retains raw packets/failures under hashes, excluding private memory and rebuildable roots. Broader human/independent-answer/semantic/Linux/VPS questions remain open. No push, installation or release.
