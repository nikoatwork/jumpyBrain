# Retrieval experiment contract — v2, frozen before comparisons

The v1 controls remain unchanged (80 tasks, 160 short pages). Augmentation adds six independently written operating workflows: a cold-chain exercise, sediment survey, archive digitization, school transport rehearsal, kitchen tasting, and theater access soundcheck. There are 27 additional pages, 24 tasks, nested scope, aliases, accepted arrangements, later proposals, sparse explicit source chains, cycles, a hub and unresolved links. Meridian and Estuary are development; Vellum, Bracken, Saffron and Quartz are reserved confirmation families. Corpus, query and rubric author and packet judge are the same person/agent; these are authored confirmation cases, not independent blind judgments. No answer model is evaluated.

Freeze all input hashes before outputs; run unchanged production source first. Public query options and first-three expansion policy are unchanged. Each arm starts from that same runtime. Experimental ESM instrumentation stays under evals and is absent from the package and production source. It changes the real driver's bounded candidate/selection seams or verified compact candidate packing, never mocks discovery. It fails closed if the expected seam is absent. Baseline uses the same observer with no mutations. No candidate/gold IDs or expected answers may inform retrieval or expansion choice.

## Fixed gates

- Evidence: affected slice = six fresh scope tasks plus original orientation/current tasks. Require +10 points adjudicated fully supported tasks, two improved reserved tasks, no overall/protected evidence losses, <=5% extra full interaction tokens, <=10% warm p95 and <=50 MiB added process-tree RSS.
- Rerank: affected slice = fresh ranking/multi-source tasks plus original discovery/orientation/current/multi-source tasks. Rerank up to 40 final merged file candidates once using provisioned QMD 2.8.3 `LlamaCpp.rerank`, fixed displayed excerpts/title, no branch-only proxy. Preserve exact-title tier, constraints and temporal eligibility. Require +5 points support, two improved reserved tasks, no overall/protected losses, same output cap, <=750 ms added warm p95, <=1 GiB extra CPU process-tree RSS. Record model-cold and warm calls, CPU-only feasibility and model hash/size. No implicit downloads or installation changes.
- Neighbors: affected slice = fresh and original multi-source/orientation tasks. Explicit `sources`, `supersedes`, `conflicts_with` only; ordinary links are excluded. A frozen generation-tagged rebuildable projection uses canonical target resolution. Seed at most three direct hits, admit at most six unique one-hop neighbors, reserving candidate slots within the existing cap. Existing ranking, excerpt, constraints and temporal scope apply. Require +10 points support, two improved reserved tasks, no overall/protected losses, same context cap, <=20% warm p95, <=128 MiB RSS, <=25% initial/incremental index time and derived bytes overhead. Projection work is charged to indexing, never a whole-corpus graph assembly per recall.
- Protected: original navigation, historical and limits cases, plus fresh protected cases. Provenance violations, budget overruns, unauthorized-source evidence, constraint bypass and newer-proposal-as-approval are automatic failures.

Mechanical required-clause coverage is a diagnostic. Inspect every changed task against original canonical spans, including subject/scope/qualification/time. Record paired per-journey support and token costs. Actual answer accuracy remains unmeasured. Quality failure is sufficient to reject: do not run expensive adoption-only performance, integration or combined-arm gates for a losing prototype. Record unmeasured costs as unmeasured, never passing. Only independently passing arms justify combined confirmation and production integration.

Quiet-window adoption timing uses sequential warmed baseline/arm calls with no concurrent eval/test jobs, at least 20 paired calls, independent of quality runs. RSS uses process descendants (GPU memory excluded). Model-cold means a newly constructed model runtime, not a promise of cold OS file cache. The CPU probe explicitly disables GPU. Lexical and semantic are separate; claims only apply to measured modes. Linux/VPS and browser usability remain outside this local experiment.
