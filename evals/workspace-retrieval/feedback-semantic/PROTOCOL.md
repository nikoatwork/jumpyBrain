# Feedback fixture author protocol and freeze

This contract is fixed before new evaluation outputs. It supplements, rather than replaces, `../PROTOCOL.md` and the existing discovery experiment's separation and evidence standards. The author owns only this directory and does not implement candidate retrieval, run evaluation or decide adoption.

## Protected evidence

Every one of the twenty-eight source-specific rubric units is protected from loss in the paired comparison. `PROTECTED-UNITS.json` enumerates the exact case, label, allowed source and complete clauses. Whole-case completeness, initial evidence, post-expansion evidence and clause losses must all be reported. A higher aggregate score cannot cancel a lost qualification, identifier, temporal boundary or uncertainty unit. Explicitly protected cases in `queries.json` additionally cover quote, path/title navigation, exclusions, exact identifiers, historical state, newer proposals, incomplete durability evidence and unknown approvals.

The two fresh substantive discovery cases are declared before outputs as `dunmere-unconstrained-paraphrase` and `rookfen-unconstrained-paraphrase`. Report them separately for task 3's currently eligible, unconstrained paraphrase comparison. The ordinary-language pair, lower-case hyphenated words and natural without case are task 2 eligibility probes. The camelCase and ticket probes protect identity while asking a natural question. Do not retroactively reclassify a miss into an unaffected denominator or select only successful cases.

Complete clauses must appear in verified canonical ranges from their declared source. A simulation note mentioning the operational policy does not substitute for the decision, and a near-match ticket mentioning the correct ticket does not substitute for that investigation. A displayed source title or the bare identifier is insufficient. Report manually sufficient alternatives or disagreements with the rubric alongside the frozen score; do not rewrite gold after looking at outputs.

## Constraints and ambiguities declared in advance

1. `-simulation` and uppercase `NOT simulation` are paired explicit exclusion inputs. The fixture author has not executed QMD or asserted its exact grammar. The experiment owner must establish and record actual pinned-backend syntax from upstream/local package documentation or a separate syntax probe before designing a narrower eligibility rule. Preserve unsupported syntax or truthful branch rejection as an outcome, rather than claiming this fixture proves that every notation is natively supported. If either notation is unsupported, retain the unchanged case as a protected diagnostic and disclose the limit; do not silently rewrite its query after quality outputs.
2. The literal `notes/ternholt/release-checklist.md` is an exact-path navigation request, not a claim that QMD supports a `path:` operator. The expected file is unambiguous. Exact title navigation is paired with it.
3. The quoted phrase is a user constraint. `amber card` appears in the accepted queue source and several contextual mentions. Finding the phrase in another file earns no required-source credit and does not establish the reservation's scope.
4. Natural `not`, `can't`, `without`, `walk-in` and `drop-off` are meaningful prose. Their presence alone is not an explicit request to exclude every page containing another word. The fixture tests the complete intent, not a particular lexical rewrite.
5. The festival, display operation, transposed ticket, simulation, public-sale survey, photography workshop and narrow remote-clip permission are plausible near-topic distractors. Their genuine local facts remain true in their own scope. `CONSTRAINTS.json` requires a manual source-bound check; score coverage alone would not detect all misleading extra evidence or a wrong generated conclusion.
6. Unknown-approver records state limits of this retained workspace. Neither record proves that approval never happened outside it. No answer agent runs under the baseline protocol, so actual abstention remains unmeasured.
7. The two unnamed paraphrase questions have some ordinary lexical overlap. A positive result is evidence on these authored cases, not proof that embeddings understand arbitrary wording or that the architecture generalizes to a different workload.

## Freeze and evaluation ownership

`AUTHOR-FREEZE.json` hashes every file in this directory except itself, using SHA-256 over the exact bytes. Its aggregate digest is SHA-256 over sorted UTF-8 lines `sha256  relative/path\n`. The timestamp identifies the input freeze only; no runtime, model, engine readiness, policy or quality result is implied. The author validates all clauses and stable IDs and then stops editing before evaluation.

Before a run, the owner must separately freeze runtime source/compiled identity, runner, candidate policy, existing controls, tokenizer, QMD/model identity and numeric quality/context/operational gates. Keep task 2 constraint-policy evaluation separate from task 3 fusion comparison so one change cannot conceal another's effect. Observe the same packet limits, provenance verification, gold-free first-three reads and failed-branch accounting as the established protocol. Do not inspect results and then modify inputs, protected units, syntax interpretation or thresholds to rescue a candidate.

The fixture is ready for integration, not evidence of a search improvement. The parent owns paired runs, full costs, source judgments, gate decisions, production changes and task finalization. No model, GUI or benchmark workload was run by this author.
