# CLI module docs

## Responsibilities

- `board` is an optional namespace using normal root/remote target selection, independent of desktop discovery. `board-args.ts` validates command-specific flags and hash preconditions. `boards.ts` composes runtime board operations or the HTTP transport. `commands.ts` enforces remote read-only policy before input files/credentials; only list/show/status are reads. Status is bounded to 12 cards by default (explicitly up to 50), with provenance and evidence gaps; it rechecks the individual board hash. No automatic indexing or Markdown writes. See [board contract](../../docs/boards.md).
- `companion.ts` provides private native descriptor/key discovery for extension management. The historical `extensions-control.json` filename remains; boards do not use this channel.

- `feedback.ts` handles explicit developer feedback before memory target policy/credentials. Strict args allow message or bounded stdin, dry-run, JSON, help and a UUID v4 for deliberate same-message retries. It sends no diagnostics and delegates to the shared feedback adapter. No memory root, app or API key is needed. Service acceptance is not inbox receipt; generic unconfirmed errors retain the report ID, never remote bodies, and no automatic retry runs.

- `remember` and its recipe strictly parse creation flags, including `--date value`/`--date=value`, before credentials/stdin. Only tags may repeat; existing optional true/false dream spellings remain supported. Shared core validation rejects malformed evidence dates. Both transports receive the same draft.

- Keep `src/cli.ts` as the executable shim; command dispatch lives in `src/cli/commands.ts` and `run` recipes live in `src/cli/recipes.ts`.
- Parse command-line arguments and stdin, select local or remote targets, and preserve stable user-facing command names, flags, JSON modes, and text output.
- Own target-aware stateless `dream` windows for local `--root` and remote `--target-url`: validate `--from`, `--days`, `--date-basis`, offsets/budgets, write private full-context packets with `--out`, and keep bodies out of compact stdout. Legacy lifecycle/apply flags fail with deprecation guidance before credentials/files; legacy runtime/HTTP batch APIs remain available. Plain dream is a read-only operation even on protected targets; old mutation flags stay blocked by access policy.
- `remember --type page --dream` creates a dream-marked page using body-only stdin, through the existing local/remote write seams. Existing `show`/hash-checked `update` and explicit `index` maintain it. Source preservation is agent-skill guidance, not a new write restriction.
- Own `migrate obsidian` and `migrate logseq` in `migrate.ts`: strict source/root and boolean flags, body-free human summaries or the unchanged app JSON result, safely quoted apply/index hints, and explicit separate indexing. Dispatch this local-only command before remote policy/credentials; reject either remote target flag even when malformed or combined with local flags.
- Obsidian always preserves original body/YAML bytes, returns notes/reference/omission counts, and rejects `--body-format`; it shares local-only strict parsing and body-free output with Logseq.
- `migrate logseq --body-format readable|preserve` uses strict nonrepeated values (readable default), reports body conversion/version/limitations, and pins the mode in apply hints. Canonical migration and explicit indexing remain separate.
- Keep migration argument strictness scoped in `args.ts`; process additionally rejects repeated apply flags, including mixed bare/value/equals spellings, without changing other legacy command parsing.
- Delegate local work through `src/cli/local-transport.ts` to the runtime/app seam.
- Delegate remote work through the HTTP client adapter while keeping API keys and URLs at the CLI boundary.
- Own target selection: `--root` selects local memory, `--target-url`/`--remote-url` selects the single remote V1 namespace, and remote API keys come only from `JUMPYBRAIN_API_KEY` in the CLI environment rather than adapters or local config.
- Own strict device-local per-origin read-only policy in `remote-access-policy.ts`: normalize HTTP(S) origins within the CLI source boundary, classify direct/recipe operations through an explicit read allowlist, fail closed on invalid existing config, and reject protected mutations during dispatch before API-key, stdin/file, preflight, idempotency, or transport work. Keep the standalone installer origin helper behaviorally aligned through parity tests rather than importing repository scripts from `src/`.
- `formatting.ts` owns shared local/hosted plain recall/search (and wrapup preflight) rendering only. Preserve source ranges, scores, and source meaning; add bounded single-line title/type plus `Written date` from valid `created_at` / `createdAt`, with unknown fallbacks. Show explicit frontmatter `date` as `Evidence date` (unknown if invalid), never inferred Observed dates; accept real ISO calendar dates or timezone-explicit timestamps without changing their timezone. Do not infer dates from filenames/mtime or display confidence as truth. Cite each additive `{ snippet, provenance }` passage independently, without repeating an identical representative passage; a positive `omittedPassages` count gets a narrower-query/source-expansion hint. `evidence-links.ts` abbreviates long (>80 characters) simple inline-link destinations and bare HTTP(S) URLs in plain snippets only, keeping recognizable ends and a stable identity hint. Preserve backtick code, link labels, and short destinations. Emit one warning directing users to JSON/source for exact addresses; abbreviations are not navigable URLs. JSON serialization and retrieval policy remain outside this formatter.
- Agent instructions favor sufficient snippets, then narrower queries/targeted expansion only for gaps. They distinguish compact's aggregate byte bound from guaranteed economy (metadata can exceed text at low limits), retaining the same 1,000-character excerpts. Text citations support local current-file range reads after source-root resolution, not verified expansion; guarded reads require available compact ID/hash handles on the same root/target. Generated/distributed guidance preserves hashes, whole-line/section limitations, and ordinary Markdown authoring advice without a required general template. `bounded-reads.ts` wires local/remote `recall`/`search --compact [--max-bytes N] [--diagnostics]` and `expand --id ... --if-match ...` with line bounds or a section anchor. Both emit only the versioned JSON-plus-LF packet, with no pretty printer/banners/mode wrapper even under `--json`. `args.ts` strictly parses bounded-read flags (including numeric `--key=value`) so budgets/ranges cannot silently disappear. Missing values, unknown/repeated flags and valued booleans fail before credentials. `expand` and its recipe are read-only allowlisted. See [CLI contract](../../docs/cli-commands.md#compact-recallsearch-and-conditional-expansion). `show` remains whole-document only for editing/broader context, never an automatic fallback for unsupported expansion.
- Keep usage text, doctor reporting, and serve bootstrap behavior in dedicated CLI submodules.
- `update.ts` detects the current managed installation (including custom roots). On macOS it loads the packaged `integrations/electron/update-cli.mjs` installation seam: a standard paired installation uses the same immutable published-release updater/transaction as the app. An open app owns preparation and explicit Restart; CLI output says prepared/restart-needed. A closed app is updated with the CLI and verified startup before success. Paired custom/pinned/foreign policies and source/ref overrides stop with guidance. CLI-only/custom-root/legacy installations retain the installer and read-only preview path. No installation behavior belongs in memory/core/server semantics.
- Route top-level memory commands and `run memory:*` recipes through shared handlers; do not duplicate behavior.
- `process` is local-only and requires actual Boolean apply authorization: `--apply`/`--apply true`/`--apply=true` authorize; `false` does not, and malformed values fail. Keep this parsing local to process rather than coercing strings with `Boolean`. Lint JSON adds structured issues, zero-clean counts, run IDs and scope; reports never overwrite a prior run. `synthesize` produces an extractive source map, not semantic reconciliation, refuses human/dream collisions, and returns an unchanged-content no-op without updating timestamps. The processing API's optional destination `ifMatch` hash is exposed by `process --if-match <hash>`; ordinary synthesis also snapshots and rechecks its destination during the operation.

## Creation outcomes

`remember` and `wrapup` retain existing identity/body/validation fields and add `saved: true`, compatibility `indexed`, and `indexing.status` (`indexed`, `pending`, `failed`). Local remember attempts nonpersisting automatic freshness after publication; stale concurrent generations remain pending; wrapup and hosted creation defer it. A failed post-save index returns exit **0**, explicit partial-success text or JSON with the saved ID/path and safe actionable diagnostics. Never retry creation to repair indexing: run index for the same root/target or allow ordinary local recall/server maintenance to recover. Canonical validation/publication, transport and pre-save replay lookup errors still fail; post-save replay persistence failure retains identity and warns that reusing the key may not be safe; an uncertain write is not automatically retried. Human deferred output explicitly labels pending state and prints the ID. Recipes use the same handlers.

## Index controls and diagnostics

Doctor strictly parses only root/json/check before probes. Default unhealthy reports retain exit 0; valueless `--check` sets exit 1 after printing the same report when required CLI/Node/QMD-version/root-compatibility checks fail. Index freshness and optional integration presence are reported separately. QMD probes are bounded to five seconds/64 KiB and never expose probe stdout/stderr. Global integration evidence is labeled; explicit roots add scoped project file presence (root itself, or parent of a conventional `memory` directory), never host activation or target-policy inference. No diagnostic initializes memory or writes a sample. `targets.ts` owns safe root-inspection messages shared by doctor and CLI dispatch; only a realpath ENOENT for the selected root gets a shell-quoted same-root init hint, while config/permission errors remain distinct.

`index --rebuild` works locally/remotely; routine index is incremental. Mutually exclusive `--semantic-model /absolute/local/model.gguf` and `--lexical` persist server-local/root policy and are rejected for remote targets before transport. `--rebuild` and `--lexical` take no value. Recipes use the same handler. CLI status/doctor print separate readiness; search/recall print partial/stale warnings, preserving the additive JSON packets. Doctor checks QMD 2.8.3's version and cheap root readiness, not model inference or SQLite integrity; installation must also provide its SDK. See [CLI reference](../../docs/cli-commands.md#indexing-policy-and-recovery).

Local search/recall (rich, compact, and recipes) automatically repair missing/stale indexes within the search deadline. `--no-refresh` is a strict valueless Boolean opt-out of repair/publication recovery, not temporary lock writes. Hosted reads remain nonrepairing and never send a hidden index mutation. Status/show/expand remain observational. Automatic repair cannot persist root policy, migrate legacy environment settings, or rebuild implicitly.

`--read-only` is a separate strict valueless Boolean for zero derived-state writes on local/hosted rich/compact reads and recipes. It implies no refresh, uses lexical-only immutable QMD reads, and refuses unsafe busy/pending/WAL-active/mismatched/changed generations. Semantic omission is explicit; do not silently fall back to ordinary read-side writes. Remote clients preflight an observational capability before sending strict reads. Keyword relaxation is demand-driven, uses only spare slots in the existing eight lexical calls after successful eligible empty discovery, preserves explicit constraints, and reports partial `keyword_query_relaxed`; partial-topic matches are not full answers.

Local search/index execution deadlines can be set with `JUMPYBRAIN_SEARCH_TIMEOUT_MS`/`JUMPYBRAIN_INDEX_TIMEOUT_MS`; serve forwards validated host configuration. Local index/search/compact transport owns per-operation SIGINT/SIGTERM cancellation and removes those listeners on completion. Library runtime never installs OS signal handlers. No new effort/depth or queue flags. Remote CLI transport defaults to 70-second reads / 610-second index; server deadlines are server-owned. See [execution contract](../../docs/technical.md#bounded-retrieval-execution). CLI doctor/update retain their separate synchronous non-retrieval probes/installers; they are not part of server QMD admission.


## Non-responsibilities

- Do not import QMD adapter internals or manage QMD cache/config paths directly.
- Do not implement server HTTP routes or server-local memory orchestration.
- Do not introduce named target registries or committed secrets without a dedicated target-config task.
- Do not treat the local read-only policy as server authorization or import it from core, app, runtime, HTTP adapter, or server modules.
- Do not change public CLI behavior during internal refactors unless a task explicitly calls for it.
- Do not run AI/model providers or perform hidden prompt injection for dreaming; local agents decide and apply edits explicitly.
- Do not put command implementation back into `src/cli.ts`; keep the binary path stable while routing through CLI submodules.

## Explicit temporal retrieval

`temporal.ts` validates `--from`, `--to`, `--reference-date`, and `--order` before target credentials. Search/recall and recipes switch to strict bounded-read argument parsing whenever any temporal flag is present: unknown/repeated flags, missing values, and valued booleans fail. The handler passes one `temporal` object through either transport. Human output reports the resolved UTC half-open interval, coverage, evidence-date basis, explicit relationship declarations, and partial warnings; non-temporal formatting stays unchanged. See [CLI temporal contract](../../docs/cli-commands.md#explicit-temporal-retrieval).

## Delete command

`delete --id <id>` and `run memory:delete` preview only. `--apply --if-match <prior hash>` authorizes permanent removal of exactly one canonical file; no path/glob/force input, Trash, cascade or automatic retry. Delete flags are strict: unknown/repeated/missing values, valued booleans and unexpected positional arguments fail before target credentials or stdin. Device read-only policy classifies deletion as a mutation (including the deletion preview command); preview itself uses a read-only GET. Output distinguishes confirmed removal from pending/failed indexing.

## Living-page checks

`dream --check-sources --id <Dream-page-ID>` or `--draft --page-file pages/topic.md` (stdin) calls the same local/hosted checker. Strict argument parsing rejects duplicate/unknown/valued Boolean flags before target credentials or stdin. The Dream read-only allowlist covers this observational operation; ordinary writes keep existing authorization. Exact unchanged updates print Unchanged and do not claim publication. See [living-page workflow](../../docs/living-topic-pages.md).

## Desktop extension management

`extensions` is dispatched before remote access policy or credential resolution, and its management module/app seam is dynamically imported only for that command. Strict parsing in `args.ts` rejects unrelated remote flags (including malformed/repeated spellings), unknown commands/flags, missing/repeated values and valued booleans before filesystem access. `extensions --help` and command `--help` expose the local-only contract.

`extensions install --source <local-package>` (or `link`) records/prepares an explicit local directory; `list`, `enable|disable|remove --id <id>` and `reload` share the app extension-management seam. Default storage is `~/Library/Application Support/jumpyBrain Companion/extensions`; `--directory` overrides that extension directory for fixtures/nonstandard hosts. No npm/git fetch or dependency install runs. CLI never executes a factory: a live companion owns activation and receives authenticated reload/manage requests; closed-host reload only prepares code. Removal preserves namespaced extension state. `extensions/disabled` permits safe startup and management of a broken package. JSON output is valid for void management outcomes too.

`extensions check --source <package> [--json]` bypasses live-host discovery and calls the explicit app check seam. It compiles into disposable storage, never registers/activates code, and reports at most five file/line/column reasons without source lines/notes/stacks. Failure exits 1; ordinary install/reload and browser errors remain sanitized.

The gateway's private support-directory control descriptor locates the exact live host, with its native control key read from the same private directory. Current generation is explicit, redirects are refused, and a live-host transport/auth failure is not treated as permission to mutate offline. This is separate from remote brain credentials and read/write policy. See [gateway extension protocol](../../integrations/macos-companion/gateway.docs.md#executable-extensions).

## Declared actors and recognition

`recognition.ts` parses explicit write actor flags and rich-search recognition options; strict search parsing accepts them alongside read-only/no-refresh/temporal flags. Reject recognition with compact packets rather than silently dropping its scope. CLI defaults to unknown editor; `--actor human|agent` opts in, with optional `--actor-id`/`--actor-name`. `--actor unknown` explicitly leaves an edit unattributed. Search controls are independent of historical evidence-date filters. See [CLI reference](../../docs/cli-commands.md#recognizing-notes-in-search).
