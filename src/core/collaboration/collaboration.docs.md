# Collaboration source policy

## Responsibilities

Own bounded source-splice rebasing, read revisions/epochs, operation identities, per-actor undo and sequenced streams. Validate UTF-16 boundaries and well-formed text. Independent operations rebase; ambiguous replacements reject rather than guessing. Snapshot history is bounded by both operation count and retained UTF-8 bytes. A fork supports publication transactions without changing the accepted model before disk success.

## Non-responsibilities

No filesystem, transport, authentication, runtime or app imports. This model never defines Saved; the app owns canonical publication.

## Granular source transactions

Connected editors preserve actual transaction coordinates. `composeSourceSplices` uses bounded original-source pieces to compose sequential transactions without guessing from repeated bytes: deleting the first `a` in `aaaa` stays a deletion at offset zero. Editing inserted pieces retains their origin boundary; deleting original text and replacing it with equal bytes remains a logical replacement. Pure insertion followed by removing only that new source composes to the identity. Composition is bounded by 1,024 transactions, 256 output splices, 4,096 pieces, source bytes and 32 million work units; exhaustion returns `provenance_limit` for retained-draft recovery.

`rebaseSourcePair` transforms both actual transactions, gives canonical remote insertions priority at equal offsets, and verifies both application branches produce the same result. Its returned remote operations apply to the optimistic local body and move selections using the actual published insertion, including repeated characters. `changesSince` returns contiguous actual model transactions without inverse cancellation; missing provenance is an explicit history failure. Nonempty equal-byte operations remain revisions rather than disappearing behind a string-equality shortcut.

`composeCausalSourceHistory` reconstructs contiguous published records and uses the same inverse-pair proof reducer as server rebasing before composing their origin pieces. A peer replacement followed by its verified Undo restores the original source coordinates; an ordinary replacement with equal bytes does not. Surviving intervening operations commute with the proven inverse, preserving their actual positions. Missing inverse ancestry remains an explicit operation; an invalid claimed inverse or a history gap rejects. Reconstruction and composition each have a 32-million-unit work bound, 1,024 records, a two-MiB source limit and a one-million-unit inverse proof budget. This allows a held own edit to recognize canonical acceptance across verified peer Undo without inventing provenance from text equality.

`sourceDifferences` reconstructs exact ascending codepoint-safe splices from two source snapshots; repeated bytes cannot establish the actual user's original edit positions. Use it for explicit snapshot reconciliation or raw observed files, while connected editor transactions use their actual operation provenance. `applySourceSplices` applies splices from right to left; `rebaseSourceSplices` transforms them across a peer transaction and rejects genuine range overlap. Alignment is bounded by source bytes, 256 splices, edit distance 2,048, 16 million work steps and 4.5 million trace cells. Budget failure is explicit `diff_limit`; ordinary live reconciliation never falls back to a broad replacement across unchanged regions. The legacy single-envelope helper remains available only where the caller explicitly needs that envelope.

Observed raw files use `rawSourceDifferences`. Equivalent shifted insertion/deletion alignments through repeated codepoints, paragraphs or rotated tokens expand to a replacement envelope marked `ambiguous: true`; opposite-direction alignment also detects correlated rotations. Its source output remains exact while uncertain original characters lose their identity. The marker survives model history, inversion, rebasing and composition. Unsafe positions or pending edits return `ambiguous_source`, which requires recovery rather than collapsing a caret onto an arbitrary replacement edge. At an uncertain envelope, a left-associated lower endpoint and right-associated upper endpoint are provable outside anchors; the opposite associations and interior are unsafe. This preserves ordered appends at old EOF and edits outside the uncertain range. No-op raw writes with identical observed bytes remain unobservable; the model does not infer their intent.

`SourceModel.applyBatch` validates every splice before committing one revision, receipt and undo unit. A rejected range or failed application leaves the model unchanged. The application forks this state and publishes its complete candidate source once before acknowledging. Request identities cover canonical ordered splice tuples, independent of object-property order.

## Selective history and positions

Undo/Redo stores causal inverse references. Rebase cancels only proven original/inverse pairs and commutes intervening independent operations; text equality and shared actor identity do not justify skipping edits. Selective inverses split removal around later inserted peer text and honor peer deletions. Redo restores only the surviving owned fragments that were actually undone. A later replacement or retired source whose ownership cannot be proven is rejected for explicit review rather than erasing peer content or resurrecting retired text. Logical inverses with no byte change still advance the session revision so their causal history remains explicit.

If an intervening inverse has lost its original operation at the retention boundary, Undo/Redo returns `history_expired` before mutation. A still-retained deletion receipt alone cannot prove that its removed text remains eligible for restoration.

`transformPosition` validates its retained read revision and UTF-16 boundary, projects through the same transaction history, supports left/right insertion bias, and rejects deleted interiors. Presence and stream consumers can invalidate an anchor rather than paint or write at an unrelated location. History, inverse proof work and splice counts remain bounded.
