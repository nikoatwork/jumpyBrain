# Core canonical Markdown docs

## Responsibilities

- Discover, normalize, parse, and read canonical Markdown memory documents from a memory root.
- Extract inline Markdown links, full/collapsed/shortcut references with same-document definitions, and wiki links; ignore images, embeds, external URLs, and undefined shortcuts (including source citations). Reference labels are case/whitespace-insensitive; first definitions win and unused definitions produce no links. This lightweight extractor is not a full CommonMark parser.
- Resolve links through case-insensitive path/basename keys and optional valid frontmatter memory IDs; path-only callers remain supported. Duplicate IDs or ID/path collisions stay ambiguous, without source-relative fallback. Decode Markdown URL-encoded paths once, retain root-first Markdown/source-relative and wiki basename lookup, and reject root-escaping traversal before any fallback. Core link policy does not depend on graph presentation or transport code.
- ID-addressed document lookup scans only canonical memory buckets (`notes`, `findings`, `decisions`, `preferences`, `sessions`, `pages`) and returns exact file content plus a `sha256:<hex>` hash over current file bytes.
- Scanners retain normal build/log/report/dependency-directory and `gold`/`answer_session_ids` path exclusions. Only standalone Markdown with `source: logseq-migration`, a valid memory ID, matching `note`/`session` type, and exact `pages/<rel>` → `notes/<rel>` or `journals/<rel>` → `sessions/<rel>` source-path metadata bypasses those exclusions. No migration manifest or derived index is needed. Otherwise skipped nonhidden directories are traversed only beneath `notes`/`sessions` to find these envelopes; ordinary descendants stay excluded. Hidden technical directories and symlinks (including bucket entrypoints) are never reopened.
- ID-addressed document replacement keeps the root-relative path stable, merges protected metadata, exclusively stages/fsyncs a same-directory temp file, then atomically renames. App updates forward their required `ifMatch`; core checks it against the initial bytes, then rechecks those bytes, frontmatter ID, single-link regular-file identity and no-symlink directory identities immediately before publication. Conflicts retain `precondition_failed`; ordinary I/O failures propagate. Returned hashes describe the published bytes.
- Core updates serialize per real root in-process. An exclusive `.<filename>.replace.lock` guards final validation/publication across cooperating processes; contention fails closed, without waiting. Temp files/owned locks are removed on handled failures. A crash can leave hidden staging or a lock: remove a stale lock only after confirming no writer is active. This is not POSIX compare-and-swap: external writers ignoring the lock can race the last check/rename, replace path ancestors, or defeat cleanup. Directory fsync is best-effort; file fsync is required.
- Title metadata renames reject `duplicate_title` before replacement when another canonical Markdown file has the same NFKC-normalized, trimmed, case-insensitive title, including files without IDs. Empty/missing titles and equivalent-title edits do not enforce uniqueness, so legacy duplicates remain body-editable. This check scans canonical files, not an index; hosted updates run inside the shared write queue and core replacements serialize in-process. Title uniqueness is not locked across processes or against external filesystem writers.
- `resolveCanonicalMemoryDocumentByTitle` scans fresh canonical frontmatter using shared `normalizedDocumentTitle` (rename and daily capture use the same helper). It returns only `found` + ID, `missing`, `ambiguous` (including ID-less/invalid-ID title matches), or `unopenable` (invalid/duplicate ID or scan/read failure). It never falls back to headings, filenames, paths, fuzzy search, or the index, and never writes/stamps IDs.
- A unique title match must pass the editor's same-root ID lookup plus a file/frontmatter-ID/title recheck. These separate reads are not an atomic uniqueness guarantee against concurrent writes or subsequent editor GETs. Scans retain existing missing-directory/symlink policy; disappearing directories can be skipped, so not every concurrent deletion is detectable. Graph link semantics remain separate: paths/basenames and optional canonical IDs, not title metadata. Path renames can break filename references and filename reuse can retarget them.
- Keep Markdown files as the durable source of truth while derived indexes and caches remain rebuildable.
- Provide backend-agnostic helpers for app use cases and compatibility barrels.

## Non-responsibilities

- Do not write memory note or wrapup files.
- Do not import retrieval, QMD, CLI, server, HTTP, logging, or package metadata adapters.
- Do not treat derived state under `.jumpybrain/` as canonical memory.
- Do not assemble graph nodes/edges, filter graph views, or own runtime/server/HTTP graph packets.
