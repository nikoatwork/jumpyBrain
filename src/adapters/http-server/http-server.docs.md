# HTTP server adapter docs

## Responsibilities

- Implement the remote HTTP protocol, authentication, JSON request/response handling, and HTTP status-code mapping for `/health`, the content-free `/` and `/graph` browser shell, and `/memories/all/{status,index,overview,tree,graph.json,search,recall,recent,documents/:id,notes,wrapups,dream/...}`.
- Compose the framework-free browser shell in `graph-page.ts`: shared transport, document codec/save controller, and optional graph presentation. `notes-browser.ts` owns home, search/connection dialogs, full-page editing, and guarded navigation. `lexical-editor.ts` owns vanilla Lexical, selection/history, and Markdown conversion; never import that browser-only entry into the Node runtime.
- `npm run build` bundles pinned Lexical dependencies with esbuild into `dist/adapters/http-server/editor-bundle.js` plus `editor-LICENSES.txt`. The shell inlines this local bundle under its existing nonce (script terminators escaped). No CDN, React, separate frontend service, or production npm install is required. Pack validation requires both assets; bundle size has a 160 KB gzip review gate, not a promise that Node HTTP enables compression.
- Support ATX headings, bold/italic and literal page-reference spans directly while editing. Keep unchanged source lines verbatim and avoid writes on hydration/selection. Preserve unsupported Markdown as dotted-underlined editable literal blocks; disable formatting/shortcuts there rather than stripping syntax. Text/heading controls explicitly convert blocks. Edited supported lines can normalize delimiters; this is not full CommonMark/GFM round-tripping. Paste consumes plain text, never clipboard HTML. Frontmatter remains outside Lexical.
- Reset selection/history on every document transition, including empty-to-empty transitions. Keep undo/redo history across autosaves and restore Lexical ranges through search; do not rebuild the rich surface after each save.
- Use authenticated indexed search for Cmd/Ctrl+K, validate canonical IDs from `provenance.metadata.id` rather than QMD hit IDs, deduplicate document hits, and report index staleness including locally confirmed writes. Home and direct `/?note=<id>` loads do not fetch graph data. Preserve result-row DOM and scroll position during freshness/selection-only updates so autosave cannot detach a pointer gesture's click target. Search selection keeps the dialog visible until guarded navigation succeeds and explains blocked navigation instead of silently dismissing the result.
- The connection toolbar reflects successful authenticated requests, not merely a stored key. Settings keep draft key edits separate from transport credentials, mask keys unless explicitly revealed, and remask on close. Disconnect uses the navigation/save guard before removing the browser key and returning home; late responses from previous credentials cannot restore connected status. Disconnect forgets browser credentials, not server-side key authorization.
- Home prioritizes a filled New note action above outlined Search, aligned with recent notes; display platform-specific Cmd/Ctrl+Enter and Cmd/Ctrl+K hints and accessible shortcut metadata. Keep navigation and keyboard focus visible.
- Compose quick capture through authenticated idempotent `POST /memories/all/notes` with `{ type: "note", body: "", dailyDate: "YYYY-MM-DD" }` using the browser-local date. App/server-memory chooses the readable `YYYY-MM-DD_note_N` title inside the write queue; the writer supplies its heading. Never derive the suffix from browser state or indexed search.
- New note buttons and Cmd/Ctrl+Enter share one guarded flow. Handle the chord before Lexical's Enter handler without adding body text; leave browser New Window/Tab chords untouched and suppress repeat, composition, shifted/Alt chords, and creation inside dialogs. Retain the exact request/key after unconfirmed creation, suppress concurrent attempts, and restore history before unlocking a failed async creation. Retry state is tab-local, not crash recovery.
- Reuse the search dialog for literal `[[Exact Page Title]]` insertion via `[[` or Insert page reference. Preserve the draft/range, Lexical undo, cancellation and focus; block unsafe/missing or visibly duplicate titles and retain picker errors across save freshness updates. Do not imply collection-wide title uniqueness or title-based graph resolution; canonical link lookup remains filename-based. No editor/graph navigation or target write is needed for insertion.
- Share the semantic CSS tokens in `graph-page.ts` across home, map, editor, and all dialogs: white `--surface`, warm-grey `--control-fill`/`--surface-hover`, charcoal text, neutral borders, and a visible focus ring. No view-specific cream/green palettes or legacy color aliases. Graph categories use separate muted `--node-*` data accents; errors retain semantic red. The note view uses the same white surface with a borderless proportional-font editor and title field (no enclosing focus ring); navigation controls retain visible focus.
- Keep the memory map visually quiet: shared navigation, one heading, title/tag filter, secondary native Filters disclosure, refresh, and zoom/reset. Browser depth input is removed; graph APIs/CLI retain their depth contract and default. Inclusion defaults are unchanged; the displayed note count excludes missing-note placeholders. Bound long visual labels while retaining full accessible titles.
- Preserve background mouse drag-to-pan and wheel-to-zoom. Wheel zoom anchors under the pointer; +/− anchor at the visible canvas center, adjusting pan using the clamped scale ratio. The graph SVG has no viewBox, so local units match CSS pixels; revisit coordinate conversion if that changes. Horizontal-only wheel input must not zoom. Reset keeps the original scale-1/pan-0 behavior.
- Graph nodes reuse the canonical-ID full-page detail route and existing guarded browser history, not a separate preview/renderer. Returning restores the in-memory camera/filter context and originating node focus where available; no new persistent camera state or custom history stack. Keep filters above status feedback and close their disclosure on navigation.
- Edit page names as title metadata through the same serialized autosave/If-Match controller as the Markdown body, without rewriting filenames, headings, or references. Canonical updates reject duplicate renamed titles using fresh Markdown, not indexed search. Display save errors inline, retain rejected drafts, and resume autosave when a duplicate/invalid name is corrected. Unchanged legacy duplicate titles remain body-editable.
- Keep the persistent rich editor/caret stable through blur, search, saves, and reconciliation. Reconcile idle saved frontmatter only when the response body still matches the local body. Preserve 750 ms/blur autosave, sequential If-Match saves, retained failed drafts and explicit retry, unload protection, and the temporary one-retry last-write-wins policy. No-op edits and undo to a confirmed body report Saved without another write. Unconfirmed saves remain pending even after undoing to the previous body, because a lost response may hide a committed write.
- Guard in-app and Back/Forward navigation before abandoning a draft. Restore a history traversal to the current entry before flushing, replay it only on success, and keep the editor read-only until the approved destination is applied. Close modal dialogs on history navigation. Canonical whole-document/frontmatter policy remains in existing app/core seams.
- Start and stop the Node HTTP server used by the opt-in `serve` command.
- Call app/server-memory seams for server-local status, index, graph, search/recall, document reads/updates, writes, idempotency, dream batches, and auto-index state while hiding server filesystem paths from remote clients.
- Keep document update handling protocol-only: parse JSON and `If-Match`, run the update inside the shared write queue, map precondition errors to HTTP status codes, and log only method/path/status/id/file/stale/error-code metadata.
- `dream-handoff.ts` owns the memory-map **Consolidate notes (Dream)…** dialog and self-contained copyable agent prompt. Build it only on user request from a validated browser origin and frozen three-date UTC evidence window, without credentials, note bodies, network calls, or CLI imports. Submitting it explicitly authorizes bounded dream-page changes and indexing on that target; source preservation and budgets are agent instructions, not ACLs or spend guarantees. Keep auth/read-only/harness policies intact, copy exactly the selectable preview with manual fallback, invalidate late clipboard feedback after close/reopen, and integrate focus/shortcut/history guards. No provider selection, terminal launch, orphan workflow, or run/completion tracking. Warn about concurrent dream-page edits and refresh after external work.
- Keep dream route handling thin: authenticated GET `/memories/all/dream/window` validates query options and delegates read-only selection without the write queue. It never records dream state. Retain legacy batch routes/state transitions inside the shared write queue for compatibility, and log only route/status/batch/file-count/error-code metadata. Note creation accepts optional strict boolean `dream` metadata (including type page) through normal writing seams.
- Home shows up to eight recent notes as keyboard-accessible title/date links, using guarded navigation and native modified-click behavior. Reload on home entry and connection submission; abort superseded/leaving-home requests. Keep loading, empty, authentication, and retry states inline, with text-only untrusted titles. No graph or individual document fetch is needed to populate home.
- Authenticated GET `/memories/all/recent` delegates a fresh, read-only canonical scan to server-memory and returns `{ memory: "all", target: "remote", root: "remote:all", notes: [...] }`. The fixed eight-note cap is not query-configurable; no body, frontmatter, index status, or server root is returned. Other methods return 405 after authentication; failures return a generic `recent_failed` 500 without filesystem diagnostics.
- Share route literals with the HTTP client through `src/adapters/http-protocol.ts`; keep future route splits behind this adapter surface.

## Non-responsibilities

- Do not parse CLI command usage or target selection.
- Do not own canonical Markdown storage semantics, protected-frontmatter normalization, or server-memory workflows beyond delegating to app use cases; browser reconstruction is transport/UI state for the existing whole-document PUT contract.
- Do not run AI/model providers, schedulers, server-side prompt construction, or server-side memory consolidation for dreaming. Explicit client-side copyable instructions are presentation only, not execution or permission enforcement.
- Do not expose QMD adapter internals directly to CLI modules.
