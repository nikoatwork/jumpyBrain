# Browser and editor contract

Choose focused checks through [the testing guide](../../../docs/testing.md), including [WebSocket/editor failure scenarios](../../../docs/testing.md#live-editing-and-websocket-scenarios). The checks listed below are available feature coverage; run those affected by the change.

## Responsibilities

- Companion backend build mismatch notices explain that jumpyBrain and the CLI need matching software, rather than reporting an unavailable memory folder. Board collection failures reuse this static guidance for the same known code; arbitrary backend messages are not shown there.

- `browser-dropdown.ts` owns the shared `.dropdown` native select and quiet sidebar variant, including progressively enhanced themed pickers constrained to trigger width, wrapping options and viewport-edge placement. Call its idempotent `prepareDropdown` helper after creating/replacing options to add the browser-managed truncated selected label without hiding the arrow. Parent layout owns width; consumers retain native labels, validation, disabled/value/change handling and keyboard behavior. No custom focus/option controller or hidden-select synchronization. Unsupported hosted browsers keep their platform picker. Verify with `scripts/dropdown-smoke.mjs`.

- `browser-design-system.ts` owns shared type, spacing, control-size, radius and palette-derived hover tokens; icon-only controls retain their resting background/border and change glyph color, with nonshrinking centered targets. Disabled controls stay inert and selected/focus/status treatments remain distinct. `browser-theme.ts` owns scheme/palette preferences and default Ember colors; `browser-palettes.ts` owns the paired Ocean/Mono/Pride semantic alternatives. Follow [the browser design system](../../../docs/design-system.md) when changing UI. Ordinary sidebar destinations share one regular UI font role; controls use only regular/semibold weights. Home, New note, New board and global Search share an icon-only compact row with transparent resting borders/backgrounds and a visible border/fill for the current Home destination and companion theme preferences live in Settings → Appearance. Native-injected Updates uses the shared utility slot and icon target rules.

- Leaving the graph cancels pending layout/filter timers and drops its hidden SVG/listener tree. Keep the bounded graph packet, filters, selection and camera so Back/reopen can rebuild the same view; no editor draft/save-barrier or graph freshness policy changes.

- Shared Feedback has a message field, default-on **Include logs** checkbox with a hover/focus information tooltip, one Send action and an accessible top-right close icon. It has no diagnostic preview or email-client/download alternatives. `feedback.ts` uses schema-v1 safe events: at most 120 tab-local events, request duration/status/code and opaque correlation, confirmed/unconfirmed saves, external-refresh failures, exception/rejection/editor categories, safe shell line/column, and app/editor build fingerprints. Failures survive routine polling. No raw error text/stack, URLs, document IDs/titles/content, queries, keys/cookies, paths, provider output, raw filesystem logs, or crash dumps enter the report. Browser-only hosted reports explicitly have no server-log access. Browser history resets on reload.
- Companion Feedback collects sanitized gateway, owned local-server, native and Electron history through authenticated, generation/tab-fenced `GET /companion/diagnostics`. It neither starts a local engine nor reads remote-server logs. Collection is capped at two seconds; unavailable/degraded sources, buffer drops, coalesced healthy reads, truncated input bytes, and export omissions remain in the report. Host cache is brain/generation scoped for two seconds. Cancellation/late results cannot revive a closed dialog or an opted-out attachment. Attachment evidence freezes, with report-local correlation references. Runtime/editor fingerprints expose stale mixed builds.
- Feedback's primary action explicitly submits the message and optional diagnostics to same-origin authenticated `POST /feedback`; the host forwards only that report to the configured support relay. Nothing uploads on opening the dialog. Provider credentials stay on the relay. Success requires `{accepted:true,id}` matching the submission; failures retain the message and immutable report/UUID for retry, including close/reopen. Editing the report starts a new submission. Sending disables editing and duplicate sends while Escape/Close remain available. Reopening a pending submission shows its retained text without another send; session fencing suppresses late dialog effects. Feedback drafts and frozen retry submissions are tab-local in memory, independent of the selected brain, and survive close/reopen and local-backend reconnect. Reload/restart ends that scope; no feedback text or diagnostic attachment is persisted. Builds include the public relay URL from package metadata; explicit empty/custom overrides remain supported and packaging verifies the intended configuration. Opening cancels references and shortcuts cannot edit notes. See [deployment](../../../docs/feedback-delivery.md).

Producers call `systemMessages.dispatch({ source, text, severity, duration?, scope?, revision?, action? })` and `clear(source)` on resolution. `source` is a stable producer key, not a new ID per poll. `revision` distinguishes separate operations with identical text. `browser-toast.ts` is a compatibility re-export for note confirmations via `show`; it has no separate presentation or lifecycle.

One compact overlay anchored to the workspace bottom-left (clear of sidebar navigation) shows the highest severity, newest message first. Other sources remain pending, up to 16; overload evicts the oldest lowest-severity entry. Deduplication remembers at most 32 outcomes without retaining action closures. Identical updates neither reset visible time nor replay a dismissed/expired result; clearing a source permits recurrence. Ordinary messages expire after four visible seconds, actions/errors after eight; warnings default to persistent until dismissed/resolved, and explicit `duration: 0` supports an ongoing operation or session fence. Hover/focus pauses expiry. Close/expiry releases that entry and displays the next. Replacing a note confirmation releases its previous action. Focus returns to the prior connected control without stealing editor focus on arrival. Messages are text-only; errors use an assertive alert, other severities a polite status.

Default brain scope binds to credential revision/companion generation. `sync()` removes old-scope pending messages, deduplication and callbacks; action clicks recheck scope before running, including when a different message becomes current. Native update/host results explicitly use app scope. `stop()` removes listeners, timers and entries; pagehide clears tab state. No persistent notification history, dependency or polling is added. Canonical save/recovery controls, field validation, view empty/error states and active dialog instructions remain with their owners. Session Retry/Recover draft controls remain available even after dismissing the notice.
