# Browser and editor contract

## Responsibilities

- Shared Feedback defaults to an inspectable diagnostic attachment addressed to `jumpybrain@agentmail.to`. `feedback.ts` uses schema-v1 safe events: at most 120 tab-local events, request duration/status/code and opaque correlation, confirmed/unconfirmed saves, external-refresh failures, exception/rejection/editor categories, safe shell line/column, and app/editor build fingerprints. Failures survive routine polling. No raw error text/stack, URLs, document IDs/titles/content, queries, keys/cookies, paths, provider output, raw filesystem logs, or crash dumps enter the report. Browser-only hosted reports explicitly have no server-log access. Browser history resets on reload.
- Companion Feedback collects sanitized gateway, owned local-server, native and Electron history through authenticated, generation/tab-fenced `GET /companion/diagnostics`. It neither starts a local engine nor reads remote-server logs. Collection is capped at two seconds; unavailable/degraded sources, buffer drops, coalesced healthy reads, truncated input bytes, and export omissions remain visible. Host cache is brain/generation scoped for two seconds. Cancellation/late results cannot revive a closed dialog or an opted-out attachment. Preview evidence freezes, with report-local correlation references. Runtime/editor fingerprints expose stale mixed builds.
- Feedback exports UTF-8 MIME `.eml` with `jumpybrain-diagnostics.txt` attached. Budget the report to 21 KB and enforce 64 KiB on the complete encoded email, including worst-case Unicode messages. Mailto includes logs inline only below 8,000 characters; otherwise its button says message only. Email-client `.eml` editing/mailto support vary; the user reviews/sends or manually emails the visible address. No telemetry, mail credential, developer-service upload, or automatic sending. Closing/reopening preserves message/checkbox only in this tab, with a fresh snapshot. Opening cancels references, shortcuts cannot edit notes, and navigation/fencing closes the modal. No crash-persistent feedback text.
- The workspace toolbar shows the desktop brain contours as a monochrome, theme-adaptive mark in its top-right corner on Home, notes, graph, and Settings; it is decorative, outside the save-status live region, and remains visible on narrow layouts.
- The shared navigation brand visibly labels the app `(beta)`; beta status is separate from the numeric release version.
- Shared navigation uses a desktop left sidebar with compact note actions and page rows. Pinned pages precede the eight most recently visited unpinned pages; Graph sits with Settings/appearance at the bottom. `browser-page-navigation.ts` owns device-local title/ID navigation metadata in `jumpybrain.pageNavigation.v1:<scope>` storage: hosted data is origin-local and companion data is additionally scoped to the active brain profile ID and destination (so editing a profile to point elsewhere starts a separate history). Keep up to 30 visits and 50 pins, synchronize tabs, and fall back to tab memory when storage is unavailable. Only successful document opens count as visits; confirmed title changes update rows without reordering. Confirmed deletion/404 removes a page, while transient/auth errors retain it. Pin controls are available on the open page and individual sidebar rows, including read-only brains; they never write canonical memory. Titles are text-only, long titles truncate with full tooltips, and pinned pages do not repeat in Recent. A workspace toggle collapses the desktop sidebar without replacing the editor; `jumpybrain.sidebarCollapsed` remembers the preference, synchronizes tabs, and is read before paint. At narrow widths navigation stays visible as a compact top bar with horizontal page lists regardless of that desktop preference. Keep the active destination visible with `aria-current`, companion status beneath the brand, and save/recovery feedback in the content workspace. All destination links retain guarded navigation and companion brain scoping.

- Compose the framework-free browser shell in `graph-page.ts`: authentication/companion transport and injected document/map controllers. `document-controller.ts` owns typed save state, Markdown split/compose, and editable-title composition; transport, clocks, selection checks, and UI callbacks are explicit host dependencies. `map-controller.ts` owns fetch sequencing, notices, rendering, layout and camera through injected DOM/window, authenticated fetch, status and guarded-open callbacks. The shell retains guarded navigation and connection state. `notes-browser.ts` owns home, search/connection dialogs, full-page editing, and guarded navigation. `companion-browser.ts` owns the explicitly enabled companion settings/control UI; ordinary hosted `serve` does not enable it. `lexical-editor.ts` owns vanilla Lexical, selection/history, and Markdown conversion; never import that browser-only entry into the Node runtime.
- `npm run build` bundles `browser-entry.ts`, including pinned Lexical dependencies and the typed browser controllers, with the existing esbuild pipeline into `dist/adapters/http-server/editor-bundle.js` plus `editor-LICENSES.txt`. The shell inlines this local bundle under its existing nonce (script terminators escaped). No CDN, React, separate frontend service, or production npm install is required. Pack validation requires both assets; bundle size has a 160 KB gzip review gate, not a promise that Node HTTP enables compression.
- Support ATX headings, bold/italic and literal page-reference spans directly while editing. Keep unchanged source lines verbatim and avoid writes on hydration/selection. Preserve unsupported Markdown as dotted-underlined editable literal blocks; disable formatting/shortcuts there rather than stripping syntax. Text/heading controls explicitly convert blocks. Edited supported lines can normalize delimiters; this is not full CommonMark/GFM round-tripping. Paste parses plain-text Markdown with the same conservative grammar as loading, as one undoable edit; it never consumes clipboard HTML. Insertions within literal/code blocks stay literal, while replacing a whole block can introduce formatting. Empty clipboard text is a no-op. Frontmatter remains outside Lexical.
- Reset selection/history on every document transition, including empty-to-empty transitions. Keep undo/redo history across autosaves and restore Lexical ranges through search; do not rebuild the rich surface after each save.
- `external-document-updates.ts` checks the visible open note through the existing authenticated canonical GET about every two seconds, serially, with a ten-second read deadline and error backoff up to thirty seconds. Hidden/pagehide pages pause and abort; focus/pageshow return checks promptly. Document identity, credential/companion scope, baseline hash, draft revision, and reconciliation token fence late reads. No index/graph fetch, provider execution, new transport, or server cache is introduced. Canonical ID discovery currently scans the root on each GET; large brains, multiple tabs, and remote latency remain polling-cost limits.
- Clean external snapshots update the saved baseline without a PUT. Dirty, blocked, unconfirmed, saving, navigating, or stale-session editors retain their text and original hash; pending changes show "Changes available". Composition, recent field input/key/pointer interaction, title focus, text selection, and open dialogs defer acceptance. New body text uses Lexical's external-refresh path: retain scroll, map an idle caret through equal source lines where possible, and establish a new undo baseline so Undo cannot restore pre-refresh text. Changed/new nonblank source lines get a four-second theme-aware tint; reduced motion uses a static tint until removal. The accessible "Updated elsewhere" notice also covers title changes and deletions. Attribution and exact diff/merge history are not inferred. Decorations never enter Markdown. Read failures retain the current note; existing connection/recovery UI remains authoritative.
- Use authenticated indexed search for Cmd/Ctrl+K, validate canonical IDs from `provenance.metadata.id` rather than QMD hit IDs, deduplicate document hits, and report index staleness including locally confirmed writes. Home and direct `/?note=<id>` loads do not fetch graph data. Preserve result-row DOM and scroll position during freshness/selection-only updates so autosave cannot detach a pointer gesture's click target. Search selection keeps the dialog visible until guarded navigation succeeds and explains blocked navigation instead of silently dismissing the result.
- The connection toolbar reflects successful authenticated requests, not merely a stored key. Settings keep draft key edits separate from transport credentials, mask keys unless explicitly revealed, and remask on close. Disconnect uses the navigation/save guard before removing the browser key and returning home; late responses from previous credentials cannot restore connected status. Disconnect forgets browser credentials, not server-side key authorization.
- Home prioritizes a filled New note action above outlined Search, aligned with recent notes; display platform-specific Cmd/Ctrl+Enter and Cmd/Ctrl+K hints and accessible shortcut metadata. Keep navigation and keyboard focus visible.
- Compose quick capture through authenticated idempotent `POST /memories/all/notes` with `{ type: "note", body: "", dailyDate: "YYYY-MM-DD" }` using the browser-local date. App/server-memory chooses a readable date title (`October 14, 2026`, then `October 14, 2026 · 2`) inside the write queue, continuing sequences from legacy technical titles; the writer supplies `How is your day?` as the body heading. Never derive the suffix from browser state or indexed search.
- New note buttons and Cmd/Ctrl+Enter share one guarded flow. Handle the chord before Lexical's Enter handler without adding body text; leave browser New Window/Tab chords untouched and suppress repeat, composition, shifted/Alt chords, and creation inside dialogs. Retain the exact request/key after unconfirmed creation, suppress concurrent attempts, and restore history before unlocking a failed async creation. Retry state is tab-local, not crash recovery.
- Inline autocomplete retains matching option identities and the selected result while a newer query is loading. Its status reserves space to avoid moving options, and printable keydown events leave refresh to the committed input/selection update. Query cancellation and live insertion/session guards still apply; unrelated old options are removed. Global search retains its existing clear-on-query behavior.
- `reference-autocomplete.ts` installs inline suggestions for `[[` using an independent instance of the existing search controller and authenticated transport; Cmd/Ctrl+K stays global search and Insert page reference stays the explicit modal picker. Insert only literal exact-title text with live range/session revalidation and a single undo transaction; never navigate/mutate targets. `reference-policy.ts` supplies both pickers with `unsafe_title`, `missing_id`, and `visible_duplicate` eligibility reasons while each picker owns its messages and acceptance state. The range scanner reuses the same pure title predicate. Canonical ID format comes from browser-safe core `document-id-format.ts`; duplicate detection is limited to visible suggestions. `browser-transport.ts` constructs the shared search request and reuses protocol-owned document paths; authentication, abort signals, If-Match and companion generation/tab fencing remain with the existing host transport. Mark suggestions stale after actual saves; abort/dismiss on document, credential, modal, navigation/read-only transitions. Editor/listbox/active-option ARIA, separate live status, stable rows, and tap-versus-scroll handling retain editor focus.
- `reference-ranges.ts` owns conservative editor-only recognition. Recognize single-leaf titles in paragraphs/headings/bullets; leave formatted cross-leaf references inert. Unfinished suggestions require logical block end; the explicit picker can instead insert at the caret. Exact-length multiline backticks suppress code; unclosed spans and unsupported quote/list/indented fences suppress through EOF. These intentional false negatives are not a general Markdown parser. Keep inactive references literal too: activation state must not introduce escapes into existing filename/alias references or change graph semantics.
- Active page-reference brackets use a decorative CSS Custom Highlight at 24% ink over the current theme surface; titles and underlines retain their normal styling. Mutation-driven DOM ranges leave literal text, wrapping, selection and Markdown untouched; unsupported browsers retain ordinary brackets. Native selection takes precedence, and editor teardown removes its ranges.
- Normal click/tap, Tab→Enter, and click-only accessible activation resolve fresh titles after the existing save/history guard. Prefetch and validate the target ID/title/content before replacing the editor; failure retains the current draft with inline feedback. Cancel delayed lookup on modal/credential/history transitions, deduplicate repeat activation, and reuse the confirmed payload on route apply. Resolution is not atomic against later writers; rename/title reuse can break/retarget links. Drag selection/copy/arrow editing remain native; navigation wins the first click of a double click.
- Automated scope: desktop/narrow touch Chromium integration, DOM clipboard, synthetic composition, touch pan/tap, wrapped-caret/scroll/viewport geometry, and simulated zoom. Physical IME/mobile keyboards, OS clipboard, assistive technology, Safari/Firefox, and physical pinch zoom remain unverified; do not infer them from emulation. Production regression runners live in `scripts/{page-reference-editor,reference-autocomplete,page-reference}-smoke.mjs`; the feasibility editor/plugin/scanner forks are removed.
- `browser-theme.ts` owns shared semantic CSS tokens for Ember Light (parchment) and Ember dark (graphite), with coral focus/caret accents, readable secondary/error text, theme-aware graph lighting/backdrops/shadows, and muted `--node-*` data accents. Home, map, editor, autocomplete, dialogs, and companion settings consume these tokens rather than view-specific palettes. The borderless proportional editor/title keep the shared surface (no enclosing focus ring); navigation controls retain visible focus.
- The navigation theme selector offers System (default), Light, and Dark. A nonce-protected head bootstrap resolves appearance before content paints; System tracks live OS changes, and CSS also honors the OS without JavaScript. Explicit preferences persist under `jumpybrain.theme` independently of credentials/brain selection; storage events synchronize tabs and blocked storage degrades to tab-only selection. Theme changes never rehydrate the editor or navigate. Palette provenance and MIT notice: [Ember license](../../../docs/licenses/ember.txt). Verify with `node --test test/browser-theme.test.js` and `npx --package=playwright node scripts/theme-smoke.mjs` after building.
- The writing page uses a local Charter/Georgia serif stack, a bounded 680px text measure, responsive margins, and transparent formatting controls. Source lines remain separate blocks, with blank source lines supplying paragraph gaps. The title textarea grows on hydration/input/window resize; wrapping is visual only, pasted newlines are removed, and Enter moves to the body except during IME composition. Title metadata still uses the existing single-line validation/autosave path.
- Keep the memory map visually quiet: shared navigation, one heading, title/tag filter, secondary native Filters disclosure, refresh, and zoom/reset. Browser depth input is removed; graph APIs/CLI retain their depth contract and default. Inclusion defaults are unchanged; the displayed note count excludes missing-note placeholders. Bound long visual labels while retaining full accessible titles.
- The map's persistent polite status region presents server warnings as text, separates shown document counts from the whole-brain `stats.documents` count, and gives a filtering hint for the existing limit warning. The node cap includes unresolved targets; neither a filtered matching-total nor an exact omitted-note count is available. Do not infer truncation from counts alone or claim more matching notes exist: the existing producer can warn for exactly-limit filtered results. Clear old notices at refresh start; only the latest successful response replaces them, and cached layout redraws cannot restore a success notice after failure. Keep notices in layout above the canvas, not over its content or filter controls.
- Add depth only through presentation: a faint blue/lavender/sage wash beneath the SVG, a shared connection gradient, and shaded category-colored nodes with soft halos. Each connection keeps its count-based core width, with a narrow lit rim and opposite shaded rim for a rounded strand effect; decorative copies have no test identity or accessible/pointer target. Shared SVG definitions bound gradient/filter overhead; the background and decorative node circles do not receive pointer input. Visible labels also open their note; hidden labels remain inert. Preserve the same node positions, degree-based radii, connection counts, and shared theme-aware controls. No continuous animation or extra rendering engine is needed; existing reduced-motion rules cover hover transitions.
- Preserve background mouse drag-to-pan and wheel-to-zoom. Wheel zoom anchors under the pointer; +/− anchor at the visible canvas center, adjusting pan using the clamped scale ratio. The graph SVG has no viewBox, so local units match CSS pixels; revisit coordinate conversion if that changes. Horizontal-only wheel input must not zoom. Reset keeps the original scale-1/pan-0 behavior.
- Graph nodes reuse the canonical-ID full-page detail route and existing guarded browser history, not a separate preview/renderer. Returning restores the in-memory camera/filter context and originating node focus where available; no new persistent camera state or custom history stack. Keep filters above status feedback and close their disclosure on navigation.
- Edit page names as title metadata through the same serialized autosave/If-Match controller as the Markdown body, without rewriting filenames, headings, or references. Canonical updates reject duplicate renamed titles using fresh Markdown, not indexed search. Display save errors inline, retain rejected drafts, and resume autosave when a duplicate/invalid name is corrected. Unchanged legacy duplicate titles remain body-editable.
- Keep the persistent rich editor/caret stable through blur, search, saves, and reconciliation. Post-save reconciliation updates frontmatter only when the response body still matches the local body; visible-note external refresh owns accepting a different clean body under the guards above. Preserve 750 ms/blur autosave, sequential If-Match saves, retained failed drafts and explicit retry, unload protection, and fail-closed conflicts on ordinary and companion servers. On a confirmed 412, the browser rereads the canonical note and conservatively merges independent source-line edits or concurrent end additions against the last saved body. The same idle/selection/composition/dialog guards apply before and after that read, with document/scope/revision/hash fencing. `document-merge.ts` treats each side as one contiguous range and refuses overlapping or same-line replacements; title disagreements also require review. Retry at most twice against fresh If-Match hashes. Conflicts, failed reads, and continuing contention retain the draft with friendly Review changes feedback and block switching. Uncertain saves never enter this automatic merge path. No-op edits and undo to a confirmed body report Saved without another write. Unconfirmed saves remain pending even after undoing to the previous body, because a lost response may hide a committed write.
- Guard in-app and Back/Forward navigation before abandoning a draft. Restore a history traversal to the current entry before flushing, replay it only on success, and keep the editor read-only until the approved destination is applied. Close modal dialogs on history navigation. Canonical whole-document/frontmatter policy remains in existing app/core seams.
- `dream-handoff.ts` owns the memory-map **Consolidate notes (Dream)…** dialog and self-contained copyable agent prompt. Build it only on user request from a validated browser origin and frozen three-date UTC evidence window, without credentials, note bodies, network calls, or CLI imports. Submitting it explicitly authorizes bounded dream-page changes and indexing on that target; source preservation and budgets are agent instructions, not ACLs or spend guarantees. Keep auth/read-only/harness policies intact, copy exactly the selectable preview with manual fallback, invalidate late clipboard feedback after close/reopen, and integrate focus/shortcut/history guards. No provider selection, terminal launch, orphan workflow, or run/completion tracking. Warn about concurrent dream-page edits and refresh after external work.
- Home shows up to eight recent notes as keyboard-accessible title/date links, using guarded navigation and native modified-click behavior. Reload on home entry and connection submission; abort superseded/leaving-home requests. Keep loading, empty, authentication, and retry states inline, with text-only untrusted titles. No graph or individual document fetch is needed to populate home.
Map-warning verification: build first, then `node --test test/graph.test.js` and `npx --package=playwright node scripts/graph-warning-smoke.mjs`. The smoke serves 501 disposable Markdown notes through the production graph route and checks the unchanged 500-node cap, filtered/global counts, empty/uncapped responses, safe warning text, unresolved targets, refresh/failure/retry, and notice layout at 1280/390/320 px without indexing or touching the installed app. `scripts/graph-editor-smoke.mjs` retains the indexed editor/Dream/map navigation regression coverage.

## Companion-only browser contract

The loopback companion gateway opts in with `graphPageHtml(nonce, view, { companion: true })` and serves the same reloadable shell at `/settings`, `/`, and `/graph`. No companion markup/bootstrap/control calls are enabled by the ordinary two-argument shell. Existing nonce CSP and local editor bundling remain unchanged; no CORS, framework, or browser-held target API key is introduced.

- `companion-browser.ts` owns named local/remote profile forms, active destination/health/read-only presentation, native folder selection, edit/remove/test/switch actions, registration, polling, and the all-tab acknowledgement client. Settings uses the existing navigation/save guard, not a competing connection dialog. Local selection never initializes a root. Remote editing approval is an unchecked, explicit target-specific checkbox by default.
- Companion Settings also owns explicit search-index refresh, removed alongside brain switching from the native menu. Refresh uses the existing generation/tab-fenced `POST /memories/all/index` transport, never an implicit CLI root; disable it while offline, read-only, frozen, unregistered, or running another Settings action. Report unconfirmed failures inline without retrying automatically. Native-only login/update and recovery actions remain grouped in menu submenus.
- A fragment `#companion=<token>` is consumed into `POST /companion/session { token }` and erased before requests. Without a fragment, use the existing same-origin cookie. Tokens and real API keys are never persisted to localStorage; ordinary browser-key storage is neither read nor changed in companion mode. The harmless in-memory `activeApiKey = "companion-session"` satisfies existing UI gates but is never sent as Bearer authorization.
- The gateway exposes cookie-authenticated `GET /companion/state` and POST `profiles { profile, revision }`, `remove { id, revision }`, `test { id }`, `select-folder {}`, `switch { id }`, `register/poll/unregister { tabId, generation }`, and `ack { tabId, switchId, ok }`. State carries `{ profiles, activeId, revision, generation, phase: "idle" | "preparing", switchId, health, active, target }`; profiles/active must omit keys. Revision conflicts remain visible rather than resubmitting edits against changed profiles. The masked key field is write-only; blank editing omits `key` to preserve Keychain. Submission/cancel/leaving settings/pagehide clears the transient field.
- Every page has a fresh, nonpersistent tab ID. Registration completes before any initial memory fetch. All memory requests carry `X-Companion-Generation` and `X-Companion-Tab`; the gateway must fence stale traffic with 409 `stale_generation` and enforce target authorization. Polls run approximately every 750 ms **after** the previous asynchronous poll settles, never concurrently. `pagehide` unregister uses keepalive; BFCache restoration re-registers before reopening editing. Transport/session failure freezes the draft and explains recovery; it is not a successful target health check.
- Only entering a frozen/fenced state cancels references and closes Search/Dream; unchanged healthy idle polls preserve dialogs, in-flight queries, and reference suggestions while still synchronizing permissions. Repeated frozen snapshots do not repeat destructive cancellation.
- Preparing freezes the editor, title, navigation, graph controls, creation, formatting, references, and settings mutations. An already-started creation/navigation/document load must settle; the client then flushes its current editor against the old generation. Failed/unconfirmed saves and unconfirmed idempotent note capture send a negative acknowledgement. No discard, creation replay on another brain, or 412 overwrite is allowed. The client stays frozen after acknowledgement until authoritative idle; failed switches unfreeze the same draft. A ten-second client wait for busy navigation is only a negative-ack bound, never permission to remove a tab. The coordinator remains responsible for fail-closed missing acknowledgements, old in-flight requests, and activation/persistence.
- A changed generation reloads to `/?brain=<activeId>` or `/settings?brain=<activeId>` before adopting new state, clearing old note query/editor/search/reference/graph/capture state. History and native links are scoped by `brain`; old or unscoped note URLs are rejected before document GET, even when IDs are identical across targets. Browser Back to old entries must not silently resolve IDs on a different brain.
- Dream handoff uses the actual authorized remote profile URL, never the loopback gateway. Read-only remote and local profiles receive an explanation and no generated prompt; local CLI root instructions are not invented. The existing handoff validator requires a credential-free HTTP(S) origin.

Verification: `node --test test/companion-browser.test.js test/notes-browser.test.js test/daily-notes-browser.test.js test/dream-handoff.test.js`; build first. `npx --package=playwright node scripts/companion-browser-smoke.mjs` exercises the production shell/editor with a disposable cookie-authenticated control fixture: settings/key handling, Search from Home/navigation and delayed queries across idle polls, inline suggestion survival/insertion, local Dream explanation survival, two-tab freeze/flush, uncertain creation, same-document conflict-stop, target-scoped reload/history links, remote read-only policy, serialized slow polls, and session failure. This fixture is not verification of native Keychain/folder UI, real target proxying, coordinator crash durability, sleeping OS tabs, physical IME, Safari, or Firefox; those belong to companion integration tests/manual checks. It does not modify the installed app or personal memory.

## Browser verification

`npm run smoke:page-references` builds and runs production editor preservation/context regressions, isolated autocomplete/controller checks with stub transport, and real disposable-root/QMD/server integration (navigation, save failures, cancellation, history, search freshness, insertion and touch scrolling). Set `JUMPYBRAIN_REFERENCE_SMOKE_BENCH=1` for small/large-note app timings, or `JUMPYBRAIN_REFERENCE_EDITOR_BENCH=1` for isolated editor timings. Historical feasibility entrypoints forward to these production runners; no second editor is maintained.

`npm run smoke:lexical` checks formatted heading/emphasis editing, toolbar undo, Markdown preservation (including edits within unsupported blocks), exact reference titles, empty-document history isolation, safe paste, and desktop/mobile layout in a disposable root. It needs no QMD index. Set `JUMPYBRAIN_SMOKE_SCREENSHOT_DIR` to retain screenshots. Unsupported syntax stays literal; edited supported lines may normalize delimiters. This is a deliberately small Markdown subset, not a general rich-document conversion guarantee.

`npm run smoke:daily-capture` runs disposable-root Chromium desktop/mobile checks for dated creation, auth, lost-response retries, duplicate suppression, reference insertion/editor undo, autosave failures, and saved-note discovery after explicit indexing. `JUMPYBRAIN_SMOKE_SCREENSHOT_DIR` optionally retains screenshots. Automated key events verify app handling, not delivery by every headed browser/OS; Safari, Firefox, physical devices, and OS-level shortcut reservations require separate QA.

`npm run smoke:graph` runs a Playwright browser smoke test against a live server's `/graph` page. It requires Playwright's Chromium (`npx playwright install chromium`) and two environment variables:

- `JUMPYBRAIN_GRAPH_SMOKE_URL` — base URL of the running jumpyBrain server (e.g. `http://localhost:5173`).
- `JUMPYBRAIN_GRAPH_SMOKE_API_KEY` — a valid server API key; passed to the page via the `#apiKey=` fragment (not sent to the server).

The script verifies the graph loads, renders SVG nodes/edges, filters metadata, and opens a valid canonical node full-page without writing. Optional `JUMPYBRAIN_GRAPH_SMOKE_NODE_ID` chooses a specific root-relative graph node. On failure it writes `scripts/graph-ui-smoke-failure.png`.

`npm run smoke:graph-editor` starts an isolated server over a disposable memory root and real QMD index. Desktop and mobile flows exercise empty-home entry, title/body search, full-page editing, persistence, caret/scroll stability, modal focus, durable URLs, Back/Forward, stale-index feedback, failed-save/undo recovery, and mobile authentication recovery. It also runs the read-only graph smoke against that same fixture server. It never writes to a live memory root. Set `JUMPYBRAIN_SMOKE_SCREENSHOT_DIR` to an output directory to retain fixture screenshots for visual review.

Browser Back/Forward restores the current history entry before a pending-save flush and replays the traversal only on success. Failed drafts remain reachable with Retry. After an unconfirmed write, even undoing to the previously saved body still requires Retry: a failed network response may hide a committed server write. Closing search preserves rich-editor focus, caret, and scroll; title/frontmatter are never interpreted as browser HTML.

## Non-responsibilities

- Canonical publication, protected frontmatter, ID uniqueness, and title uniqueness belong to core/app. Browser guards do not replace them.
- Public HTTP schemas, authentication, CSP, compatibility, and wire errors belong to the [protocol reference](../../../docs/shared-memory-protocol.md).
- Native ownership, Keychain, launch agents, and gateway coordination belong to the companion integration. Browser smokes do not establish device readiness.

## Controller verification

Behavioral tests directly import the typed document/map controllers, shared reference eligibility, and request construction. Save serialization, lost responses, reconciliation, ordinary versus companion conflicts, newline preservation, camera anchoring and warning races remain behavioral regressions. Shell parse, nonce/CSP, local bundle and script-terminator checks remain production integration checks. `scripts/browser-shell-test-helpers.mjs` is transitional extraction plumbing only for functions still composed in the shell; new logic belongs in typed modules.

Smoke runners use `scripts/playwright-runtime.mjs` for Chromium loading and launch. Launch options survive the missing-executable fallback; `JUMPYBRAIN_PLAYWRIGHT_CHANNEL` selects its default fallback channel. Explicit channels or disabled fallback fail directly. Shared `editor-smoke-helpers.mjs` continues to own editor interaction plumbing; isolated scanner/controller checks, real HTTP/browser fixtures and companion gateway coordination remain separate coverage.

## Note lifecycle and recovery controls

`document-actions.ts` owns accessible comparison/deletion dialogs over the existing typed editor. Conflicting edits expose Review changes; other failed saves expose Recover draft; Copy draft is available for every loaded note and falls back to selectable text when clipboard access fails. Comparison reads the current saved note without writing. Explicit **Discard draft and load saved note** rereads on acceptance and applies only to the same editor/scope/revision, with no silent overwrite. Frozen/read-only states cannot discard/reload or delete; copying remains available. Preparing/generation changes close inactive dialogs; active actions settle before acknowledgement. Dialog bodies are cleared on close.

**Delete note…** first flushes the current draft, requests a guarded preview and shows the selected title, irreversible-removal warning and advisory inbound-link counts. Confirmation submits one DELETE with the reviewed hash. Stale previews fail closed; unconfirmed removals never retry automatically. Cancel leaves the file intact. Confirmed removal returns Home, invalidates graph/cache, suppresses the deleted indexed hit in this tab, and reports pending/failed index work separately. No Trash or backlink rewrite is implied.

`recent-write-search.ts` keeps at most 50 confirmed writes and 50 deletion tombstones in tab memory, with body search bounded to 32 KiB per saved note. Global search and reference suggestions merge matching local saves ahead of stale indexed versions. Superseded titles/bodies cannot reappear through an older hit. A verified fresh server generation retires cached writes/tombstones unless a new write arrived during the query; exact indexed title matches stay ahead of body-only local matches. Results/cache are scoped to credential revision/companion generation and cleared on scope change; no localStorage persistence or cross-brain reuse. Backend failure can return explicitly labeled matching saves from this tab, never an apparently complete search. Other tabs/external edits still require indexing. Stale search includes explicit Refresh search index, permission-gated and never automatic on each keystroke.

Narrow map filtering gets its own full-width row at 390/320 px. Featured labels are measured and suppressed on overlap/canvas-edge collisions, retaining full accessible titles and focus/hover reveal; core graph nodes and connection meaning are unchanged. Expired sessions expose Retry and Recover draft directly above the page; messages distinguish retrying a valid cookie from reopening through the companion for a fresh session.

Verification: build, `node --test`, and `npx --package=playwright node scripts/note-lifecycle-smoke.mjs` exercise the real server/QMD engine over a disposable root: immediate saved-note discovery, title-link map consistency, two-tab conflicts/reload, 390/320 filtering/labels, deletion cancel/apply, preserved surviving backlinks and index refresh. Optional screenshot output uses `JUMPYBRAIN_SMOKE_SCREENSHOT_DIR`. Physical devices, assistive technology and other browsers remain separate gates.
