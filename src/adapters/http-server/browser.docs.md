# Browser and editor contract

## Responsibilities

- `browser-dropdown.ts` owns the shared `.dropdown` native select and quiet sidebar variant, including progressively enhanced themed pickers constrained to trigger width, wrapping options and viewport-edge placement. Call its idempotent `prepareDropdown` helper after creating/replacing options to add the browser-managed truncated selected label without hiding the arrow. Parent layout owns width; consumers retain native labels, validation, disabled/value/change handling and keyboard behavior. No custom focus/option controller or hidden-select synchronization. Unsupported hosted browsers keep their platform picker. Verify with `scripts/dropdown-smoke.mjs`.

- `browser-design-system.ts` owns shared type, spacing, control-size and radius tokens; `browser-theme.ts` owns scheme/palette preferences and default Ember colors; `browser-palettes.ts` owns the paired Ocean/Mono/Pride semantic alternatives. Follow [the browser design system](../../../docs/design-system.md) when changing UI. Ordinary sidebar destinations share one regular UI font role; controls use only regular/semibold weights. Home, the New note compose icon and labeled global Search share a compact row and theme uses one accessible sun/moon toggle. Native-injected Updates uses the shared utility slot and icon target rules.

- Leaving the graph cancels pending layout/filter timers and drops its hidden SVG/listener tree. Keep the bounded graph packet, filters, selection and camera so Back/reopen can rebuild the same view; no editor draft/save-barrier or graph freshness policy changes.

- Shared Feedback has a message field, default-on **Include logs** checkbox with a hover/focus information tooltip, one Send action and an accessible top-right close icon. It has no diagnostic preview or email-client/download alternatives. `feedback.ts` uses schema-v1 safe events: at most 120 tab-local events, request duration/status/code and opaque correlation, confirmed/unconfirmed saves, external-refresh failures, exception/rejection/editor categories, safe shell line/column, and app/editor build fingerprints. Failures survive routine polling. No raw error text/stack, URLs, document IDs/titles/content, queries, keys/cookies, paths, provider output, raw filesystem logs, or crash dumps enter the report. Browser-only hosted reports explicitly have no server-log access. Browser history resets on reload.
- Companion Feedback collects sanitized gateway, owned local-server, native and Electron history through authenticated, generation/tab-fenced `GET /companion/diagnostics`. It neither starts a local engine nor reads remote-server logs. Collection is capped at two seconds; unavailable/degraded sources, buffer drops, coalesced healthy reads, truncated input bytes, and export omissions remain in the report. Host cache is brain/generation scoped for two seconds. Cancellation/late results cannot revive a closed dialog or an opted-out attachment. Attachment evidence freezes, with report-local correlation references. Runtime/editor fingerprints expose stale mixed builds.
- Feedback's primary action explicitly submits the message and optional diagnostics to same-origin authenticated `POST /feedback`; the host forwards only that report to the configured support relay. Nothing uploads on opening the dialog. Provider credentials stay on the relay. Success requires `{accepted:true,id}` matching the submission; failures retain the message and immutable report/UUID for retry, including close/reopen. Editing the report starts a new submission. Sending disables editing/duplicate clicks/ordinary dismissal until it settles; forced session fencing still closes the dialog. No crash-persistent feedback text. Builds include the public relay URL from package metadata; explicit empty/custom overrides remain supported and packaging verifies the intended configuration. Opening cancels references and shortcuts cannot edit notes. See [deployment](../../../docs/feedback-delivery.md).
- The sidebar header is the single visible brand location: a compact serif `jumpyBrain` Home link with italic `jumpy` and semibold `Brain` beside the collapse toggle. The old beta suffix and duplicate workspace brain mark are removed. Mac windows receive host-owned `data-native-mac=true` for traffic-light insets and header drag regions; ordinary hosted/browser shells reserve no native-control space. Interactive controls, brain selectors and tooltips/popovers opt out of dragging.
- Confirmed feedback success clears the submitted draft, closes the dialog, restores Feedback focus and dispatches one app-scoped shared thank-you message keyed by submission ID. Support delivery is independent of the selected brain. Forced close/session transitions suppress late success/failure UI; failed/unconfirmed sends retain the frozen retry report. A new dialog after success collects fresh evidence.
- Shared navigation uses a desktop left sidebar with Home, New note compose and labeled global Search actions, a visually continuous page list with pinned notes first and even row spacing, then a compact Graph/Settings/Feedback and theme/update icon row. The native update control stays icon-only, using a readiness glow with a traveling highlight on its fixed rounded border (static under Reduced Motion) and tooltip/accessibility text; it never adds a status/details row. Pinned and Attention have accessible list labels without visible section headings. `browser-page-navigation.ts` retains device-local pins under `jumpybrain.pageNavigation.v1:<scope>` (50 maximum), preserving existing stored pins and synchronizing tabs; hosted data is origin-local and companion pins are profile/destination-scoped. Visit history is retained for compatibility but no longer selects sidebar notes. Pinned pages stay visible independent of settle/snooze and are deduplicated from Attention. Pin, Snooze and Settle live in sidebar rows (including pinned rows); the note toolbar has no duplicate attention/pin controls. Initialize lifecycle guards before consulting them during stored-pin hydration. Pins are navigation preferences, including on read-only brains; they never write canonical memory. Empty Pinned has no helper copy or reserved section gap. Stable unchanged row DOM preserves pointer/focus targets across autosaves. Titles are text-only with full tooltips, guarded navigation and companion brain scoping. The toggle persists `jumpybrain.sidebarCollapsed` before paint without rebuilding the editor; it moves between the sidebar header and collapsed workspace toolbar while retaining focus. Narrow navigation keeps horizontal page lists and a reachable collapse/expand toggle. Native collapsed headers retain the traffic-light inset, including full-screen transitions. Global Search/Cmd+K and guarded New note/Cmd+Enter keep their existing scope and save behavior.

- `workspace-navigation.ts` owns the typed save/restore navigation controller and a six-destination tab-local app trail (current plus five previous destinations). The workspace header places accessible Back/Forward icon controls beside the sidebar, after the collapse toggle when collapsed. Controls disable at trail boundaries, during pending navigation and companion freezes. They traverse existing browser entries through the save guard; a new destination drops Forward, and reload/brain changes start a fresh trail. Settings is hidden from this trail and keeps its Back to app action; returning from Settings to the same app destination updates its browser-entry position without adding a duplicate. Graph-to-note Back reuses retained graph filters/camera. Ordinary browser history remains available beyond the control window.

- `note-workspace.ts` owns the explicit Format disclosure, compact view-only Page details disclosure, empty-body guidance and saved-version presentation. Format is closed on document entry, retains its state through saves/theme changes, and never remounts the editor or writes. Pointer opening retains the editor selection; keyboard formatting reuses the editor’s captured selection. Escape is scoped to the trigger/format controls and defers to dialogs/slash/reference popups. Link stays directly reachable outside the fold. Details is closed on entry and scope/navigation changes, anchors below its toolbar button without moving or narrowing prose, and closes on outside pointer, Close or Escape with trigger focus restored for Close/Escape. It contains saved-version/editor/date/location facts, source checks and raw Markdown metadata. There is no section outline/count. Related pages stay below the writing surface, independent of details. Accessible icon-only Copy and Delete sit together in the toolbar; save/retry/review/recovery remain directly reachable.
- Saved-version editor/date/location context travels atomically with accepted document baselines and confirmed PUT responses in `document-controller.ts`; missing fields clear older claims. Dirty/rejected/stale reads cannot relabel the saved revision. Only current revision-checked recognition can name a declared person/agent; You requires the exact local browser actor ID. The label describes the saved version, never all text in an unsaved draft or authenticated presence. Date-only metadata stays a calendar date, and invalid dates remain unknown. Clean loaded baselines say Saved; unconfirmed/failed drafts never do. Empty writing guidance is presentation only, is hidden on read-only or nonempty/literal/code surfaces and never enters Markdown. Verify with `test/note-workspace.test.js`, `test/external-document-updates.test.js`, `scripts/note-workspace-smoke.mjs` and the production Electron smoke.

Narrow layouts use a compact section row; panel motion respects Reduced Motion. `browser-appearance.ts` supplies native radio-card groups: decorative CSS System/Light/Dark miniatures and paired Ember/Ocean/Mono/Pride swatches. Selection applies immediately, preserves editor state and synchronizes with the footer toggle and same-origin tabs. `jumpybrain.theme` remains the scheme key; `jumpybrain.palette` stores nondefault palette IDs, with invalid/missing values falling back to Ember. Legacy `grove` preferences resolve to `mono` before paint and are rewritten when storage permits; old cross-tab values also resolve to Mono. The shared bootstrap applies both before paint and handles blocked storage in-tab. Choosing a built-in option emits `jumpybrain-appearance-change` so the optional extension controller clears its selected overrides. Graph rendering observes both `data-theme` and `data-palette`. Leaving Brains clears connection-form secrets. Ordinary hosted connection dialogs remain unchanged.
- Companion Settings puts brains first in a semantic list with muted health dots, active-row accessibility, truncated destination paths with full tooltips, and small named icon actions. Failed/read-only captions remain separate from path truncation. Search refresh is one icon beside the Brains breadcrumb, with accessible busy/target/disabled details and existing permission gates; it has no standalone section. Extensions has its own section with a heading-aligned reload icon and a palette row only when custom themes are available. Empty extension status reserves no space. The sidebar footer places the active brain in a full-width row above its utility icons and below the divider. It shows a static brain name for one connection and a stable shared quiet dropdown for multiple connections; all selection paths share the existing guarded switch action. Active connections cannot be removed in the UI. Add/Edit asks for the destination before an optional inferred name; only applicable fields participate in native validation. Server failures stay inline and retain entered fields; success/cancel/pagehide clear keys. Save does not select the brain: a scoped success message offers Switch. Closing the form restores focus to Add connection. Keep explicit per-brain write consent and session/draft recovery controls.
- `npm run build` bundles `browser-entry.ts`, including pinned Lexical dependencies and the typed browser controllers, with the existing esbuild pipeline into `dist/adapters/http-server/editor-bundle.js` plus `editor-LICENSES.txt`. The shell inlines this local bundle under its existing nonce (script terminators escaped). No CDN, React, separate frontend service, or production npm install is required. Pack validation requires both assets; bundle size has an 187 KB gzip review gate (approximately 186.2 KB with folded formatting and compact note context; no new dependencies), not a promise that Node HTTP enables compression.
- Support ATX headings, bold/italic and literal page-reference spans directly while editing. Keep unchanged source lines verbatim and avoid writes on hydration/selection. Preserve unsupported Markdown as editable literal blocks without decorative underlines; disable formatting/shortcuts there rather than stripping syntax. Text/heading controls explicitly convert blocks. Edited supported lines can normalize delimiters; this is not full CommonMark/GFM round-tripping. Paste parses plain-text Markdown with the same conservative grammar as loading, as one undoable edit; it never consumes clipboard HTML. Insertions within literal/code blocks stay literal, while replacing a whole block can introduce formatting. Empty clipboard text is a no-op. Frontmatter remains outside Lexical.
- Reset selection/history on every document transition, including empty-to-empty transitions. Keep undo/redo history across autosaves and restore Lexical ranges through search; do not rebuild the rich surface after each save.
- `external-document-updates.ts` checks the visible open note through the existing authenticated canonical GET about every two seconds, serially, with a ten-second read deadline and error backoff up to thirty seconds. Hidden/pagehide pages pause and abort; focus/pageshow return checks promptly. Document identity, credential/companion scope, baseline hash, draft revision, and reconciliation token fence late reads. No index/graph fetch, provider execution, new transport, or server cache is introduced. Canonical ID discovery currently scans the root on each GET; large brains, multiple tabs, and remote latency remain polling-cost limits.
- External updates are writer-independent: saves from another user’s editor, agent CLI updates, and direct Markdown edits use the same refresh, highlighting, and draft-protection path. `scripts/external-document-updates-smoke.mjs` verifies another editor in an isolated browser context alongside CLI/filesystem changes. Clean external snapshots update the saved baseline without a PUT. Dirty, blocked, unconfirmed, saving, navigating, or stale-session editors retain their text and original hash; pending changes show "Changes available". Composition, recent field input/key/pointer interaction, title focus, text selection, and open dialogs defer acceptance. New body text uses Lexical's external-refresh path: retain scroll, map an idle caret through equal source lines where possible, and establish a new undo baseline so Undo cannot restore pre-refresh text. Changed/new nonblank source lines get a four-second theme-aware tint; reduced motion uses a static tint until removal. The accessible "Updated elsewhere" notice also covers title changes and deletions. Attribution and exact diff/merge history are not inferred. Decorations never enter Markdown. Read failures retain the current note; existing connection/recovery UI remains authoritative.
- Use authenticated indexed search for Cmd/Ctrl+K, validate canonical IDs from `provenance.metadata.id` rather than QMD hit IDs, deduplicate document hits, and report index staleness including locally confirmed writes. Home and direct `/?note=<id>` loads do not fetch graph data. Preserve result-row DOM and scroll position during freshness/selection-only updates so autosave cannot detach a pointer gesture's click target. Search selection keeps the dialog visible until guarded navigation succeeds and explains blocked navigation instead of silently dismissing the result.

Reference scanning masks code with non-whitespace sentinels of the same UTF-16 length, avoiding accidental indented-code classification of adjacent prose. Page-reference nodes suppress Markdown shortcuts without passing an internal code-format flag into newly typed prose. History is seeded after document hydration so the first pointer toggle can undo even before a caret has been placed. External refresh maps source-line ranges across multiline code blocks and restores the caret through Lexical, with no save on hydration, selection, theme or highlighting.

Pipe tables with at least two columns, a matching `---`/`:---`/`---:`/`:---:` delimiter row (three or more dashes), consistent body widths and optional outer pipes render as a semantic, horizontally scrolling table. Escaped pipes and matching inline-code spans do not split cells. Cells display inert text; inline emphasis/link/code syntax is preserved visibly. The **Table Markdown** disclosure exposes the same editable source, with literal newlines/Tab and Ctrl/Cmd+Enter to continue below. Load/plain-text paste recognizes tables; typing a new table requires reopen/paste to produce a preview. Invalid edits open the source disclosure and keep all text; malformed/ragged tables, one-column tables and indented code remain literal. Source edits, undo and external refresh never use preview text for serialization. This is source editing with a preview, without cell editing, row operations, rich cell markup or full GFM support.

Standard `**bold**` and `__bold__` already render. Whitespace just inside the delimiters (`** bold **`, `**bold **`) stays literal; ambiguous syntax is not silently repaired. Untouched valid and literal examples remain byte-preserved through unrelated saves.

Active page-reference brackets have empty, zero-advance glyphs while reading, so they leave no gaps or extra wrapping. Only the currently edited/selected blocks restore brackets; blur, focus on another block and read-only mode collapse them. `reference-marker-font.ts` embeds an original two-glyph WOFF generated by the optional `scripts/build-reference-marker-font.py` authoring tool (Python fontTools, not a build/runtime dependency). The buffered FontFace loads once per document with no network request or CSP exception; title glyphs fall back to the writing font. The original single text leaf, selection offsets, copy, exact `[[title]]` export and keyboard/pointer navigation remain intact. Font-load failure retains ordinary visible brackets. Inline/fenced code and inert references keep literal presentation. Literal bullets retain reference completion through the shared source scanner; their internal shortcut-suppression flag does not classify them as code.

`editor-slash-commands.ts` offers `/text` (`/paragraph`), `/h1`, `/h2`, `/h3`, `/bold`, `/italic`, `/checkbox` (`/task`), `/code` (`/inline-code`) and `/code-block` (`/codeblock`). A collapsed caret after a slash token at the beginning of a plain paragraph/heading (optional leading whitespace) opens the filtered listbox. Arrow keys select, Enter accepts and Escape preserves literal text. Acceptance consumes only the token before the caret, preserving any suffix, and calls the toolbar's shared operation in one history transaction. Inline actions set the format for subsequent typing. URLs, mid-sentence slashes, literal/code/task/table blocks, selections, composition and read-only locks do not invoke commands. Blur/modal navigation and session/document replacement invalidate the live range; acceptance revalidates it. The menu retains editor focus and shares ARIA controls with reference suggestions.

## In-note find and control labels

`note-find.ts` owns Cmd/Ctrl+F and the native `jumpybrain:find` menu event, scoped to a loaded note’s rendered body. CSS Highlight ranges show case-insensitive literal matches across inline formatting, a current match and count; Enter/Shift+Enter or arrow buttons cycle, Escape restores the previous editor selection/focus unless body changes have invalidated the captured range, and note navigation clears ranges. The sticky bar stays visible while a match scrolls into view. Only visible text participates; collapsed table-source disclosures are excluded until opened, and opening/closing them refreshes counts. Body DOM changes refresh results without touching Lexical state, history, autosave or canonical Markdown. It bounds decorations to 2,000 matches (count gains `+`), does not search title/frontmatter or normalize Unicode spellings, and does not intercept modal inputs. Browsers lacking CSS Highlights retain native keyboard behavior. There is no replace action.
