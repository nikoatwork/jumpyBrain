# Browser and editor contract

## Responsibilities

- `browser-design-system.ts` owns shared type, spacing, control-size and radius tokens; `browser-theme.ts` owns semantic Ember colors and theme preferences. Follow [the browser design system](../../../docs/design-system.md) when changing UI. Ordinary sidebar destinations share one regular UI font role; controls use only regular/semibold weights. Home/New note/Search share an icon row and theme uses one accessible sun/moon toggle. Native-injected Updates uses the shared utility slot and icon target rules.

- Leaving the graph cancels pending layout/filter timers and drops its hidden SVG/listener tree. Keep the bounded graph packet, filters, selection and camera so Back/reopen can rebuild the same view; no editor draft/save-barrier or graph freshness policy changes.

- Shared Feedback has a message field, default-on **Include logs** checkbox with a hover/focus information tooltip, one Send action and an accessible top-right close icon. It has no diagnostic preview or email-client/download alternatives. `feedback.ts` uses schema-v1 safe events: at most 120 tab-local events, request duration/status/code and opaque correlation, confirmed/unconfirmed saves, external-refresh failures, exception/rejection/editor categories, safe shell line/column, and app/editor build fingerprints. Failures survive routine polling. No raw error text/stack, URLs, document IDs/titles/content, queries, keys/cookies, paths, provider output, raw filesystem logs, or crash dumps enter the report. Browser-only hosted reports explicitly have no server-log access. Browser history resets on reload.
- Companion Feedback collects sanitized gateway, owned local-server, native and Electron history through authenticated, generation/tab-fenced `GET /companion/diagnostics`. It neither starts a local engine nor reads remote-server logs. Collection is capped at two seconds; unavailable/degraded sources, buffer drops, coalesced healthy reads, truncated input bytes, and export omissions remain in the report. Host cache is brain/generation scoped for two seconds. Cancellation/late results cannot revive a closed dialog or an opted-out attachment. Attachment evidence freezes, with report-local correlation references. Runtime/editor fingerprints expose stale mixed builds.
- Feedback's primary action explicitly submits the message and optional diagnostics to same-origin authenticated `POST /feedback`; the host forwards only that report to the configured support relay. Nothing uploads on opening the dialog. Provider credentials stay on the relay. Success requires `{accepted:true,id}` matching the submission; failures retain the message and immutable report/UUID for retry, including close/reopen. Editing the report starts a new submission. Sending disables editing/duplicate clicks/ordinary dismissal until it settles; forced session fencing still closes the dialog. No crash-persistent feedback text. Builds include the public relay URL from package metadata; explicit empty/custom overrides remain supported and packaging verifies the intended configuration. Opening cancels references and shortcuts cannot edit notes. See [deployment](../../../docs/feedback-delivery.md).
- The workspace toolbar shows the desktop brain contours as a monochrome, theme-adaptive mark in its top-right corner on Home, notes, graph, and Settings; it is decorative, outside the save-status live region, and remains visible on narrow layouts.
- The shared navigation brand visibly labels the app `(beta)`; beta status is separate from the numeric release version.
- Shared navigation uses a desktop left sidebar with Home/New note/Search icon actions, a visually continuous page list with pinned notes first and even row spacing, then a compact Graph/Settings/Feedback and theme/update icon row. The native update control stays icon-only, using a static readiness glow and tooltip/accessibility text; it never adds a status/details row. Pinned and Attention have accessible list labels without visible section headings. `browser-page-navigation.ts` retains device-local pins under `jumpybrain.pageNavigation.v1:<scope>` (50 maximum), preserving existing stored pins and synchronizing tabs; hosted data is origin-local and companion pins are profile/destination-scoped. Visit history is retained for compatibility but no longer selects sidebar notes. Pinned pages stay visible independent of settle/snooze and are deduplicated from Attention. Pin, Snooze and Settle live in sidebar rows (including pinned rows); the note toolbar has no duplicate attention/pin controls. Initialize lifecycle guards before consulting them during stored-pin hydration. Pins are navigation preferences, including on read-only brains; they never write canonical memory. Empty Pinned has no helper copy or reserved section gap. Stable unchanged row DOM preserves pointer/focus targets across autosaves. Titles are text-only with full tooltips, guarded navigation and companion brain scoping. The workspace toggle persists `jumpybrain.sidebarCollapsed` before paint without rebuilding the editor; narrow navigation keeps the compact top bar and horizontal page lists.

- Compose the framework-free browser shell in `graph-page.ts`: authentication/companion transport and injected document/map controllers. `document-controller.ts` owns typed save state, Markdown split/compose, and editable-title composition; transport, clocks, selection checks, and UI callbacks are explicit host dependencies. `map-controller.ts` owns fetch sequencing, warning data, rendering, layout and camera through injected DOM/window, authenticated fetch, status and guarded-open callbacks. The shell retains guarded navigation and connection state. `notes-browser.ts` owns home, search/connection dialogs, full-page editing, and guarded navigation. `companion-browser.ts` owns the explicitly enabled companion settings/control UI; ordinary hosted `serve` does not enable it. `lexical-editor.ts` owns vanilla Lexical, selection/history, and Markdown conversion; never import that browser-only entry into the Node runtime.
- `npm run build` bundles `browser-entry.ts`, including pinned Lexical dependencies and the typed browser controllers, with the existing esbuild pipeline into `dist/adapters/http-server/editor-bundle.js` plus `editor-LICENSES.txt`. The shell inlines this local bundle under its existing nonce (script terminators escaped). No CDN, React, separate frontend service, or production npm install is required. Pack validation requires both assets; bundle size has a 172 KB gzip review gate (approximately 171 KB measured after graph presentation and maintenance, about 5 KB over the prior reviewed bundle; no new dependencies), not a promise that Node HTTP enables compression.
- Support ATX headings, bold/italic and literal page-reference spans directly while editing. Keep unchanged source lines verbatim and avoid writes on hydration/selection. Preserve unsupported Markdown as editable literal blocks without decorative underlines; disable formatting/shortcuts there rather than stripping syntax. Text/heading controls explicitly convert blocks. Edited supported lines can normalize delimiters; this is not full CommonMark/GFM round-tripping. Paste parses plain-text Markdown with the same conservative grammar as loading, as one undoable edit; it never consumes clipboard HTML. Insertions within literal/code blocks stay literal, while replacing a whole block can introduce formatting. Empty clipboard text is a no-op. Frontmatter remains outside Lexical.
- Reset selection/history on every document transition, including empty-to-empty transitions. Keep undo/redo history across autosaves and restore Lexical ranges through search; do not rebuild the rich surface after each save.
- `external-document-updates.ts` checks the visible open note through the existing authenticated canonical GET about every two seconds, serially, with a ten-second read deadline and error backoff up to thirty seconds. Hidden/pagehide pages pause and abort; focus/pageshow return checks promptly. Document identity, credential/companion scope, baseline hash, draft revision, and reconciliation token fence late reads. No index/graph fetch, provider execution, new transport, or server cache is introduced. Canonical ID discovery currently scans the root on each GET; large brains, multiple tabs, and remote latency remain polling-cost limits.
- External updates are writer-independent: saves from another user’s editor, agent CLI updates, and direct Markdown edits use the same refresh, highlighting, and draft-protection path. `scripts/external-document-updates-smoke.mjs` verifies another editor in an isolated browser context alongside CLI/filesystem changes. Clean external snapshots update the saved baseline without a PUT. Dirty, blocked, unconfirmed, saving, navigating, or stale-session editors retain their text and original hash; pending changes show "Changes available". Composition, recent field input/key/pointer interaction, title focus, text selection, and open dialogs defer acceptance. New body text uses Lexical's external-refresh path: retain scroll, map an idle caret through equal source lines where possible, and establish a new undo baseline so Undo cannot restore pre-refresh text. Changed/new nonblank source lines get a four-second theme-aware tint; reduced motion uses a static tint until removal. The accessible "Updated elsewhere" notice also covers title changes and deletions. Attribution and exact diff/merge history are not inferred. Decorations never enter Markdown. Read failures retain the current note; existing connection/recovery UI remains authoritative.
- Use authenticated indexed search for Cmd/Ctrl+K, validate canonical IDs from `provenance.metadata.id` rather than QMD hit IDs, deduplicate document hits, and report index staleness including locally confirmed writes. Home and direct `/?note=<id>` loads do not fetch graph data. Preserve result-row DOM and scroll position during freshness/selection-only updates so autosave cannot detach a pointer gesture's click target. Search selection keeps the dialog visible until guarded navigation succeeds and explains blocked navigation instead of silently dismissing the result.
- The connection toolbar reflects successful authenticated requests, not merely a stored key. Settings keep draft key edits separate from transport credentials, mask keys unless explicitly revealed, and remask on close. Disconnect uses the navigation/save guard before removing the browser key and returning home; late responses from previous credentials cannot restore connected status. Disconnect forgets browser credentials, not server-side key authorization.
- Home prioritizes a filled New note action above outlined Search, aligned with recent notes; display platform-specific Cmd/Ctrl+Enter and Cmd/Ctrl+K hints and accessible shortcut metadata. Keep navigation and keyboard focus visible.
- Compose quick capture through authenticated idempotent `POST /memories/all/notes` with `{ type: "note", body: "", dailyDate: "YYYY-MM-DD" }` using the browser-local date. App/server-memory chooses a readable date title (`October 14, 2026`, then `October 14, 2026 · 2`) inside the write queue, continuing sequences from legacy technical titles; the writer supplies `How is your day?` as the body heading. Never derive the suffix from browser state or indexed search.
- New note buttons and Cmd/Ctrl+Enter share one guarded flow. Handle the chord before Lexical's Enter handler without adding body text; leave browser New Window/Tab chords untouched and suppress repeat, composition, shifted/Alt chords, and creation inside dialogs. Retain the exact request/key after unconfirmed creation, suppress concurrent attempts, and restore history before unlocking a failed async creation. Retry state is tab-local, not crash recovery.
- Inline autocomplete retains matching option identities and the selected result while a newer query is loading. Matching suggestions show only options, with no keyboard explainer, freshness header, or reserved status space; empty/loading-without-results and error states retain inline feedback. Printable keydown events leave refresh to the committed input/selection update. Query cancellation and live insertion/session guards still apply; unrelated old options are removed. Global search retains its existing clear-on-query behavior and freshness feedback.
- `reference-autocomplete.ts` installs inline suggestions for `[[` using an independent instance of the existing search controller and authenticated transport; Cmd/Ctrl+K stays global search and Insert page reference stays the explicit modal picker. Insert only literal exact-title text with live range/session revalidation and a single undo transaction; never navigate/mutate targets. `reference-policy.ts` supplies both pickers with `unsafe_title`, `missing_id`, and `visible_duplicate` eligibility reasons while each picker owns its messages and acceptance state. The range scanner reuses the same pure title predicate. Canonical ID format comes from browser-safe core `document-id-format.ts`; duplicate detection is limited to visible suggestions. `browser-transport.ts` constructs the shared search request and reuses protocol-owned document paths; authentication, abort signals, If-Match and companion generation/tab fencing remain with the existing host transport. Mark suggestions stale after actual saves; abort/dismiss on document, credential, modal, navigation/read-only transitions. Editor/listbox/active-option ARIA, separate live status, stable rows, and tap-versus-scroll handling retain editor focus.
- The companion editor enables `atReferenceTrigger` so `@` also opens the same inline picker, with semantic matches under ordinary search readiness. Accepting either trigger inserts literal `[[Exact Page Title]]`; `@` introduces no canonical link syntax or target mutation. The shortcut starts at block/leaf start, after whitespace or `(`, checks preceding-leaf text to exclude email addresses, and requires a single-leaf query at logical block end. Escapes, code and unsupported contexts stay inert through the existing scanner. Existing `[[` editing takes precedence even for titles containing `@`. Hosted editors leave the option disabled. The reference control's companion-only tooltip advertises the shortcut.
- Mac missing-reference activation saves the source first, then calls authenticated `ensure-title` only for a missing title on a writable connection. Reuse canonical titles, preflight the confirmed target and retain drafts/history on errors. `canActivateReference` separately allows permission-readonly navigation/feedback while frozen/navigation-locked editors stay inert. `reference-creation.ts` tracks only newly completed active reference text from typing, paste, picker insertion, title edits and committed IME/redo. Hydration, selection, undo, external refresh and context-only activation of old literals never enqueue targets. Wait until the complete current body matches its confirmed saved body; continued input or a safe rebase defers creation until the next confirmed save. Preserve existing pending intent through external rebases without enqueueing external links. Errors require explicit Retry page creation and block navigation/switch acknowledgement until resolved or the reference is removed. Requests are session-fenced; the companion gateway requires target-specific write permission and drains admitted work. Target creation changes neither source Markdown, caret nor undo history; undo never deletes an already created target. Ordinary hosted browser navigation remains lookup-only.
- `reference-ranges.ts` owns conservative editor-only recognition. Recognize single-leaf titles in paragraphs/headings/bullets; leave formatted cross-leaf references inert. Unfinished suggestions require logical block end; the explicit picker can instead insert at the caret. Exact-length multiline backticks suppress code; unclosed spans and unsupported quote/list/indented fences suppress through EOF. These intentional false negatives are not a general Markdown parser. Keep inactive references literal too: activation state must not introduce escapes into existing filename/alias references or change graph semantics.
- Active page-reference brackets use a decorative CSS Custom Highlight at 24% ink over the current theme surface; titles retain their normal styling. Literal blocks and page references have no decorative underlines. Active references use a pointer cursor, hover background, and visible keyboard-focus outline. Mutation-driven DOM ranges leave literal text, wrapping, selection and Markdown untouched; unsupported browsers retain ordinary brackets. Native selection takes precedence, and editor teardown removes its ranges.
- Normal click/tap, Tab→Enter, and click-only accessible activation resolve fresh titles after the existing save/history guard. Prefetch and validate the target ID/title/content before replacing the editor; failure retains the current draft with inline feedback. Cancel delayed lookup on modal/credential/history transitions, deduplicate repeat activation, and reuse the confirmed payload on route apply. Resolution is not atomic against later writers; rename/title reuse can break/retarget links. Drag selection/copy/arrow editing remain native; navigation wins the first click of a double click.
- Automated scope: desktop/narrow touch Chromium integration, DOM clipboard, synthetic composition, touch pan/tap, wrapped-caret/scroll/viewport geometry, and simulated zoom. Physical IME/mobile keyboards, OS clipboard, assistive technology, Safari/Firefox, and physical pinch zoom remain unverified; do not infer them from emulation. Production regression runners live in `scripts/{page-reference-editor,reference-autocomplete,page-reference}-smoke.mjs`; the feasibility editor/plugin/scanner forks are removed.
- `browser-theme.ts` owns shared semantic CSS tokens for Ember Light (parchment) and Ember dark (graphite), with coral focus/caret accents, readable secondary/error text, theme-aware graph lighting/backdrops/shadows, and muted `--node-*` data accents. Home, map, editor, autocomplete, dialogs, and companion settings consume these tokens rather than view-specific palettes. The borderless proportional editor/title keep the shared surface (no enclosing focus ring); navigation controls retain visible focus.
- The theme utility is an accessible sun/moon button whose name describes the action (Switch to light/dark theme). A nonce-protected head bootstrap resolves appearance before paint. The initial/stored System preference keeps following the OS until an explicit toggle chooses Light/Dark; CSS also honors the OS without JavaScript. Explicit preferences persist under `jumpybrain.theme`, storage events synchronize tabs and blocked storage degrades to a tab-only choice. Theme changes do not rehydrate the editor or navigate. Palette provenance: [Ember license](../../../docs/licenses/ember.txt). Verify with `test/browser-theme.test.js` and `scripts/theme-smoke.mjs` after building.
- The writing page uses a local Charter/Georgia serif stack, a bounded 680px text measure, responsive margins, and transparent formatting controls. Source lines remain separate blocks, with blank source lines supplying paragraph gaps. The title textarea grows on hydration/input/window resize; wrapping is visual only, pasted newlines are removed, and Enter moves to the body except during IME composition. Title metadata still uses the existing single-line validation/autosave path.
- Keep the memory map visually quiet: shared navigation, one heading, shared note search, secondary native Filters disclosure, refresh, and zoom/reset. Browser depth input is removed; graph APIs/CLI retain their depth contract and default. Inclusion defaults are unchanged; the displayed note count excludes missing-note placeholders. Bound long visual labels while retaining full accessible titles.
- Map queries share normal-depth authenticated search, canonical normalization and the recent-write/tombstone projection. Global search keeps 24 requested hits/12 rows; map search requests 120 candidates, filters for stronger evidence through `graph-search.ts`, then preserves all qualifying normalized direct matches without an additional display-count cap. The existing shared-search 120-candidate retrieval budget and graph node/edge/byte safety budgets still apply; this does not promise exhaustive corpus retrieval. Search adds no nonmatching neighbors (`neighborLimit:0`); only canonical links between retained matches appear. Full-query lexical matches in a title or passage and full-body confirmed-write matches survive regardless of score. Other hits need a finite base `qmdScore` of at least 0.75 and at least 85% of the strongest candidate base score; ranking/recency/dream boosts cannot satisfy this gate. QMD base scores include rank fusion, so these are conservative display heuristics, not calibrated semantic confidence or cosine distance; unscored semantic-only hits are omitted. Shared retrieval/ranking, global/reference search and API/focus-only expansion stay unchanged. Semantic discovery does not create edges. Query/focus/orphan/inclusion behavior remains explicit; no-hit queries never restore an unfiltered graph.
- Every committed search/focus edit queues 250 ms debounce, including one/two characters and clear; composition waits for committed text, Enter/refresh cancel the timer. A scoped overview supplies all provisional full-query title matches within the loaded overview without adding neighbors or new body/index reads; body/semantic results replace them. A zero-title projection retains the useful scene with aria-busy until authoritative results arrive. Errors expose Retry; generic stale/incomplete warning lines are removed. Tab-local-only results retain a specific explanation.
- `map-controller.ts` owns request/scope fencing, one 10k-node/20k-edge lean overview, a bounded topic packet, transient positions, camera, hit testing and scene lifecycle. App graph assembly still performs a fresh canonical link scan after each settled authoritative query; request cancellation propagates through canonical scanning and asynchronous link/snippet reads; synchronous parsing and OS-uninterruptible I/O remain limits. No persistent graph cache is introduced. Confirmed writes invalidate the overview; status publication invalidates it before refreshing the current query. Brain/credential changes evict topology, positions and node metadata.
- `graph-layout.ts` computes deterministic weak components and radial link trees, with no simulation. Entering a topic gives its small neighborhood readable space, then surviving identities keep positions across adjacent query edits. Manual camera changes survive query refinement; clearing an automatically fitted topic restores the full overview. Back preserves the camera/selected note. Resize recomputes visible geometry.

The backing store caps device scale at 1.5 and 4 million pixels; no perpetual redraw loop. Both paths expose actual link evidence and preserve canonical full-page navigation. Node/edge/byte truncation stays in protocol metadata and the Refresh tooltip rather than a banner.
- `graph-labels.ts` projects to screen space, uses a collision grid and prioritizes focus/hover/selection, then direct matches before context. Fixed 12px labels wrap to two lines, try alternate anchors, then truncate with full accessible titles. Zoom/pan/resize request one frame; measurements have a bounded cache. Dense graph arrow keys traverse every loaded note, centering an offscreen target and making its SVG button accessible; Enter/Space opens, and click-only assistive activation remains supported. Visible labels also activate the same note. Physical devices and assistive technologies still require separate QA.
- Hover/focus highlights incident connections and quiets competing edges. Mouse/wheel anchoring and touch drag/cancel are explicit; pointer ownership prevents cancelled/right-button gestures from opening notes. Hidden/navigation-away scenes release their DOM/listeners, pending frame/layout/filter work and Canvas backing store, while preserving bounded history data. Theme changes redraw the visible Canvas; reduced motion adds no simulation or mandatory transition.
- `search-maintenance.ts` observes authenticated status only while graph/search is visible: serial 10 s checks, 5 s deadline, scope fencing and hide/pagehide abort. Dream, connection and feedback dialogs suspend observation; closing them schedules the next check without immediate network traffic. A confirmed fresh `lastIndexedAt` generation refreshes the current visible query once without an index mutation. Normal background work stays quiet; unavailable/failed search exposes a compact recovery control. Existing Settings/search explicit indexing remains recovery, permission-gated on remote brains. Historical failure state cannot override fresh canonical readiness.
- Edit page names as title metadata through the same serialized autosave/If-Match controller as the Markdown body, without rewriting filenames, headings, or references. Canonical updates reject duplicate renamed titles using fresh Markdown, not indexed search. Display save errors inline, retain rejected drafts, and resume autosave when a duplicate/invalid name is corrected. Unchanged legacy duplicate titles remain body-editable.
- Keep the persistent rich editor/caret stable through blur, search, saves, and reconciliation. Post-save reconciliation updates frontmatter only when the response body still matches the local body; visible-note external refresh owns accepting a different clean body under the guards above. Preserve 750 ms/blur autosave, sequential If-Match saves, retained failed drafts and explicit retry, unload protection, and fail-closed conflicts on ordinary and companion servers. On a confirmed 412, the browser rereads the canonical note and conservatively merges independent source-line edits or concurrent end additions against the last saved body. The same idle/selection/composition/dialog guards apply before and after that read, with document/scope/revision/hash fencing. `document-merge.ts` treats each side as one contiguous range and refuses overlapping or same-line replacements; title disagreements also require review. Retry at most twice against fresh If-Match hashes. Conflicts, failed reads, and continuing contention retain the draft with friendly Review changes feedback and block switching. Uncertain saves never enter this automatic merge path. No-op edits and undo to a confirmed body report Saved without another write. Unconfirmed saves remain pending even after undoing to the previous body, because a lost response may hide a committed write.

Restore a history traversal to the current entry before flushing, replay it only on success, and keep the editor read-only until the approved destination is applied. Close modal dialogs on history navigation. Canonical whole-document/frontmatter policy remains in existing app/core seams.

## Companion-only browser contract

The loopback companion gateway opts in with `graphPageHtml(nonce, view, { companion: true })` and serves the same reloadable shell at `/settings`, `/`, and `/graph`. No companion markup/bootstrap/control calls are enabled by the ordinary two-argument shell. Existing nonce CSP and local editor bundling remain unchanged; no CORS, framework, or browser-held target API key is introduced.

- `companion-browser.ts` owns named local/remote profile forms, active destination/health/read-only presentation, native folder selection, edit/remove/test/switch actions, registration, polling, and the all-tab acknowledgement client. Settings uses the existing navigation/save guard, not a competing connection dialog. Local selection never initializes a root. Remote editing approval is an unchecked, explicit target-specific checkbox by default.
- Companion Settings presents compact profile rows with named SVG action buttons, a neutral active-profile marker and a collapsed Add connection disclosure (Edit opens it; clear/save/cancel resets and closes it). The selected brain label shows a muted green dot for confirmed health, using coordinator health on Settings before any memory fetch; failures and read-only status remain explicit. `browser-icons.ts` supplies trusted decorative SVGs shared by static and generated controls.
- Companion Settings also owns explicit search-index refresh, removed alongside brain switching from the native menu. Refresh uses the existing generation/tab-fenced `POST /memories/all/index` transport, never an implicit CLI root; disable it while offline, read-only, frozen, unregistered, or running another Settings action. Dispatch refresh progress/results through the shared system-message component without retrying automatically. Native-only login/update and recovery actions remain grouped in menu submenus.
- A fragment `#companion=<token>` is consumed into `POST /companion/session { token }` and erased before requests. Without a fragment, use the existing same-origin cookie. Tokens and real API keys are never persisted to localStorage; ordinary browser-key storage is neither read nor changed in companion mode. The harmless in-memory `activeApiKey = "companion-session"` satisfies existing UI gates but is never sent as Bearer authorization.
- The gateway exposes cookie-authenticated `GET /companion/state` and POST `profiles { profile, revision }`, `remove { id, revision }`, `test { id }`, `select-folder {}`, `switch { id }`, `register/poll/unregister { tabId, generation }`, and `ack { tabId, switchId, ok }`. State carries `{ profiles, activeId, revision, generation, phase: "idle" | "preparing", switchId, health, active, target }`; profiles/active must omit keys. Revision conflicts remain visible rather than resubmitting edits against changed profiles. The masked key field is write-only; blank editing omits `key` to preserve Keychain. Submission/cancel/leaving settings/pagehide clears the transient field.
- Every page has a fresh, nonpersistent tab ID. Registration completes before any initial memory fetch. All memory requests carry `X-Companion-Generation` and `X-Companion-Tab`; the gateway must fence stale traffic with 409 `stale_generation` and enforce target authorization. Polls run approximately every 750 ms **after** the previous asynchronous poll settles, never concurrently. `pagehide` unregister uses keepalive; BFCache restoration re-registers before reopening editing. Transport/session failure freezes the draft and explains recovery; it is not a successful target health check.
- Only entering a frozen/fenced state cancels references and closes Search/Dream; unchanged healthy idle polls preserve dialogs, in-flight queries, and reference suggestions while still synchronizing permissions. Repeated frozen snapshots do not repeat destructive cancellation.
- Preparing freezes the editor, title, navigation, graph controls, creation, formatting, references, and settings mutations. An already-started creation/navigation/document load must settle; the client then flushes its current editor against the old generation. Failed/unconfirmed saves and unconfirmed idempotent note capture send a negative acknowledgement. No discard, creation replay on another brain, or 412 overwrite is allowed. The client stays frozen after acknowledgement until authoritative idle; failed switches unfreeze the same draft. A ten-second client wait for busy navigation is only a negative-ack bound, never permission to remove a tab. The coordinator remains responsible for fail-closed missing acknowledgements, old in-flight requests, and activation/persistence.
- A changed generation reloads to `/?brain=<activeId>` or `/settings?brain=<activeId>` before adopting new state, clearing old note query/editor/search/reference/graph/capture state. History and native links are scoped by `brain`; old or unscoped note URLs are rejected before document GET, even when IDs are identical across targets. Browser Back to old entries must not silently resolve IDs on a different brain.
- Dream handoff uses the actual authorized remote profile URL, never the loopback gateway. Read-only remote and local profiles receive an explanation and no generated prompt; local CLI root instructions are not invented. The existing handoff validator requires a credential-free HTTP(S) origin.

Verification: `node --test test/companion-browser.test.js test/notes-browser.test.js test/daily-notes-browser.test.js test/dream-handoff.test.js`; build first. `npx --package=playwright node scripts/companion-browser-smoke.mjs` exercises the production shell/editor with a disposable cookie-authenticated control fixture: settings/key handling, Search from Home/navigation and delayed queries across idle polls, inline suggestion survival/insertion, local Dream explanation survival, two-tab freeze/flush, uncertain creation, same-document conflict-stop, target-scoped reload/history links, remote read-only policy, serialized slow polls, and session failure. This fixture is not verification of native Keychain/folder UI, real target proxying, coordinator crash durability, sleeping OS tabs, physical IME, Safari, or Firefox; those belong to companion integration tests/manual checks. It does not modify the installed app or personal memory.

## Browser verification

`npm run smoke:page-references` builds and runs production editor preservation/context regressions, isolated autocomplete/controller checks with stub transport, and real disposable-root/QMD/server integration (navigation, save failures, cancellation, history, search freshness, insertion and touch scrolling). Set `JUMPYBRAIN_REFERENCE_SMOKE_BENCH=1` for small/large-note app timings, or `JUMPYBRAIN_REFERENCE_EDITOR_BENCH=1` for isolated editor timings. Historical feasibility entrypoints forward to these production runners; no second editor is maintained.

`npm run smoke:lexical` checks formatted heading/emphasis editing, toolbar undo, Markdown preservation (including edits within unsupported blocks), exact reference titles, empty-document history isolation, safe paste, and desktop/mobile layout in a disposable root. ## Note lifecycle and recovery controls

`document-actions.ts` owns accessible comparison/deletion dialogs over the existing typed editor. Conflicting edits expose Review changes; other failed saves expose Recover draft; Copy draft and Delete note use labeled/tooltipped SVG icon buttons; Insert page reference uses a plus icon without visible text. Copy draft is available for every loaded note and falls back to selectable text when clipboard access fails. Comparison reads the current saved note without writing. Explicit **Discard draft and load saved note** rereads on acceptance and applies only to the same editor/scope/revision, with no silent overwrite. Frozen/read-only states cannot discard/reload or delete; copying remains available. Preparing/generation changes close inactive dialogs; active actions settle before acknowledgement. Dialog bodies are cleared on close.

**Delete note…** first flushes the current draft, requests a guarded preview and shows the selected title, irreversible-removal warning and advisory inbound-link counts. Confirmation submits one DELETE with the reviewed hash. Stale previews fail closed; unconfirmed removals never retry automatically. Cancel leaves the file intact. Confirmed removal returns Home, invalidates graph/cache, suppresses the deleted indexed hit in this tab, and reports pending/failed index work separately. No Trash or backlink rewrite is implied.

`recent-write-search.ts` keeps at most 50 confirmed writes and 50 deletion tombstones in tab memory, with body search bounded to 32 KiB per saved note. Global search and reference suggestions merge matching local saves ahead of stale indexed versions. Tab-local hits carry `confirmedWriteMatch:true` after full cached-body matching, so graph precision filtering does not lose evidence beyond the 240-character display snippet. Superseded titles/bodies cannot reappear through an older hit. A verified fresh server generation retires cached writes/tombstones unless a new write arrived during the query; exact indexed title matches stay ahead of body-only local matches. Results/cache are scoped to credential revision/companion generation and cleared on scope change; no localStorage persistence or cross-brain reuse. Backend failure can return explicitly labeled matching saves from this tab, never an apparently complete search. Host-owned background maintenance discovers other tabs/external edits; the status observer adopts fresh publication. Explicit Refresh search index remains a permission-gated recovery action; browser typing never launches an index mutation.

Narrow map filtering gets its own full-width row at 390/320 px. Labels respond to projected density and zoom, retaining full accessible titles; link meaning is unchanged. Expired sessions expose Retry and Recover draft directly above the page; messages distinguish retrying a valid cookie from reopening through the companion for a fresh session.

## System messages

`browser-system-messages.ts` owns the shared markup, styles, dispatcher and lifecycle for app-wide notifications: note confirmations/Undo, graph warnings/errors, search maintenance/index outcomes, companion/session notices, extension command failures and native desktop outcomes. Producers call `systemMessages.dispatch({ source, text, severity, duration?, scope?, revision?, action? })` and `clear(source)` on resolution. `source` is a stable producer key, not a new ID per poll. `revision` distinguishes separate operations with identical text. `browser-toast.ts` is a compatibility re-export for note confirmations via `show`; it has no separate presentation or lifecycle.

One compact overlay anchored to the workspace bottom-left (clear of sidebar navigation) shows the highest severity, newest message first. Other sources remain pending, up to 16; overload evicts the oldest lowest-severity entry. Deduplication remembers at most 32 outcomes without retaining action closures. Identical updates neither reset visible time nor replay a dismissed/expired result; clearing a source permits recurrence. Ordinary messages expire after four visible seconds, actions/errors after eight; warnings default to persistent until dismissed/resolved, and explicit `duration: 0` supports an ongoing operation or session fence. Hover/focus pauses expiry. Close/expiry releases that entry and displays the next. Replacing a note confirmation releases its previous action. Focus returns to the prior connected control without stealing editor focus on arrival. Messages are text-only; errors use an assertive alert, other severities a polite status.

Default brain scope binds to credential revision/companion generation. `sync()` removes old-scope pending messages, deduplication and callbacks; action clicks recheck scope before running, including when a different message becomes current. Native update/host results explicitly use app scope. `stop()` removes listeners, timers and entries; pagehide clears tab state. No persistent notification history, dependency or polling is added. Canonical save/recovery controls, field validation, view empty/error states and active dialog instructions remain with their owners. Session Retry/Recover draft controls remain available even after dismissing the notice.

Injected native code dispatches `jumpybrain-system-message` on `document` with data-only `{ source, text, severity?, duration?, scope?, revision? }`. The component validates keys, enums, length and finite duration; it ignores action callbacks from events. Native actions still use their existing fixed navigation seam. `test/browser-toast.test.js` covers queue/priority, deadlines, duplicate polls, operation revisions, focus, overload, event validation, action errors and scope/disposal. Production Electron, companion, graph and note-attention smokes exercise the composed shell; physical assistive technology remains a separate gate.

## Recognizing search results

Global search and the explicit reference modal share title, plain-text two-line preview, edit/editor context and quiet path rows. `search-presentation.ts` owns bounded conservative Markdown cleanup, safe text-node literal query highlights, local-calendar labels and accessible exact date/declared-editor details. Creation is labeled separately; missing/invalid dates/editors stay unknown. No source Markdown or agent evidence is rewritten. Inline suggestions reuse compact preview cleanup while retaining stable row identity and gesture guards.

Visible Last edited/Created, date-range, Last editor and sort controls issue opt-in recognition requests. Relevance stays default. Calendar presets/custom bounds use the browser timezone, inclusive dates and calendar arithmetic; changing controls resets paging and retains query text. Previous/Next page through matches over at most 120 ranked candidates plus up to 50 tab-local saves (combined display capped at 120), with a persistent partial-coverage explanation; empty results do not assert corpus-wide absence. Unsupported servers fail rather than silently ignoring filters.

`jumpybrain.editor-id` is a random browser-local identity, separate from access credentials. App writes declare a human actor; `You` requires an exact ID match to that browser identity. Storage-disabled sessions can declare Human but cannot say You. This is not account authentication, a device-wide identity, or verified shared-brain attribution; clearing storage/another profile means another identity. CLI writers explicitly declare actors. Legacy and externally edited revisions remain unknown. No last-human-edit history is retained.

Confirmed save responses and freshly read creation packets carry dates/editor into the scoped tab overlay. Filtering/sorting precedes its page cap. The overlay cannot borrow attribution from an older indexed version and retires only after the existing fresh-generation checks. Graph requests keep their previous short snippet/ranking behavior.
