# Companion extension renderer

## Responsibilities

`browser-commands.ts` is the shared shell/extension command dispatcher. Search buttons and its shortcut invoke `search.open`. IDs are unique; stable IDs settle shortcut conflicts, with built-in search reserved. `extensions-browser.ts` is built as the separate `extensions-bundle.js` IIFE (`JumpyBrainExtensionBrowser`) and embedded only in companion pages under the shell nonce. It starts after registration, and refreshes descriptors on the existing state packet's `extensions.revision`. An absent signal is silent, including lifecycle events. No background extension timer exists; the UI asset load has a one-shot deadline.

The renderer uses the existing `graphJson` generation/tab-authenticated transport. Revisioned same-origin UI scripts carry the shell nonce and must register synchronously from the expected current script through `globalThis.JumpyBrainExtensions.register(id, factory)`. A detached/stale script cannot register a replacement activation. UI factories and mounted panels dispose independently of shell/editor state. Close, document change, scope freeze, revision change, disable/remove and page teardown abort pending panel work, fence late results and restore focus when appropriate. Extension errors remain bounded user feedback.

Document identity and its last delivered notification survive descriptor-only revisions. The first usable snapshot delivers the current document once if it was observed before descriptors arrived; subsequent `document.changed` deliveries require a document transition or a new authenticated scope. An event-handler error revision cannot synthesize another document event and create a refresh/dismissal loop. `scope.changed` belongs to the host, never a per-tab browser event.

Persisted `pagehide` suspends the existing controller: it aborts pending work, disposes contributions, releases commands/themes and disconnects theme observation. Persisted `pageshow` resumes its lifetime listeners and observer without requesting descriptors. The companion's existing re-registration and state sync reactivate it only once an authenticated scope is available, preserving `graph-page.ts`'s controller reference. A nonpersisted hide permanently disposes the controller and its listeners; disposal cannot be resumed. No additional poll is introduced.

Async factory and renderer returns race their activation/UI/panel cancellation. Closing or invalidating a panel releases the invoking button even when a contribution never resolves. Late returned disposers run exactly once for their original lifetime; late factory registration is rejected and detached mount containers cannot revive closed DOM. Disposers registered after cancellation run immediately. This does not preempt synchronous extension code or stop unmanaged side effects.

Companion Settings places Extensions after brain connections, with a heading-aligned named reload icon, one palette row when custom themes are available, and no empty status gap. Initial status is empty until the host signals extension support; loading/errors still use the existing status region. Companion Settings owns compact status, enable/disable/remove/reload, palettes, command access and device-local schema-v1 order/placement/shortcut preferences under `jumpybrain.extensions.v1`. `sidebar.actions` and `note.actions` contain only extension contributions; save/recovery controls retain shell ownership. Inputs/results use text DOM, never HTML. Panels use a labelled native dialog, explicit Close and Escape. Custom UI receives only abort/document metadata, scoped command execution and guarded note opening.

Theme colors allow optional `--` semantic names with hex values. Overrides are removed on disable/reload/fallback, restore built-in appearance preferences and redraw the graph without rehydrating the editor. Appearance toggle returns to built-in palettes. Theme and command preferences are device-local, not memory writes.

Stable fixture hooks: `#extension-settings`, `#extension-list`, `#extension-status`, `#extension-reload`, `#extension-theme` (accessible name `Extension palette`); `#extension-panel` labelled by `#extension-panel-title`, `#extension-panel-content`, `#extension-panel-close` (`Close extension panel`). Commands use descriptor titles as accessible button names; slots use `data-extension-slot`.

Focused verification: `npx tsc --noEmit` and `npx --package=playwright node scripts/extensions-browser-controller-smoke.mjs`. The smoke bundles controller and view sources directly without changing `dist`; it covers throwing document-observer revision feedback, never-resolving factory/renderer cancellation, late cleanup and stale contexts, and repeated persisted hide/show restoration alongside normal command/theme behavior.

Theme validation consumes the SDK `EXTENSION_THEME_ROLES` tuple. A safe-mode snapshot may include bounded `recovery` guidance; it is rendered as text and is optional for older hosts. Device-local preferences retain schema v1 and semantic contribution IDs through replacement/rollback.


## Non-responsibilities

No arbitrary browser-path installation, host/module preparation, raw privileged fetch, editor replacement, memory/write policy, feature-specific Related notes logic or hosted extension activation. Runtime/gateway own authoritative registration/capability/revision checks. Current SDK declares writes at package level, so UI confirmation conservatively applies to each command in a write-capable package and submits `allowWrites` for that invocation only; target policy remains independent. Same-origin extension code is trusted, not sandboxed. The renderer does not promise to preempt blocking code or undo unmanaged extension side effects.
