# App dream workflow

## Responsibilities

- Expose `getDreamWindow({ root, request?, config?, now? }): Promise<DreamWindow>` as the read-only, stateless filesystem context seam. Resolve/validate the request through core policy; scan canonical Markdown directly without an index or source-ID assignment. Ignore all legacy dream state, including open/corrupt batches and completion cursors. Do not initialize roots, create support directories, or write any state.
- Use core retrieval policy’s shared `isDreamDocument` classifier to exclude only strict boolean frontmatter `dream === true` from primary source evidence, regardless of bucket; ordinary pages, `[[dream]]` navigation, and string values are not classified as generated outputs. Agents can search existing dream context separately, including outside this window.
- Return target-safe root metadata and a resolved UTC `window: { from, to, timezone, dateBasis }`, with oldest-inclusive `from` and anchor-inclusive `to`. File contexts include optional ID, canonical relative path, type/title/frontmatter, selected UTC date and its actual basis (`date`, `filename`, `created_at`, `createdAt`, `mtime`, or `modified`), `dateConfidence` (`declared`, `filename`, `fallback`, or `modified`), mtime, full-file hash/byte length, returned byte length, body prefix, and truncation flag. Missing IDs are allowed with a warning; normal edit ID/hash requirements are unchanged.
- Sort matching evidence by oldest date, then codepoint path; apply request-local offset, max-file count, per-file bytes, and total bytes. `totalFiles` counts matching files in that scan, not reviewed evidence. Return `hasMore` and `nextOffset` for unconsumed matching files. Stop when total body budget is exhausted; do not fill later contexts with empty bodies merely to consume the file quota. Per-file truncation warns even when there are no additional matching files. Hashes always describe full original bytes, never truncated content.
- Continue with `from: result.window.to`, the same days/date basis/limits, and `offset: result.nextOffset`. Truncated file bodies require explicit full-source reads; offsets continue to the next file, not the next byte. Concurrent edits can shift offsets and membership; a file changed/disappeared during hydration is omitted with a warning. Neither pagination nor historical windows prove complete review. Empty/sparse windows and out-of-range offsets return empty files without state changes.
- Prioritize packet omissions/truncation and returned-file diagnostics over root-wide date summaries. Only returned files receive path-bearing warnings; out-of-window, unselected, unreadable, or hydration-omitted files are summarized by count. `diagnostics` counts successfully scanned non-dream files, unreadable canonical files, creation/mtime fallback files and all date-diagnostic files (each with outside-window counts), hydration omissions, truncated bodies, omitted metadata, and omitted/clipped warning messages. Date counts describe the requested basis: modified mode does not audit historical metadata. Aggregated files are not counted as budget-omitted warning messages.
- Bound the complete serialized warning array to 16 KiB / 100 entries, each serialized string to 1 KiB, including an explicit omission/clipping summary. Structured counts and per-file content truncation flags remain available even when warning strings are omitted. Return frontmatter separately capped at 4 KiB serialized per file, IDs at 512 bytes, and titles at 1 KiB; omit oversized fields with warnings rather than silently altering their values. `maxTotalBytes` bounds content, not JSON escaping/envelope overhead. These output caps do not bound filesystem scan cost: evidence-date selection still reads canonical Markdown.
- Creation/mtime `fallback` confidence may indicate an import date, not an event date; `declared` and journal `filename` provenance are not independent date verification. Keep existing ordering and date precedence even when an import burst crowds the page. Inspect imports deliberately with `dateBasis: modified`, `from` set to their modification UTC day, `days: 1`, and request-local offsets; imports whose mtime was preserved require the corresponding modification day, or evidence-mode pagination around their creation fallback date. Narrowing a window, a no-op, or reaching its final offset never proves corpus coverage. No filename guessing, automatic redating, writes, or persistent queue is added.
- Parameterize local and remote target/root labels using existing `DreamWorkflowConfig`; the window path ignores its support-state paths. Remote contexts use the safe root label, never scanned absolute paths in result metadata/diagnostics.
- Retain legacy create/resume/hydrate/complete/abandon/status batch APIs for runtime compatibility. Only these legacy APIs use state/batch JSON, completion cursor advancement, and one-open-batch semantics. They do not share a completion ledger with windows.

## Non-responsibilities

- Do not parse CLI flags, format command output, authenticate HTTP requests, choose HTTP status codes, or log requests.
- Do not import QMD internals, AI/model providers, prompt templates, or scheduler/background job code.
- Do not apply dreamed edits or impose dream-specific write ACLs. Callers use explicit normal document create/update flows, preserve source provenance, and obtain authorization before global/team/remote writes.

## Living topic sources

`source-check.ts` exposes `checkDreamSources(root, {id} | {content,file})` for explicit saved Dream-page or draft checks. Compose canonical bounded reads with core reference comparisons, returning only root-relative provenance, transient checked time, page hash, per-source outcomes and partial/unread/omission counts. No state/index writes, source ID assignment, model calls or implicit publication. Version-pass limits: 64 KiB page, 32 references, 500 files, 256 KiB/file, 4 MiB successful/reserved read bytes. Existing selected-ID discovery and directory enumeration remain corpus scans outside these byte limits. Incomplete source passes cannot establish uniqueness/absence and conservatively return not_checked. See [workflow/limitations](../../../docs/living-topic-pages.md).
