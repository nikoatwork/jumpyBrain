# App Logseq migration workflow

## Responsibilities

- Export `migrateLogseq(source, root, { apply?, failOnConflict? })` and result types for runtime/CLI composition. Default is read-only dry-run. `applied` is true on a successful apply, including identical no-op reruns; action counts describe the plan. `outputDocuments`/byte totals describe surviving imports only. `indexed` is always false; explicitly run `jumpybrain index --root <destination>` afterward.
- Discover only regular Markdown recursively in default `pages/` and `journals/`. Ignore hidden support content, assets, backups, non-Markdown and root Markdown. Count ignored files using directory metadata only, except bounded `logseq/config.edn` reads needed to reject unsupported modes. Never read ignored asset/backup bodies or traverse symlinks.
- Reject overlapping roots, symlink components (including ancestors), hardlinked/special active files, unsafe mappings, normalized/case collisions, incompatible/custom destination schemas (including redirected `indexRoot`), custom Logseq page/journal directories, Org-mode configuration and likely database/mirror graphs. DB detection is conservative and heuristic, not a proof of graph provenance; ambiguous/custom EDN is unsupported rather than executed. At least one default source bucket directory is required; an empty bucket is valid for removal reconciliation. Literal colons in filenames are supported on POSIX; Windows rejects them to prevent alternate data stream paths.
- Support compatible nonempty roots, including standard manual roots without config. Stage normal `initializeMemoryRoot` setup privately, then transactionally publish config/ignore policy and canonical directories. Existing configured roots are not reinitialized. No source writes or index operations occur.
- Plan the whole reconciliation before mutation. Validate prior durable ownership manifest, detect conflicts, preserve stable IDs/times, verify envelope body hashes, and perform atomic same-directory replacement. Only exact manifest-owned identity-matched paths may be deleted; never infer ownership by scanning unrelated files.
- Recheck source membership/hashes and destination snapshots before publication; recheck each target immediately before write/delete. Exclusive sibling transaction directories serialize cooperating migrations. Exclusive links publish new files without clobbering concurrent creations. Rollback verifies expected installed bytes/identity and refuses to overwrite concurrent edits.

## Transaction and recovery

The durable ownership manifest is `.logseq-migration-manifest.json` at the root, **outside disposable derived state**. Keep it with canonical Markdown backups; without it removed-source ownership cannot be reconstructed safely. A lost manifest permits importing currently present source mappings again, but cannot authorize cleanup of old mappings.

During apply, `<root>.logseq-migration-transaction/` is a private (0700) sibling directory with `receipt.json` (version 1), numbered rollback preimages (0600), and optional staged initialization. The receipt has relative paths, before/after hashes, modes, created directories, operation completion hints and transaction status; no source bodies. Backups do contain private old canonical bytes and are retained only on interrupted/unsafe recovery. New canonical outputs are 0600; existing file modes are preserved. Successful commits remove all transaction data. A normal injected failure restores files, deletions, manifest, initialization files and newly created empty directories. Empty directories left behind by successful source deletions are harmless and intentionally retained.

**Crash recovery is manual and fail-closed.** Any retained transaction blocks dry-run and apply. Stop every writer, preserve a private copy of the destination and transaction, and inspect the receipt:

1. `committed`: verify after-hashes (or absence for deletions), then remove only the transaction directory. Do not restore preimages of a committed run.
2. `rolled-back`: verify before-hashes/absence; remove transaction data and any recorded newly created empty ancestors.
3. Any other status: inspect each operation in reverse. A completion flag is advisory because crashes can occur between rename and receipt persistence. If target matches after-hash, restore its numbered preimage (or remove it if before-hash is null). If already at before-hash, leave it. If neither matches, preserve the concurrent content and resolve manually—never blindly overwrite. Restore recorded file modes. Remove recorded temporary files and created directories only after verifying ownership and emptiness; never recursive-delete a root. Finally verify all before-hashes and remove transaction data.

Receipts/preimages are fsynced and renamed; directory fsync is best-effort on unsupported platforms. This is not an automatic crash-recovery API. There is a narrow mkdir-before-receipt window where a crash can leave an extra empty directory; before acquiring the sibling lock, missing parent directories may also be created. A sudden power loss may require manual empty-directory cleanup. Portable Node filesystems provide no atomic compare-and-swap rename or directory-descriptor traversal: rechecks significantly reduce, but do not eliminate, races with hostile noncooperating writers replacing paths between checks and syscalls. Quiesce writers for migration. Rollback refuses unsafe restoration and retains recovery data if concurrent edits or permission failures prevent complete rollback.

`migrateLogseqWithHooks(..., hooks)` is an app-internal testing seam, not a runtime export. `hooks.onStep(step, {writes, deletes})` may throw at `before-init`, `after-init`, `after-write`, `after-delete`, or `after-manifest`; thrown contents are redacted. Filesystem/config errors likewise omit private source paths/content. Normal JSON returns only relative filenames, metadata, hashes, aggregate reference/omission counts and the requested resolved destination root.

## Non-responsibilities

No CLI parsing/formatting, remote API, QMD/indexing, Markdown normalization, assets/config copying, scheduled/live synchronization, merging, or source mutation. Runtime should export only the public operation and result types, not hooks/recovery internals.
