# App local-memory module docs

## Responsibilities

- Compose core canonical Markdown and memory-root policy with the QMD adapter for local indexing and search use cases.
- Keep retrieval-depth normalization outside QMD so result shaping remains backend-independent.
- Provide the app seam that runtime and compatibility barrels call for local memory index/search operations.
- Own `overviewMemory` tree/overview summaries, including optional explicit Markdown/wiki-link connection stats without body snippets.
- `connections.ts` collects canonical resolved edges, unresolved occurrences, and neighbor sets once for overview/graph. Graph alone adds snippets/stats, unresolved-node deduplication, presentation/filter/limit policy. Overview retains unresolved occurrence counts without graph node work.
- Graph skips the overview-only neighbor map, computes degrees only for the final bounded response, and reads snippets/mtime fallbacks only for returned documents. `includeSnippets:false` skips both presentation reads and bounds the lean response to 10,000 nodes, 20,000 edges and an 11 MiB node/edge JSON budget. Byte counting conservatively includes the HTTP serializer's actual nested pretty indentation and UTF-8/escape bytes, including arbitrary tag arrays, reserving envelope/degree room below the companion's 16 MiB cap. Whole records are omitted with explicit `truncation` flags; titles/paths/tags are never silently shortened. The byte budget bounds graph data, not arbitrary caller-supplied options. Title/path/ID resolution and whole-corpus link/filter/omission semantics still require a fresh metadata/link scan; this is not a persistent graph cache or a bound on arbitrary canonical input bytes.
- Own `graphMemory` app-level graph assembly for explicit Markdown/wiki-link relationships derived from canonical Markdown files.
- Graph `files` optionally selects exact root-relative canonical file paths before focus/orphan filtering and the node cap; `[]` deliberately selects nothing. Browser shared search supplies the matching paths; graph assembly does not retrieve/rank or invent semantic links. The existing graph `query` remains a literal metadata filter for API/runtime callers.
- Opt-in `seeds` preserves supplied direct-match path order, deduplicates it, and expands real one-hop links in either direction against the eligible graph before limiting. Missing seeds and `seeds:[]` produce no matches. Direct matches come first with `match:"direct"`; additional nodes have `match:"context"`. `neighborLimit` defaults to 60 and accepts zero. Ranked seeds receive context turns fairly so one hub cannot exhaust the budget ahead of every other seed. Exact `files`, metadata, focus, unresolved and orphan filters still constrain eligibility when combined. Graph does not perform retrieval or imply semantic links. `edgeLimit` optionally bounds visible edges; final degrees describe only returned edges.
- Every authoritative graph call reads current canonical metadata/links, including external edits, rename and deletion. Browser topology reuse is provisional, scoped to its brain/credential generation and bounded lifetime; it never makes cached edges authoritative. `graphMemory(root, options, {signal})` propagates cancellation through canonical discovery/metadata and connection/snippet reads, with checkpoints between stages/documents. HTTP disconnection and shutdown share that signal through server-memory; signals are local execution controls, never serialized graph options. Cancellation does not preempt synchronous link parsing/filtering or OS-uninterruptible I/O, and this is not a bound on arbitrary canonical input bytes.
- Expose ID-addressed local document read/update operations by composing core canonical primitives; updates require a prior content hash and return an explicit stale/not-indexed state instead of rebuilding the index synchronously.
- `expansion.ts` exposes `expandMemoryDocument(root, options)` after root compatibility validation; it reads at the editor root, not retrieval-only `indexRoot`. The core [guarded expansion contract](../../core/canonical/canonical.docs.md#guarded-evidence-expansion) owns hash/range/whole-response budgets. No indexing, ID stamping, state writes, or extra packet envelope.
- Expose a local ID-stamping maintenance alias that delegates to the processing `ensure-ids` mode so callers do not reimplement canonical bucket scans.

## Index/search contract

`indexMemory(root, options)` discovers file paths in the configured retrieval-only `indexRoot` and passes them to the QMD lifecycle, which reads each canonical snapshot under its existing lock; `options` accepts `rebuild` and a persisted `indexing` policy. Routine updates reuse hashes/vectors; explicit rebuild is not the default. Index results add work counts and readiness.

`overviewMemory` derives `index.stale` and freshness warnings from the same observational readiness used by status/search, including missing database and pending publication. Manifest membership counts and per-file `indexed` flags remain descriptive and do not establish freshness. Incompatible/uninitialized roots remain safe summaries with a stale index. Overview never repairs, recovers publication, or mutates derived state.

`freshness.ts` owns the shared observational `retrievalReadiness` source/policy check; `memoryStatus` composes core setup compatibility with it. Freshness compares canonical file lists and size/mtime/ctime stats to the committed manifest, plus configured policy and model stats; no body hashing, inference, model download, or QMD subprocess is needed. This is a cheap scan, not a constant-time check or SQLite-integrity test. Search adds `readiness` and `retrieval` outcomes; stale/incomplete/failed branches are labeled partial, total backend failure propagates. See [QMD lifecycle](../../adapters/qmd/qmd.docs.md#index-lifecycle-and-readiness) for publication/locking.

`ensureMemoryIndexed(root, { signal?, timeoutMs? })` validates the existing root, recovers pending publication, checks actual readiness, and performs at most one incremental repair. It never initializes roots, persists/migrates policy, accepts rebuild, or downloads models. Ordinary local search/compact recall call it by default inside the existing search permit/deadline; fresh sources require no indexing worker/model work. The searched generation is checked again under the root lock; changes during repair/query return labeled partial evidence, not a retry loop or snapshot guarantee. Repair failure throws actionable existing errors, rather than returning an apparently complete empty result. Historical failure diagnostics do not override verified source/policy freshness.

App-level [`creation.ts`](../creation.ts) exposes `ensureSavedMemoryIndexed(root, saved, ExecutionOptions)`, composing the same ensure workflow after canonical publication, then verifies the saved ID/path is covered by the current configured source generation before reporting indexed. Excluded `indexRoot` saves report pending `index_scope_excluded`, not false indexed success; stale/missing identities remain pending. Indexing errors are safe saved/failed outcomes and never canonical retries. CLI uses this host seam, not QMD or filesystem policy directly.

`SearchMemoryOptions.refresh: false` (also compact options) skips automatic repair and pending-publication recovery. Missing indexes fail with explicit index guidance; pending publication fails rather than mixing DB and manifest generations. Stale published generations retain partial readiness. This is **nonrepairing**, not zero filesystem writes: the existing PID lock still creates/removes coordination files and requires writable derived storage. Status/show/expand never repair. Hosted reads deliberately use this nonrepairing path while joined server maintenance uses `ensureMemoryIndexed`.

For callers forbidding all derived-state writes, rich/compact `readOnly: true` implies no refresh and selects pinned QMD lexical functions through an immutable read-only SQLite connection. It never acquires/reaps the PID lock, recovers publication, initializes schema/cache, or runs models. Require an existing published/DB generation, no active/abandoned lock, no pending marker and no nonempty WAL; validate generation/file signatures before/after full retrieval and fail closed if changed or corrupt. This is optimistic change detection, not a reader snapshot. Always report `read_only_index`; semantic-capable indexes additionally report `read_only_lexical_fallback`. No ordinary retrieval effort/ranking changes; existing nonrepairing `refresh:false` compatibility remains separate.

Index/search/compact recall accept local `signal` and whole-operation `timeoutMs`, with bounded admission and async children owned by the [QMD execution seam](../../adapters/qmd/qmd.docs.md#bounded-execution). Compact verification shares the search deadline rather than opening a second budget. Read-only discovery waits observe cancellation; canonical scans/reads receive backend-agnostic signals. No detached write/publication is permitted. Finite backend deadlines do not bound synchronous parsing, total corpus input bytes, or OS-uninterruptible I/O.

## Non-responsibilities

- Do not parse CLI flags or format CLI output.
- Do not expose QMD adapter internals to CLI modules.
- Do not implement pure core Markdown or memory-root policy here.
- Do not make overview output carry full graph/export details; use the dedicated graph app seam for richer node/edge data.


## Opt-in compact recall

`compact.ts` exposes `compactSearchMemory(root, query, limit, { depth?, maxBytes?, diagnostics? })`. It reuses `searchMemory` ranking/excerpts and delegates byte packing to [core retrieval policy](../../core/retrieval-policy/retrieval-policy.docs.md#compact-recall-packets). The packet omits local-root metadata and arbitrary frontmatter by default; readiness/retrieval outcomes remain mandatory. Existing unbudgeted contracts are unchanged.

Each available expansion token uses a unique canonical document ID (never the QMD hit ID), the guarded canonical reader's raw-byte hash, and source-verified coordinates. The indexed path must resolve to that same canonical document, including retrieval-only subroots. A stale backend snippet cannot receive a new hash without matching its cited current source. Verified identities use current canonical creation metadata for the written date; unavailable identities retain indexed metadata under the packet's readiness warning. Missing/invalid/duplicate IDs, changed/unavailable/mismatched source, invalid UTF-8, and roots outside canonical memory explicitly disable expansion while retaining searchable provenance. Read-only recall never stamps/repairs IDs. Duplicate/invalid identities are not exposed as unique `documentId` values.

Compact recall discovers all requested IDs in one canonical corpus pass per call; guarded full source reads are cached per ID within that call. Output is bounded, not input work or memory usage. Verification is not a filesystem snapshot against concurrent external writers; later expansion must recheck the returned hash. No new index, summary generator, or alternative relevance policy is introduced.

### Compact temporal verification

Local search validates/resolves optional `temporal` before root/backend access and delegates bounded manifest discovery plus prefix metadata checks to QMD. Both rich and compact candidates omit changed/incomplete frontmatter or changed body-start coordinates with `source_changed`, including ID-less sources; no cross-filesystem snapshot is claimed. Compact recall forwards optional `temporal` to search and preserves its resolved interval/coverage. Explicit temporal passages carry indexed evidence dates and declared relationships; successfully verified sources provide current relationship metadata. If current source evidence-date metadata differs from indexed evidence or falls outside the interval, omit that passage, increment omissions, and report partial `source_changed` rather than attach a fresh hash to out-of-scope evidence. Written dates remain independent. This is still not a filesystem snapshot; missing/unavailable identities retain indexed provenance with existing readiness/expansion warnings.

## Guarded deletion

`document-delete.ts` exposes observational `previewMemoryDocumentDeletion` and explicitly applied `deleteMemoryDocument` through the local runtime. Preview uses guarded canonical ID reads and bounded examples (20) of inbound canonical links and declared relationship matches. Counts are advisory, not a complete dependency graph; preview and apply are separate reads. Removal delegates to core publication safeguards, leaves surviving bytes/links unchanged, and reports `removed:true`, `indexed:false`, stale index and pending indexing. Ordinary readiness detects the changed canonical set; reconcile with incremental index, never by repeating deletion.

## Exact no-op updates

Normal updates still require the prior destination hash. An exact unchanged-content submission returns `unchanged:true` without canonical publication/edit-time changes; stale submissions still fail. This is byte equality, not semantic reconciliation or source checking. Explicit living-page source checks belong to app/dream and never refresh indexes.
