# Current behavior to preserve during multiplayer migration

Inspected 2026-11-01 at source baseline `1cc3b4153922935ada80f509cbe3cc227ce4c1ce`. This inventory describes code and existing assertions; it does not report test execution. The parity runner's separate report owns execution results, environment, blocked prerequisites and artifact hashes. Later changes on the integration branch must extend this inventory before they can enter the refactor baseline.

## Deployment cases

- **Local human and agent:** the app's owned gateway starts a local HTTP engine against the selected Markdown root. A local CLI command currently calls the local runtime independently; a raw-file writer can bypass both. App selection does not retarget the CLI. These paths can observe the same files without sharing one backend process today.
- **Hosted humans and agents:** browser/desktop and remote CLI use authenticated HTTP against the server-local root. The desktop gateway forwards only allowlisted routes, injects remote credentials server-side, and independently enforces the profile's write approval. One server process per root is the documented deployment limit; there is no distributed writer coordination.
- **Future target, not baseline:** one on-demand backend per brain, live simultaneous editing, streamed agent changes, recoverable disconnected drafts, separately revocable reader/writer credentials, and WebSocket subscriptions. Existing polling/optimistic saves are the compatibility behavior to reproduce while those capabilities are introduced.

## What current protection does not guarantee

- The body merge is conservative three-way reconciliation, not a collaborative document algorithm. It represents each side as one changed range, uses source-line separation conservatively, retains both supported end appends, and rejects ambiguous overlaps. It does not provide arbitrary concurrent structural editing or per-character shared undo.
- External refresh waits for safe interaction: no active composition/pointer gesture, a 1.5-second idle period, no title focus/modal or active text selection. The future live binding can replace this policy deliberately, but must preserve selection/IME safety and draft contents; faster transport alone does not prove that.
- Cooperating processes use replacement locks, while raw writers can ignore them. The final validation and rename/unlink are not filesystem compare-and-swap. A raw writer can race the last check; watcher notifications cannot recover every transient version written and replaced before observation. The new design must state this residual boundary rather than claim all filesystem writers become transactional.
- Ordinary browser drafts are currently tab-local. Existing restart recovery refuses to move a dirty draft to a new generation, but tab/crash-persistent recoverable draft storage is not established. The user-requested disconnected-draft guarantee therefore belongs to a later capability gate, not baseline parity.
- Server bearer keys today authenticate the same allowed server surface. There is no separately managed human/agent principal with reader/writer role and live revocation. Device policy and gateway approval are meaningful existing protections but do not establish server-side role authorization.
- Canonical creation and the hosted idempotency receipt are separate publications. A crash between them can permit a duplicate retry. A separate CLI invocation generates a new key. Current document PUT/deletion are not generally replayable exactly-once operations.
- Actor metadata is a declared creator/latest-editor claim tied to a revision digest, not verified identity or contributor history. Raw file edits can invalidate it; preserve unknown attribution rather than credit the last authenticated reader.
- Source scans, multiple-file reads, title uniqueness and indexing do not form one global filesystem snapshot. Retrieval freshness and successful canonical publication are separate evidence.
- Existing simulated/fake QMD tests prove adapter lifecycle and failure policy, not real semantic model behavior. Chromium automation with credential seams proves neither physical macOS Keychain/signing continuity nor other browsers/assistive technology.

## First-gate execution recommendation

The first gate establishes repeatable baseline evidence; it does not enable WebSockets, accounts or live editing.

1. Freeze the reviewed scenario/test/helper/fixture contract at the source revision above, plus package/lockfile hashes. Record an immutable copy or verifiable artifact of the baseline inputs and built runtime before any refactor. Record dirty runtime inputs explicitly and refuse to call a mixed snapshot the baseline. Planning/tooling additions alone do not change the baseline runtime.
2. Run the complete existing deterministic suite against that built snapshot. Inspect skips, cancellations, zero-test discovery and child-process failures; exit code alone is not enough. Build and checks consuming `dist` run sequentially. A test requiring real QMD must either use the supported installed engine or block its scenario, not silently substitute the fake lifecycle engine.
3. Run the real disposable-root/real-server browser flows below. Their canonical Markdown assertions are required, not optional screenshots. Reuse a provisioned Chromium/Chrome and pinned Playwright; do not mutate personal notes, app settings or shared production roots.

   - `npx --package=playwright node scripts/note-lifecycle-smoke.mjs` — P03/P05/P09/P11 across capture, current saved search, graph/title navigation, stale-save recovery and deletion. Requires the supported real lexical QMD installation.
   - `npx --package=playwright node scripts/external-document-updates-smoke.mjs` — P04/P05/P06 with raw writes, idle application, independent merge/conflict recovery and caret/scroll behavior. No semantic model is needed.
   - `npx --package=playwright node scripts/markdown-formatting-smoke.mjs` — P06 source preservation through actual editor operations.
   - `npx --package=playwright node scripts/companion-gateway-smoke.mjs` — P07/P08 with two local roots, a loopback hosted root, write approval, credential failures, save barriers and stale-generation fencing. This is an application/gateway fixture, not physical Keychain evidence.

4. Demonstrate that the gate fails for a tampered baseline, missing/changed required assertion or fixture, missing prerequisite, failing/zero/skipped required test, interrupted command and a failed semantic observation. Then verify the untouched baseline with the same contract. Keep the report and exact command/environment with the artifact; a mutable latest-success badge is insufficient.
5. Report physical Mac/install/update, real HTTPS/VPS and real semantic checks as separate evidence dimensions. They are not all prerequisites for freezing the portable parity contract, but a candidate that changes those paths cannot claim that deployment ready until its relevant checks pass. Loopback hosted tests are reproducible protocol evidence, not proof of public deployment.

The migration-specific gate is intentionally stronger than ordinary small-beta release preparation. It does not activate every deferred release test for unrelated changes or authorize publishing/installing a candidate.

## Baseline extension and merge rule

Existing behavior added by unrelated work after this baseline must enter an additive reviewed contract before the migration merges. Preserve the original baseline and record the extension's source/artifact/check hashes; do not regenerate expected results from the refactor candidate. Correcting a demonstrated baseline bug requires a separately recorded behavior decision and regression assertion, not deletion of an inconvenient oracle.

At each proposed merge, run the frozen parity contract and the claimed new capability's scenarios against the exact integration candidate, with candidate artifact identity recorded. Old paths remaining green while the new backend is untested is insufficient. A stage may merge behind its documented feature gate while retaining honest blocked/untested deployment dimensions; it must not become the default for those dimensions until their gates pass.
