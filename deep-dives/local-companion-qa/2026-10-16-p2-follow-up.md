## Result

P2 is fixed in the development browser shell. A persistent, polite/atomic status region above the canvas now shows:

- Shown document counts versus whole-brain counts when the view is partial, for example `500 notes shown · 501 notes in this brain.`
- Returned server warnings as safe text, including `Graph response was limited to 500 nodes.`
- `Filter to narrow the view.` when the existing limit warning is present.

The 500-node default cap and graph protocol are unchanged. Unresolved targets are excluded from note counts but still consume cap capacity. `stats.documents` is the entire brain, not the filtered matching-total. The existing warning producer can also warn for exactly-limit filtered results; the UI does not claim an exact omitted-note count or additional matching notes. That producer precision remains a possible separate follow-up, not an API change in this fix.

Refresh clears old notices immediately; only the current successful response replaces them. Failure/retry, filtered/empty results, and cached graph layout redraws do not resurrect stale success notices. Notices take layout space rather than covering the graph or filter controls. An uncapped complete graph with no warnings hides the notice.
