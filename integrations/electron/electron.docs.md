# Unified macOS desktop boundary

## Responsibilities

- `main.mjs` starts `application.mjs`, which owns one Electron app identity, the tray, window/onboarding, login preference, and explicit quit flow. Last-window closure leaves the host running. Background login does not open an editor. Preserve the existing Electron user-data path/partition and first-run marker.
- `desktop-host.mjs` resolves the runtime and internal native helper relative to the current app resources, starts only its own child, and authenticates readiness using a fresh instance identifier as well as the private control capability. Refuse occupied/foreign services. Stop only the owned child; the native parent watchdog and gateway watchdog clean up descendants after a parent crash.
- The internal `native/jumpyBrain Host.app` uses the existing Swift Keychain/folder/RPC code in `--desktop-host` mode, with no separate menu, update flow, or login registration. It holds the established companion lock and starts the bundled runtime. Keep Keychain service/reference identity; ad-hoc signature changes can still require explicit credential repair.
- `lifecycle.mjs` prepares all-tab shutdown through the gateway's existing save barrier before closing windows, flushing diagnostics, and stopping the host. Failed saves, missing acknowledgements, or unload cancellation leave the app running. Cancel releases the freeze without changing brain or generation; a bounded lease recovers a lost shutdown response.
- `login.mjs` owns one guarded LaunchAgent for the installed Electron executable with `--background`. Toggling affects the next login and never unloads the running app.
- `window.mjs` keeps the sandboxed editor with no preload/Node bridge, same-origin navigation, bounded feedback download, and default-preserve draft close protection. On macOS, `titleBarStyle: hidden` integrates real native traffic lights at `{x:16,y:18}` into the app surface. The host publishes only a same-origin `data-native-mac=true` presentation marker at DOM ready and before first show; the shared shell owns the 48px header, traffic-light inset and explicit drag/no-drag regions. Hosted/browser sessions retain ordinary insets. Application menu actions reopen the window when needed.
- `back-navigation.mjs` reuses Chromium's window-local history: current plus five previous destinations, removing the oldest native entries without retaining a second list or page snapshots. Reload/brain-scope changes clear history. DOM mouse button 3 (once on release), driver-mapped Cmd+[ and Electron's rightward native `swipe` request the existing renderer save/restore guard. The documented swipe event requires the older three-finger gesture with “Swipe with two or three fingers” enabled; standard animated two-finger swipe is deferred. No wheel/scroll interception, preload, IPC, worker, or polling is added. Renderer traversal is deliberate: the installed Electron 44.8.0 probe did not traverse using native `canGoBack`/`goBack` immediately after pruning, while `history.back()` preserved `popstate` and state.
- `onboarding.mjs`/`setup.mjs` retain the isolated welcome bridge, native-selected folder validation, explicit local creation, and existing connection save barrier. Neither retargets the CLI nor authorizes remote writes implicitly.
- The welcome page explains the usual existing CLI memory path, the native chooser's hidden-path shortcut, the software-folder distinction and unchanged agent targets before creation/selection. Missing-helper recovery reuses a default managed install or points to public source setup; it does not require private repository access. Paths still come only from explicit native selection.
- `setup.mjs` owns the shared repair text for welcome and actual startup failures. Raw filesystem errors stay in main-process startup state; notifications use known actionable reasons. Early startup failures notify before controlled quit. The paired-update socket rejects overlong UTF-8 paths before binding, retaining its established same-user location and ownership checks.
- `diagnostics.mjs` retains private bounded host/renderer evidence and submits safe events through the authenticated gateway. Raw errors/URLs/credentials never enter support exports.
- `install.mjs` packages Electron, compiled runtime/editor, native helper, and icon as one locally signed `jumpyBrain.app`. `desktop-install.py` composes native compilation and rollback installation, validates legacy ownership, checks processes and the native lock, preserves app data and login preference, and backs up older owned app bundles. `scripts/setup-desktop.mjs` builds the complete app; it provisions a missing CLI/QMD installation but does not update an existing CLI.
- Desktop setup calls the read-only `scripts/desktop-prerequisites.mjs` preflight, also exposed by `npm run desktop:setup -- --check`. It reports missing requirements together and checks macOS/Node/Python minimum versions before any installation.
- `smoke-*.mjs` are excluded test entrypoints. Production imports no fixture environment variable. `application.mjs` accepts explicit main-process options so lifecycle tests can use disposable resources and user data.

`npm run build` then `npx --package=playwright node scripts/window-chrome-smoke.mjs` verifies the production hosted and Mac shells, global search for a real canonical note outside the sidebar (deterministic indexed-search packet), native header geometry, both themes, collapsed/narrow layouts, native full-screen/minimize APIs, capture shortcuts, failed-save close/create protection and reopen. Screenshots go to `.local-pack/window-chrome-ui/`. Add `--inspect` to retain a disposable Mac window with the production application menu for actual traffic-light/drag checks; write `inspection-complete` in that screenshot directory to release it. Native controls are outside renderer captures and require direct OS inspection.

## Non-responsibilities

No alternate memory engine/editor, implicit sync or remote writes, CLI/agent retargeting, public signing/notarization, unattended updates, or crash-persistent drafts. External Node/QMD remain prerequisites. The bundled runtime is the same app code with its own release lifecycle; CLI-only installation does not need Electron or a Mac app.

## Executable extensions

The internal gateway composes the [extension app host](../../src/app/extensions/extensions.docs.md) against `<support>/extensions`; Electron keeps the same sandboxed renderer, no preload/Node bridge and existing shutdown/update barrier. The shared shell embeds a separate nonce-protected extension presentation bundle only in companion mode. A browser extension panel is trusted same-origin code, not an Electron/native capability.

`integrations/electron/package-lock.json` pins esbuild as a build dependency to the exact root production compiler version. Existing v0.3.7 workers install this incoming lockfile with `npm ci --include=dev` and then call incoming `install.mjs --output …`; no root node_modules or root npm install is required. Failed/offline dependency installation still stops preparation before replacement. `desktop-install.py` validates both pins and snapshots the pinned esbuild library and one matching Mac platform executable into the bundled runtime for lazy TS/JS package preparation. It does not copy the development dependency tree or depend on compiler modules resolving from a source checkout. The relocated compiler regression executes actual TypeScript preparation from a standalone temporary runtime and checks version mismatch rejection. Local package source/enablement/state remain in app support across runtime/app replacement.

`node scripts/extensions-desktop-smoke.mjs` exercises executable example packages, nonce UI loading, real lexical results, native keyboard dispatch, repeated panel cleanup, disable, and two actual sandboxed windows acknowledging shutdown preparation. Its process samples cover the harness gateway/memory engine and Electron tree, excluding the sampler; the Swift helper, login/tray/updater and physical devices are not instantiated by that diagnostic. It is not a whole-installed-app resource budget or long-run leak proof.

`npm run build` then `node scripts/mac-back-navigation-smoke.mjs` exercises the production sandboxed window/gateway against disposable brains: Chromium mouse input/default suppression, native swipe-event dispatch, five-step boundary/branching, failed-save Retry, deleted targets, real brain switching, tab cleanup, and repeated note/graph resource samples. Optional `--baseline-window <path>` loads a prior window module for matched host comparisons. Raw heap/process samples precede test-only diagnostic GC used to distinguish reachable DOM/listeners from garbage awaiting collection. This is fixture coverage, not physical mouse/trackpad verification or a whole-desktop physical-footprint budget.

`npm run build` then `node scripts/connection-usability-smoke.mjs` exercises add/validation/rename/test/switch/remove in the production sandboxed window against real disposable local and loopback remote engines, including a dirty note flushed before sidebar switching. `--inspect` pauses for manual native inspection. The runner isolates Electron user data, uses test credential/picker seams and checks that connection removal preserves all Markdown. See [browser verification](../../src/adapters/http-server/browser.docs.md#connection-usability-verification).

The native companion sources remain available for internal hosting and legacy migration/maintenance. Their standalone installer is not the new user-facing Mac setup path. Current packaging supports the private per-user installation; global/custom legacy locations require explicit migration.

## System messages

`system-messages.mjs` routes native host/window notices to the owned same-origin editor's shared `browser-system-messages.ts` component using the data-only `jumpybrain-system-message` event. Delivery checks the window, contents and gateway origin, escapes serialized data and bounds text; a missing/unavailable shell falls back through the injected native dialog presenter. Startup/onboarding/crashed-renderer failures therefore remain visible. `application.mjs` and `window.mjs` use this dispatcher for operational failures; `update-inline.mjs` emits the same event with app scope and operation revision, retaining its existing fixed action checks. Graph, session/connection and index notices use the same renderer component. No preload, generic IPC action, network endpoint or extra polling is introduced.

The destructive draft-close choice, onboarding field feedback and startup-blocking update recovery remain separate workflows. The shared dispatcher does not approve a close/restart, weaken a save barrier or grant remote write permission. `test/desktop-system-messages.test.js` covers safe delivery and native fallback. The production `smoke-inline-updates.mjs` additionally exercises native/renderer warnings, one component, priority, action/focus behavior, text safety and brain/app scope fencing in both themes.

## User-initiated updates

`updater.mjs` owns one operation shared by the sidebar, native menus and supported paired CLI. Its read-only snapshot exposes `phase`, `detail`, installed app/runtime/CLI policy and versions, available release/notes, restart errors and an authoritative `actions` array. Fixed actions are `check`, `update`, `app-only`, `cancel`, `restart`, `recover`, and `log`. Checking never prepares software; a download click pins the release already offered. `checkOnStartup()` checks once when idle/current/canceled or after a persisted successful/recovered update, preserving active jobs and actionable failures/recovery. `application.mjs` also starts one hourly release-discovery timer through `startUpdatePolling()`, independent of editor windows and the local host's health. It skips shutdown attempts and is cleared on completed quit; vetoed quit leaves hourly checks available. Renderer polling only observes local updater state. The native **Check for updates…** menu remains an additional manual entry point.

Hourly `checkInBackground()` calls share the updater's operation lock. They refresh idle/current/available/completed states without showing a checking state, preserve the last offer on network failure and retry on the next hourly tick. Startup/manual discovery failures carry `checkFailed` so a later successful poll can clear them. Preparing/ready/updating states, interrupted recovery and preparation failures retain their selected release and actions. User actions arriving during a background check wait for it and then execute, rather than being consumed as duplicate discovery. These checks never download, install, relaunch or open a window.

`update-inline.mjs` mounts one accessible 32px icon/16px glyph in `.nav-utilities` (with `.nav-preferences` compatibility). Available uses a stationary download glyph with an accent glow and a highlight traveling around the fixed rounded button border; ready uses a stationary relaunch glyph with the same border highlight. The masked conic gradient animates its angle rather than rotating the outline, and inherits the shared button corners. Reduced Motion keeps the readiness glow/border static. The decorative border does not intercept clicks or change layout; preparation uses the existing reduced-motion-aware spinner. The button stays visible from mount through idle/current/canceled and verified success/recovery, retaining its slot and neighboring control positions. Idle/canceled/recovered use a quiet refresh glyph and **Check for updates** action; current/success use a quiet checkmark glyph and **Up to date; check for updates** label. Before the first snapshot it remains visible but disabled. Working states disable it, while authoritative actions enable manual checks, downloads, relaunch and recovery as appropriate. The sidebar mounts no status paragraphs, details section, version text or release notes. Completion/recovery and actionable failures use the shared expiring bottom-left overlay, deduplicated across identical polls. Settings shows the installed Mac app version in its quiet version footer. Action names, failures and blocked-restart guidance remain in the accessible name and tooltip after a notice expires. The editor retains no preload/IPC bridge. `window.mjs` injects a read-only snapshot and intercepts only fixed `jumpybrain-update://ACTION` main-frame navigations from its owned gateway origin. Both URL parsing and current action availability are checked before execution; credentials, paths, arguments, child frames and external scopes cannot acquire update capability. Renderer polling pauses around native actions and discards older generations. Neither polling nor state transitions recreate the editor or replace its focused draft. Hosted/browser sessions receive no native control.

Normal updates open no popup. Pinned/custom/missing CLI policy uses the same download icon explicitly named **Update app only; CLI stays unchanged**, with the policy explanation in its tooltip. Retry/recovery actions reuse the icon; authoritative action checks still reject unavailable operations. Quitting without relaunch cancels preparation through the existing updater lifecycle. `update-window.mjs` remains only for startup-blocking recovery when the editor cannot run; its sandboxed sender/main-frame/URL-checked IPC has no generic commands, URLs, versions or paths. Only the startup recovery surface renders release notes, using text content. `env -u ELECTRON_RUN_AS_NODE integrations/electron/node_modules/.bin/electron integrations/electron/smoke-inline-updates.mjs` verifies the actual sandboxed production shell, inert state fixtures, eight edge/corner samples of a traveling highlight on a stationary rounded border, stationary action glyphs, reduced motion, keyboard/focus, themes, narrow layouts and action restrictions; screenshots go to `.local-pack/update-inline-ui/`. The recovery renderer keeps its separate `smoke-updater-ui.mjs` fixture.

`update-control.mjs` exposes a private same-user Unix socket at `~/.jumpybrain/u.sock` for `status`/`update` only. It validates ownership, mode and non-linked managed root and coordinates with the live app operation; it is not an HTTP or renderer API. `src/cli/update.ts` loads `update-cli.mjs` only for a supported managed Mac pair. An open app owns preparation and the all-tab restart barrier; CLI reports prepared/restart-needed. With the app closed, CLI owns the same external transaction through startup verification and re-reads the installed bundle version after exchange. CLI-only/legacy installations retain their installer flow; custom/pinned pairs require an explicit app-only exception. The socket and worker lock prevent competing update jobs. Requests/responses are bounded and timed; foreign/linked paths and live owners are refused. The socket binds under umask077 so it is private from creation, and both ends decode UTF-8 across arbitrary stream chunks. Recovery transfers shutdown ownership to its current caller (app or CLI), never to a stale request entrypoint. Worker resource preflight requires the coordinated update helpers before any replacement.

`update-release.mjs` selects the highest published numeric version across the discovered pages, including beta releases, so older installations jump directly to that version even when several intermediate releases exist. It pins an asset ID, URL, size, and SHA-256 digest; an unverifiable newest release fails the check instead of falling back to an older version. Manual/hourly checks can refresh the offered release until preparation starts; the selected release then stays fixed through preparation/restart. `update-policy.mjs` recognizes the exact default installer manifest/shim, protects custom/pinned CLI policy and data paths, and reports actual component versions. `update-worker.mjs` is copied with its dependencies into a private support workspace outside both replacement trees. It owns the shared CLI `.installer-lock` from preparation through verification. A background npm/Electron/native build uses the release's lockfile and compiled runtime. Parent death/cancellation before an acknowledged safe-quit handoff prevents publication.

Incoming release preparation looks for the native helper in the installed app; maintainer builds prefer their existing local package. `build_app(..., reuse_artifact=True)` reuses only a signed helper whose `NativeBuild.json` artifact fingerprint matches the actual Swift source, complete native build recipe and target architecture, and whose copied, unsigned executable matches the recorded digest. Configuration, revision, runtime and helper scripts are always refreshed and the new helper/app re-signed. Missing/invalid records, signature failures and changed inputs compile a fresh helper. Desktop artifact reuse deliberately survives SDK/toolchain and OS patch upgrades; it does not hash those trees. Standalone legacy companion builds retain their stricter toolchain fingerprint policy. Older installed helpers without an artifact record need one fresh build. Locked npm installation prefers cached packages but still checks lockfile integrity; no shared mutable dependency tree is used. Standard Electron packaging/pruning remains in place; the separate runtime still receives its pinned lazy extension compiler.

The worker stores private `timings.json` and bounded timing lines in `update.log`: download, extraction, dependencies, build, staged/installed readiness and publication. Phase marks separate post-download preparation and acknowledged handoff-to-verified-success from the user's wait at Ready. Incoming installers emit fixed, content-free `[build-timing]` records into that same 256 KiB log for Electron acquisition/verification, archive/checksum network transfers, unpacking/setup, source copying/ASAR/finalization, runtime/compiler copying, native reuse/compilation/signing and final bundle signing/verification/copying. Acquisition uses packager's pinned `@electron/get` downloader with normal checksum verification before passing the verified ZIP to packager. Network spans are included in acquisition, and native spans are included in desktop preparation; do not sum parent and child timings. Unpacking/setup includes packager's initial metadata/temp-directory work.

`scripts/desktop-update-smoke.mjs success` exports spans and checks into a unique private trial directory under `.local-pack/update-smoke/success/`, preserving earlier trials. It retains the original `source.tgz`, its digest, the synthetic release digest, machine/cache/baseline metadata, raw bounded log and extracted `build-timings.json`. `--package <immutable npm tarball>` repeats the same source bytes across trials, including when other work changes the shared checkout; the recorded checkout commit/diff describes the harness checkout, while the package digest identifies the tested distribution. Freeze the runner's compiled runtime and baseline too when other work could rebuild shared `dist`; run all builds/checks consuming it sequentially. Fresh fixture homes start with empty npm/Electron caches; measured archive/checksum transfers remain part of the reported application total.

`success --cold-native` removes only the disposable fixture's native reuse record to exercise a fresh build, and `success --client-v0.3.7` still runs the exact historical worker. The fixture explicitly re-signs the helper after changing its private configuration; outer `--deep` signing alone does not repair a helper stored under Resources/native. Instrumenting the fingerprinted native build recipe changes its artifact fingerprint: shipping this instrumentation alone requires one fresh helper build from earlier recipes. Matched unchanged-helper trials use a baseline built with the same recipe; they do not establish a fast migration from the previous published recipe.

`lifecycle.mjs` invokes updater handoff only after all-tab save preparation, window closure and lease commit; failed handoff retains the host. The external worker waits for parent exit, verifies staged/installed native readiness using owned children, and delegates exchanges to `update-transaction.py` under the native lock. A write-ahead journal stores inode/device identities before each atomic macOS exchange, so rollback can repeat after interruption. CLI shim/config/integrations, login items, Keychain, and Markdown are never exchanged. Normal startup is fenced while replacement/recovery is incomplete; only a matching worker-issued launch nonce admits the verification launch. Success requires that new app's exact authenticated host instance plus matching installed component versions.

Keep private logs bounded (256 KiB per job); previous components and journals remain in the Updates workspace for recovery. They are installation evidence, not canonical memory. Failed builds may need Node/npm/Python/Xcode/QMD repair or free disk space. Unknown locks, changed recovery identities and newer managed CLI versions fail closed. `scripts/desktop-update-smoke.mjs` uses disposable homes and immutable local release fixtures; production receives no fixture environment bypass. A live published release upgrade and Intel/notarized/keychain-history gates must not be inferred from fixture coverage.

Current updater readiness launches call `startDesktopHost(config, {readinessOnly: true})`; the native helper forwards only the internal flag to the gateway. Neither probe compiles or activates third-party factories or changes the persistent safe-mode marker. Real application relaunch activates normally. Already-published workers lacking this option retain their earlier probe behavior; state migrations on actual launch and unmanaged side effects remain outside installation rollback. Installed updater success/rollback smokes use one Electron profile to verify semantic palette, placement and shortcut preferences, plus an activation audit package.

## Note find menu

The native Edit menu retains standard edit roles and adds **Find in Note…** (`CommandOrControl+F`). It dispatches the fixed `jumpybrain:find` DOM event to the existing window; the browser-owned loaded-note/modal checks decide whether to open find. No new preload capability or native find-in-page state is introduced. The browser owns non-mutating body match ranges/navigation. `scripts/electron-smoke.mjs` verifies menu/keyboard, Escape, unchanged canonical Markdown and 1200/480px light/dark captures in the disposable sandboxed production window.
