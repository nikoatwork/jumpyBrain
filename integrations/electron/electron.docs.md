# Electron desktop boundary

## Responsibilities

- `diagnostics.mjs` reuses the installed runtime schema/store in the main process. Persist private bounded lifecycle history in Electron user data: bootstrap, renderer termination/unresponsive/load failures, and wrapper/runtime/editor build mismatches. Publish at most 64 safe events to the authenticated loopback companion capability; no renderer bridge, raw exception/URL capture, crash dump, or remote telemetry. Prior-session host records survive normal restarts; exports remap correlation. Missing/old runtime modules disable collection gracefully. Missing-runtime discovery and abrupt main-process death can leave final evidence unavailable. Bounded shutdown flushing preserves existing draft-close guards.
- `host.mjs` discovers the installed native companion, validates its private control capability, and authenticates gateway state. Only a refused connection permits background launch; no process adoption, restart, shutdown, shell, or arbitrary URL is used.
- `main.mjs` owns single-instance lifecycle, retained prototype browser storage, diagnostics, and first-run completion. The desktop bundle has its own stable identity and custom vector-derived icon; it coexists with the menu-bar helper. Completion is persisted only after opening the editor succeeds.
- `onboarding.mjs` serves the packaged welcome page in a separate sandboxed window/session. Only this exact main frame may invoke four fixed preload methods: status, native choose-folder, confirm local open/create, and explicitly continue with the current connection. Folder paths are retained in main, never accepted from renderer arguments. No remote keys, arbitrary IPC/channel access, or commands cross this bridge. Deny navigation, new windows, network, permissions and downloads. Remove handlers/listeners on close. The editor receives no preload.
- `setup.mjs` inspects native-selected canonical folders, refuses unrelated populated folders and unsafe markers, initializes empty folders through the installed public runtime without force/index/migration, and saves/selects local profiles via bounded native-authenticated gateway requests. Switching uses the existing all-tab save barrier. Retry reuses existing initialized roots/profiles. CLI and agent targets are unchanged.
- `window.mjs` hosts the shared companion shell with isolated sandboxed Chromium, the existing fragment-to-HttpOnly-cookie handshake, guarded native menu actions, and the default-preserve pending-draft unload dialog. Allow only fixed-recipient feedback mailto and same-origin bounded feedback `.eml` downloads; deny all other external navigation/downloads. Remove session download listeners on close.
- `install.mjs` packages `jumpyBrain Desktop.app`, excludes development/test/install sources, applies the committed ICNS, signs/verifies locally, and registers installed builds with Launch Services. Default target is `~/Applications`; `--output` creates a build artifact instead. Refuse replacement. Electron dependencies/lockfile remain isolated from the CLI.
- `scripts/setup-desktop.mjs` composes existing fresh CLI/helper installation plus desktop packaging from a trusted/private checkout. Existing managed installations are reused without updating/restarting. Fresh CLI installation omits agent integrations and initial indexing; the CLI's default brain remains separate from the desktop choice.
- `smoke-app.mjs` is test-only and uses disposable production gateway/runtime configuration supplied by `scripts/electron-smoke.mjs`. Production entrypoints never consume its fixture variable.

## Non-responsibilities

No alternate frontend/engine, backend ownership, Keychain replacement, sync, implicit remote writes, agent/CLI retargeting, automatic updates, public signing/notarization, downloadable universal release, or crash-persistent drafts. Runtime and helper upgrades remain the existing managed update flow. Fresh-machine toolchain installation, Intel hardware, and distribution signing remain manual verification boundaries.

The icon is derived from `src/adapters/http-server/favicon.ts`; `assets/app-icon.svg`, 1024px PNG, and ICNS are committed runtime assets. Regenerate PNG using `rsvg-convert`, then the standard 16/32/128/256/512px @1x/@2x iconset using `sips` and `iconutil`. These tools are for artwork maintenance, not end-user setup dependencies.
