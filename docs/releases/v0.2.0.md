# jumpyBrain v0.2.0

## Highlights since v0.1.0

- **Dream from the memory map:** choose **Consolidate notes (Dream)…** and copy a self-contained prompt into your agent. It authorizes bounded dream-page updates and indexing, preserving source notes. No model execution or credential export happens in the browser.
- **A fuller Markdown workspace:** recent notes, quick capture with readable daily titles, shared search, full-page WYSIWYG editing, page renaming, and page-reference insertion.
- **A quieter memory map:** simplified controls, pointer-anchored zoom, and shared note navigation with browser Back.
- **Better dreaming and retrieval:** stateless UTC evidence windows, relevant dream-map preference, stronger title matching, and relevance-gated recency.
- **Local macOS companion (beta):** a menu-bar app with shared CLI/runtime updates, update availability checks, and visible Terminal progress.
- **Logseq import:** safe, rerunnable, one-way migration of classic file graphs into a separate memory root.

## Update later

This release does not update running installations automatically. For public-installer installations tracking GitHub `master`, the normal update command picks up the new runtime:

```sh
~/.jumpybrain/bin/jumpybrain update --dry-run
~/.jumpybrain/bin/jumpybrain update
~/.jumpybrain/bin/jumpybrain --version
```

To install this exact release instead:

```sh
~/.jumpybrain/bin/jumpybrain update --ref v0.2.0
```

The selected ref is recorded for future updates. A tag-pinned installation stays pinned; use `--ref master` to return to tracking the branch. Installations using another source/ref do not automatically switch to GitHub `master` or the latest GitHub release.

**macOS app users:** wait for **Saved**, then choose **Update jumpyBrain…** in the app menu. For terminal-driven updates, quit the app first and reopen it afterward. Older bundled-runtime installations may need a one-time rerun of the latest public installer; see [installation and update guidance](../install.md#update). Chrome tabs remain open but need a refresh after updating. No portable signed/notarized `.app` is included.

Self-hosted servers must be rebuilt/redeployed separately to expose the new browser toolbar action; updating only a remote CLI client does not update a hosted web UI. Source checkouts use `git pull && npm install && npm run build` on their intended branch.

## Compatibility and limits

- Markdown remains canonical; this release does not require a new memory-root schema.
- **Dream CLI workflow change:** `dream` now retrieves a read-only, bounded UTC evidence window. Old CLI batch lifecycle/apply flags fail with migration guidance. Use ordinary `remember --type page --dream`, `show`/hash-checked `update`, and authorized indexing. Legacy runtime/HTTP batch APIs remain for compatibility. Window clients require a server with the window endpoint; upgrade older servers rather than falling back to batch mutations.
- The copied prompt uses the current origin and today plus the preceding two UTC dates, not map filters. Your agent needs its own CLI and memory credentials; authentication/read-only policies still apply. Copying does not start work or establish a completion record.
- Avoid concurrent browser/agent edits to the same dream page; the editor does not provide cross-tab merge protection. Agent budgets and source-preservation instructions are not enforced ACLs or model-spend guarantees.
- Node.js 22+, npm, Git, and QMD remain prerequisites for the applicable installer/local search workflows. The optional macOS app is locally built and retains its native build prerequisites.
