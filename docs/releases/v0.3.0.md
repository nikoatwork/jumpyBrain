# jumpyBrain v0.3.0

## Highlights since v0.2.0

- **Switch brains from the Mac app:** `/settings` manages named existing local folders and remote server connections. One brain is active across companion editor tabs and the menu-bar switcher; CLI and agent targets remain independent. This is target switching, not sync.
- **Safer connection handling:** remote keys stay in macOS Keychain, not the connections file or browser storage. All-tab save acknowledgements, conflict blocking, generation fencing, and destination-scoped note links prevent drafts or retries from landing on another brain. Offline targets stay selected; remote editing/indexing approval is explicit.
- **Bounded, temporal retrieval:** compact recall packets and hash-guarded evidence expansion, explicit evidence-date intervals, distinct-file source passages, and asynchronous execution deadlines/cancellation.
- **More reliable memory maintenance:** incremental recoverable semantic indexing, automatic local index freshness, strict read-only lexical retrieval, truthful saved-versus-indexed outcomes, and source-preserving extractive maintenance.
- **A calmer Markdown workspace:** page-reference navigation/autocomplete, clearer browser identity, literary typography, comfortable spacing, and wrapping page titles.

## Update

For managed installations tracking the project's `master` branch:

```sh
~/.jumpybrain/bin/jumpybrain update --dry-run
~/.jumpybrain/bin/jumpybrain update
~/.jumpybrain/bin/jumpybrain --version
```

Quit the Mac companion after every editor shows **Saved** before a terminal-driven update; reopen it afterward. The updater replaces the shared runtime and locally built native app together, preserving memory, connection metadata, control token, port, login preference, and agent integrations. Existing installations seed their configured local brain once. Open **Settings…** to add remote connections.

To pin this exact release, use `jumpybrain update --ref v0.3.0`; use `--ref master` to resume branch tracking. Other installation sources/refs do not automatically change. Source checkouts use their normal Git/npm build workflow. Self-hosted servers require a separate rebuild/redeployment; a local update does not update them.

## Compatibility and beta limits

- No canonical memory-root schema migration is required. Markdown remains canonical; indexes and retrieval state remain derived.
- Companion profile state lives in private `connections.json` under its existing support directory. Changing a destination allocates a new profile identity, invalidating old scoped note links. CLI credentials/configuration do not change when switching profiles.
- Failed/unconfirmed saves or an unresponsive registered tab block switching. Wake the tab or resolve its conflict; restarting is not a safe way to discard its draft. Browser-crash/offline draft recovery and general concurrent-edit merging are not provided.
- Ad-hoc native rebuilds may lose access to earlier Keychain items. Access fails closed without a hidden authentication prompt or plaintext fallback; re-enter the remote key through guarded Settings repair. Signed/notarized distribution and automatic signed-release credential continuity remain future work.
- Remote profiles accept HTTPS origins, or literal loopback HTTP development origins, without paths/embedded credentials/query/fragment. Redirects are not followed, and normal TLS certificate verification remains enabled.
- The companion uses the existing local engine with explicit index refresh; it is not a public multi-root server or an agent API endpoint. Local Dream handoffs explain that limitation; authorized remote handoffs use the real remote origin.
- Node.js 22+, npm, Git, exact QMD 2.8.3 and its SDK remain applicable prerequisites. Native builds additionally require macOS 13+, Xcode command-line tools, Python 3.9+, and Chrome.
