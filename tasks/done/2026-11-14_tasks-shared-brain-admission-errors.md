# Explain shared-brain admission failures consistently

Priority: P2. Status: **completed in source on 2026-11-14**; pending release. Planning notes below are kept as the investigation record; see [Outcome](#outcome) for what shipped and how it was verified.

## Goal

Give people and agents a useful, consistent explanation when a shared brain or its proxy refuses work. Preserve server resource protection and machine-readable CLI output without guessing a deployment's limits, hiding failures, or retrying writes.

## Evidence and current behavior

Inspected source and reused a successful shared build at `bfeb0a1533e1ac60ae8b24eaa1fdc7090ea8b3da` (v0.3.25 source). Read the full [November 10 report](https://console.agentmail.to/dashboard/inboxes/jumpybrain%40agentmail.to?thread=8d584d6b-3bcf-4da6-ad0b-cc486b7e5856) through the inbox API on 2026-11-14. The report concerns v0.3.22: a short sequence of CLI reads ended in HTTP 429 without JSON despite `--json`; a later manual retry worked. The report's suggested fixes are proposals, not established root causes.

- **Confirmed client gap:** [`RemoteMemoryError` and ordinary error decoding](../../src/adapters/http-client/index.ts) (lines 94–98, 145–151) retain status/code/message but discard `Retry-After`. A non-JSON 429 becomes `http_429` and a bare HTTP-number message. The [bounded decoder](../../src/adapters/http-client/bounded-response.ts) (lines 167–199) safely caps error bodies at 8192 bytes and rejects remote message text, but has the same missing 429 explanation. Keep that safety property.
- **Confirmed CLI gap:** [`runCli`](../../src/cli/commands.ts) rethrows failures after existing auth/root explanations; the [executable shim](../../src/cli.ts) prints plain text to stderr regardless of `--json`. A disposable loopback 429 with `Retry-After: 60` reproduced exit 1, empty stdout and plain stderr. The report says stdout; current behavior is stderr. Mock ordinary and compact clients both reproduced `http_429` with no retry delay. Each probe made one request; no real remote brain was used.
- **Confirmed ownership:** ordinary memory HTTP routes have no general requests-per-minute limiter or corresponding tuning option. [Deployment guidance](../../docs/vps-deploy.md#execution-and-capacity-limits) places IP/request-rate limiting at the reverse proxy. [Backend execution admission](../../docs/shared-memory-protocol.md#backend-execution-limits) is different: QMD queue saturation returns **503 `execution_overloaded`**, with **504** for deadline exhaustion. Feedback delivery and private cancellation/tab admission have separate endpoint-specific limits; do not present them as a universal memory quota.
- **Relevant prior fix:** [seamless coediting](../done/2026-11-10_tasks-seamless-live-coediting.md) identified per-keystroke whole-note sidebar reads amplifying traffic behind a proxy; v0.3.23 [release notes](../done/releases/v0.3.23.md) include the reduction. That investigation recorded one deployment's 120 requests/minute, burst 30, per-address policy. Those are historical deployment settings, **not product defaults**. Eight reported CLI calls do not establish total traffic across apps, people or a shared address.
- **Adjacent transport gap:** the [companion target transport and response forwarding](../../integrations/macos-companion/gateway.mjs) (lines 288, 548–550) preserve status/body but strip `Retry-After`. This is a small transport follow-through, not a reason to redesign editor recovery.
- **Already covered separately:** server [background index maintenance](../../src/app/server-memory/server-memory.docs.md) schedules derived work after confirmed writes. `indexed:false` is canonical save success, not permission for a client to send hidden index mutations. The report's extra-index-request suggestion does not justify coupling writes and indexing here.

The historical emitting component, its effective policy and aggregate traffic are unverified. The user-facing and JSON defects reproduce without knowing them; fixing those does not require deployment access.

## Recommended direction and boundaries

1. Normalize admission metadata once in the existing HTTP client adapter, for ordinary and bounded responses. Preserve known safe application codes such as `execution_overloaded`; use `rate_limited` for a generic 429. Supply static plain-language guidance and optional validated `retryAfterSeconds` from the response header. Unknown delay stays absent; never invent a countdown, quota or emitter identity. Distinguish rate refusal from a busy execution queue.
2. Use a focused shared CLI error formatter in `src/cli/`, leaving `src/cli.ts` an executable shim. A successfully parsed `--json` memory command should emit one documented JSON error object on stdout, exit nonzero and avoid duplicate text. Apply the same path to direct commands, recipes and board memory commands. Preserve existing successful packets, compact/expansion JSON behavior and existing auth/root recovery guidance. Decide and document compact-without-`--json` failure output explicitly, rather than accidentally changing its success schema.
3. Keep one request per operation in this increment. An automatic read retry is optional convenience with additional deadline/cancellation, amplification and method-classification complexity; it is unnecessary to close the observed error contract. Defer it until evidence shows manual/agent handling is insufficient. HTTP POST is used by observational recall, so HTTP method alone cannot authorize future retry policy. No canonical or derived mutation retry is added.
4. Forward only validated `Retry-After` through the companion's existing response allowlist. Do not forward cookies, redirects or authentication challenges. Do not change browser retry timing unless a separate reproduced gap requires it.

Changing proxy limits, adding a product rate limiter, a distributed quota service, per-agent exemptions, polling, a new observability dashboard, mandatory indexing after writes and rewriting unrelated error transports are outside scope. Operator examples may explain how to inspect/configure their own proxy; no generic numeric quota should be advertised as the app's default.

## Acceptance criteria

- JSON, text/HTML, empty and malformed-body 429 responses produce a safe `rate_limited` explanation; safe existing admission codes remain distinguishable. No raw proxy HTML, credentials, server paths or arbitrary admission message text enters CLI output.
- A valid delta-seconds or HTTP-date `Retry-After` yields a nonnegative bounded numeric delay; missing, invalid or unsafe values yield no claimed delay. Tests pin the clock for date cases. A delay is guidance, not a guarantee of future acceptance.
- Direct `show`, `tree`, rich/compact `recall`, expansion, board reads and equivalent supported recipes share the admission contract; `--json` stdout parses as one object with error code, safe message, HTTP status and optional delay, with exit 1. Plain output uses stderr. Existing success output and auth/conflict handling remain compatible.
- 503 `execution_overloaded` remains an execution-capacity failure, not a fictional per-minute quota. Failed retrieval never becomes empty-success or unrequested full-document fallback.
- All client read and write probes make exactly one attempt. No sleep/retry loop, deadline reset, extra status request or index mutation is introduced. A generic 429/503 from an unknown intermediary does not prove that a write was never committed; preserve uncertain outcomes and hash/idempotency safeguards.
- The gateway preserves a valid retry hint without broadening its header forwarding or brain/tab/generation authorization. Documentation accurately separates core capacity limits from operator-owned proxy policy.

## Outcome

**Contract.** One helper, `src/adapters/http-client/admission.ts`, classifies refusals for ordinary and bounded requests. A valid remote `execution_overloaded` code stays distinct on any status. Otherwise 429 becomes `rate_limited` and a code-less 503 becomes `service_unavailable`; other codes such as `read_only_busy` keep their existing handling. Messages are static and say that jumpyBrain did not retry and that a write should be checked before repeating. Ordinary 429/503 bodies now use the existing 8192-byte capped decoder. `RemoteMemoryError.retryAfterSeconds` comes only from a single delta-seconds or IMF-fixdate `Retry-After` within one day (past date gives 0; injectable clock). Other forms give no delay.

**CLI.** `src/cli.ts` calls `main()`. The new `src/cli/errors.ts` exits 1 and prints plain stderr, or one `{error:{code,message,status?,retryAfterSeconds?}}` object on stdout for a successfully parsed `--json` memory command, `run memory:*` recipe or `board` command. Token/argument parse errors stay plain stderr. Other commands are unchanged; `feedback` keeps its own JSON. Compact/expand without `--json` keep plain stderr and empty stdout, so stdout only holds valid packets. Auth, missing-root and stale-hash explanations keep the original error as `cause`, so codes such as `invalid_api_key`/401 and `precondition_failed`/412 survive in JSON. Local failures without a safe code use `command_failed`. `runCli` still rejects for in-process callers.

**Companion.** `targetFetch` adds a validated `Retry-After` to non-2xx results and the memory response forwards only that header. Status/body/content type, cookie/challenge/redirect stripping, scope fencing and browser retry timing are unchanged.

**Docs.** [CLI failure output](../../docs/cli-commands.md#failure-output-and-json-errors), [proxy rate limits](../../docs/vps-deploy.md#request-rate-limits-belong-to-your-proxy) (no product quota; example numbers are not defaults; shared NAT keying; nginx log inspection; `limit_req_status 429` added to the example because nginx otherwise refuses with 503), [shared-brain troubleshooting](../../docs/cloud-shared-memory.md#when-the-server-or-its-proxy-refuses-requests) (including `indexed:false` as confirmed save), [protocol](../../docs/shared-memory-protocol.md#backend-execution-limits) plus 499/503/504 rows in its error table, [HTTP client](../../src/adapters/http-client/http-client.docs.md#admission-refusals), [CLI module](../../src/cli/cli.docs.md) and [gateway](../../integrations/macos-companion/gateway.docs.md).
