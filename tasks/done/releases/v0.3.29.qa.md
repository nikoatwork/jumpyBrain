# v0.3.29 release verification

Published [v0.3.29](https://github.com/nikoatwork/jumpyBrain/releases/tag/v0.3.29) as a beta prerelease at **2026-11-25T13:45:29Z**. This is the second release of November 25 in Europe/Berlin (v0.3.28 shipped at 11:16Z). The owner explicitly asked to cut the release that day, after being told about the one-release-per-day rule. Release commit `43dfa6e3`, annotated tag object `727387cb`, pre-bump snapshot `fdcf7326`. Checks ran on macOS 15.7.7 ARM64 with Node 26.7.0 and QMD 2.8.3.

## Limits

- **No candidate period.** The owner asked to release right after the fix, so no local candidate ran on the real brain. The changed update path was tested only with disposable fixtures. The owner's Mac is still on 0.3.28; its CLI and app were moved to the stable Node link by an installer rerun the same day.
- **First real case still ahead:** no real app update to a published release has yet gone through the new Node migration. The update from 0.3.28 to 0.3.29 is that case, and under it only the app moves.
- **Still untested:** a real `brew upgrade`, Intel execution, Safari, and the shared VPS server, which runs 0.3.23 and was not updated.

- **Shared VPS server upgraded from 0.3.23 to 0.3.29 the same day.** The verified release asset was installed into its own release directory, with the search engine hard-linked from 0.3.23 (identical engine lockfile, `qmd-install-check` passed). A private backup was taken while the service was stopped: environment, proxy routes, unit, brain archive and note checksums. Downtime was about 21 s.
- **Checks after the switch:** all 13 note files are byte-identical. `/health` reports 0.3.29. With the 0.3.29 CLI, `status`, `tree` (9 indexed of 9), search and `access whoami` (admin) work and `access list` shows 8 keys. A browser sign-in gets the 400-day `Secure` session cookie without the key, and sign-out returns 401 at once. No errors in the service log. 0.3.23 is kept for rollback.
