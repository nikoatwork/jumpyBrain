# Changes

- **Linked from:** when other notes link to a page, it shows **Linked from (N)** with their titles and a short snippet, including links written before the page existed (for example after a Logseq import). The page card's new **Open in graph** button shows the page's connections on the map. Hosted brains need the server updated too.
- **Fewer false alarms in the editor:** settling, snoozing or bringing back the open note no longer reports a failure when someone else edits it at the same moment, and a dropped connection mid-action says the change may have been saved instead of "Failed to fetch", without repeating it. Cutting the first line of a new note no longer asks you to review a false conflict, guarded CLI appends reach open editors without a false replacement warning, and a wrong access key no longer leaves you stuck on the open note.
- **Calmer, more consistent interface:** graph labels stay steady when hovering across a large graph. Buttons, rows, menus, dialogs and dropdowns look and behave the same everywhere (Cancel before the main action, 40px touch targets). The sidebar is roomier, with a 320px default width; existing custom widths are kept, and double-clicking the divider applies the new default.
- **Shared brains:** opening one sends far fewer requests (17 down to 7 for a window on an eight-note brain), so several windows, people and agents behind one address are less likely to hit a proxy rate limit. When requests are refused (HTTP 429 or 503) the CLI explains why and shows a wait time only when the server gives one; it never retries automatically. With `--json`, failing memory, `run memory:*` and `board` commands print one `{"error": {...}}` object on stdout. Needs the server updated too; a newer editor keeps working against an older server.
- **Self-hosting:** builds now use `deploy/Dockerfile` (feedback relay: `deploy/Dockerfile.feedback`) with the repository root as build context. **Update the Dockerfile path in existing Coolify applications before deploying.** `JUMPYBRAIN_INDEX_DIR` can put the rebuildable search index on a separate local disk; losing that volume triggers a rebuild while notes, access credentials and recovery data stay in the memory root. Network shares remain unsupported.
- **Upgrading older installs:** `--source release` (with `--with-app` for the matching Mac app) migrates older managed CLI installations to a verified release, keeping the brain folder, settings, credentials and customized integrations, and retaining the previous runtime for recovery. A plain `--with-app` rerun explains what is missing instead of reusing an incompatible CLI.
- **Installer reliability:** readiness failures say whether the runtime is too old, failed to run, or found the brain not ready. The installer, its verification and the Mac app always use the same search engine, so an older `qmd` on `PATH` can't shadow it, and uninstall never removes a config or integration file an older installer did not record.
