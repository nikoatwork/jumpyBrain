# v0.3.28 real use: tests and fixes

The owner asked on 2026-11-25 for the "no real use first" gap of v0.3.28 to be closed by using the release on this Mac, and on the VPS through a temporary Linux install that is deleted afterwards. Bugs found were to be fixed and documented as task lists. Open items are in [the follow-ups](2026-11-27_tasks-v0.3.28-real-use-follow-ups.md).

## What was tested

**Owner's Mac** (macOS 15.7.7 arm64, Node 26.7.0, real brain with 1,666 notes):

- Updated app, bundled runtime and CLI from 0.3.27 to the published 0.3.28 with `jumpybrain update --ref master` (see the first fix for why the flag was needed). The app was quit normally first. The CLI path downloaded and verified the release, reported "startup verified" and reopened the app in the background. All three components are 0.3.28.
- `status`, `doctor`, `smart-search status`, `tree`, `recall` and `search` on the real brain (index fresh, 1,666/1,666, keyword search, recall about 0.5–1 s). The app's local service answers on its port.
- Read-only checks with the 0.3.28 CLI against the shared VPS brain (server 0.3.23): `status --target-url`, `search`, `tree`, `access whoami`. Nothing was written there.
- Not done: no notes were written to the personal brain, and the editor window was not used.

**VPS, throwaway user `jbtest`** (Ubuntu 24.04 x64, 2 vCPU, Node 22.23.1), all of it removed afterwards:

- Plain public install without a terminal (`curl … install.sh | bash`): ready in 31 s, default `personal` profile, keyword search, private QMD 2.8.3 engine, Codex skill (Codex is installed there). Its exact file report matched what was created.
- `remember`, `recall`, `search`, `tree`, `status`, `doctor` on the new brain.

- A temporary `serve` on 127.0.0.1:47123 with issued admin, writer and reader keys:
  - `GET /session` sets an HttpOnly, SameSite=Strict cookie with Max-Age 34,560,000 (400 days) that does not contain the key.
  - An invite link signs one browser in. A wrong Origin gets 403, a reused code 410, and a browser that is already signed in 409.
  - A reader session can search but gets 403 on a write.
  - Admin sign-out of the reader's browser and the admin's own sign-out both lead to 401 at once.
  - The remote CLI with a writer key saved a note; it was searchable after deferred indexing. A reader key got the clear 403 `read_only` message. `access whoami` named the role.
- `npm run smoke:hosted` from a clean `v0.3.28` clone (`b4b4e3c2`): see the Docker result below.

## Fixed

- [x] **`jumpybrain update` refused every release-installed Mac.** For a release distribution `src/cli/update.ts` passes an empty ref, and `pairedInstallation` in `integrations/electron/update-cli.mjs` accepted only `master`, so it stopped with "custom, pinned, or unowned CLI policy". The bug dates from the release-distribution change. The check now treats an empty or absent ref as the default policy; a real pin is still refused. Test: `test/desktop-updater.test.js`. Installed 0.3.27/0.3.28 CLIs still carry the old check, so they need `--ref master` until they update to a build with this fix (or update from the app).
- [x] **Bare phrase to `recall`/`search`/`expand`.** "Unexpected bounded-read argument: …" now says to pass it with `--query "…"` (or `--id` for `expand`). Test: `test/cli-args-properties.test.js`.
- [x] **`serve` blocked by the background service.** "This brain already has a live backend owner" now names `jumpybrain backend stop --root "<root>"`.
- [x] **Engine size on Linux.** The `personal` profile said the engine takes about 205 MB. On Linux x64 it took 856 MB, because node-llama-cpp also installs CUDA (530 MB) and Vulkan (77 MB) builds. The installer text and `docs/install.md` now give both sizes.
- [x] **Stale doc.** `src/adapters/http-server/browser.docs.md` still described the 24-hour cookie; it now points to the 400-day session.
- [x] Leftover processes stopped by hand: the v0.3.27 backend described in the follow-ups, a 2026-11-22 install-smoke backend and the release's disposable `personal` backend.
