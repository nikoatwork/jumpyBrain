# Changes

- Typing a wrong access key while a note is open no longer leaves you stuck on that note; you can navigate away or enter the correct key straight away.
- Buttons, rows, menus, dialogs and dropdowns now look and behave the same across the app. The brain switcher at the bottom of the sidebar highlights as one row with a proper switch icon, chevrons rotate the same way everywhere, dialogs put Cancel before the main action, and touch layouts get 40px targets consistently.
- The sidebar has more breathing room, a wider 320px default and clearer title, preview and timestamp typography. Existing custom widths are kept; double-click its divider to use the new default.

- Opening a shared brain in the browser or Mac app sends far fewer requests: the sidebar list is read once instead of three times, and note previews arrive with that list instead of one whole-note read per row (17 requests down to 7 for a window on an eight-note brain). Several windows, people and agents behind one address are less likely to hit a proxy rate limit. Needs the server updated too; a newer editor against an older server keeps working with the previous per-note reads.
- When a shared brain or its proxy refuses requests (HTTP 429 or 503), the CLI explains whether requests were rate-limited, the brain was busy, or the service was unavailable, and shows a wait time only when the server provided one. It never retries automatically. With `--json`, failing memory, `run memory:*` and `board` commands now print a single `{"error": {...}}` object on stdout instead of plain text on stderr.
- Older managed CLI installations get one reliable upgrade route: `--source release` (with `--with-app` to add the matching Mac app) migrates them to a verified release, keeping the brain folder, settings, credentials and customized integrations, and retaining the previous runtime for recovery. A plain `--with-app` rerun no longer reuses an incompatible older CLI; it explains the installed version, the missing capability and the command to run.
- Installer readiness failures now say whether the runtime is too old to report readiness, failed to run, or found the brain not ready, instead of a generic search error.
- The CLI installer, its verification and the Mac app now always use the same search engine; an older `qmd` on `PATH` can no longer shadow the selected one. Uninstall never removes a config or integration file an older installer did not record.
